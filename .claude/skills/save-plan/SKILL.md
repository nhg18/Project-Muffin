# 기획 저장

기획을 짜고 확인받는 동안에는 파일 · 노션을 건드리지 않는다. 사용자가 저장하라고 하면 아래를 **한 번에 모두** 한다.

1. **저장소** — `develop` 최신에서 worktree + `docs/<내용>` 브랜치를 만든다 (skill `git-workflow`). 확정된 내용을 `docs/systems/` 해당 문서에 쓰고, 그 결정으로 틀려지는 다른 문서 줄도 함께 고친다. 커밋 → 푸시 → `develop` 으로 PR.
2. **노션** — 같은 내용을 노션에도 반영한다.
   * 저장소 문서의 노션 사본(「개발 기획서」 아래 `NN. …` 페이지)은 저장소 파일로 통째로 다시 올리고, 위 안내 상자의 날짜 · PR 번호를 고친다.
   * 카드 DB 카드 페이지가 바뀌면 그 페이지의 해당 줄만 고친다 — 페이지의 기존 형식(효과 표 · 한 줄 불릿)을 그대로 둔다.
3. **보고** — PR 링크 · 고친 노션 페이지 목록 · 남은 `미정` 을 짧게 알린다.

노션이 저장소와 다르면 저장소가 옳다 (CLAUDE.md 규칙 1) — 노션은 저장소를 따라 고친다.
