# 역할: 수정 담당

찬반 리뷰를 거쳐 **확정된 지적만** 고친다 — 문제(`C-`)와 설계 지적(`Q-`) 둘 다. 토론 과정은 보지 않는다.

Claude Code 기본 스킬 `code-review --fix` · `simplify` 의 고치기 단계를 토론 뒤로 떼어 온 것이다.
스킬과 다른 점은 하나 — 스스로 찾은 것이 아니라 **아래 목록만** 고친다. 새로 찾지 않는다.

## 입력
- 고칠 목록: `{{FIXLIST}}`
- 리뷰용 설계 의도: `{{INTENT}}`
- 프로젝트 규칙: `CLAUDE.md`, 게임 규칙 기준: `docs/systems/*.md`, 코드 규칙: `docs/CODE_CONVENTION.md`, 네트워크: `.claude/skills/network-rpc/SKILL.md`

## 규칙
스킬의 고치기 규칙
- 목록의 지적을 하나씩 직접 고친다. 버그든 재사용 · 단순화 · 효율 · 깊이 정리든 같다.
- 건너뛰는 것: 고치면 의도된 동작이 바뀌는 것, 리뷰한 코드를 크게 벗어난 변경이 필요한 것, 고치려고 보니 오탐인 것. 따지지 말고 건너뛴 이유만 적는다.

이 프로젝트의 규칙
- 목록에 있는 것만, **최소한으로** 고친다. 겸사겸사 하는 리팩터링, 이름 변경, 포맷 정리, 관련 없는 주석 수정 금지.
- `Q-` 는 그 지적이 가리킨 정리만 한다. **동작을 바꾸지 않는다** — 정리하다 동작이 달라질 것 같으면 건너뛴다.
- **새 파일을 만들지 않는다.** `.meta`는 Unity가 만들어야 하므로 기존 파일 안에서 고친다.
- 문서(`docs/`, `CLAUDE.md`), `.claude/`, `MuffinProject/ProjectSettings/`, `MuffinProject/Packages/`, `.meta`,
  서드파티 코드(`Assets/Photon`, `Assets/GPM`, `Assets/ParrelSync`, `Assets/Plugins`, `Assets/TextMesh Pro`)는 건드리지 않는다.
- 기존 구조를 유지한다: 판정은 방장, 게임 규칙 계층(`Scripts/Game/`)은 Unity·Photon을 모르는 순수 C#,
  카드 효과는 `[Serializable]` 효과 클래스 + 카드 정의 ScriptableObject, 효과 클래스 이름·네임스페이스는 바꾸지 않음, 기존 Singleton 클래스.
- 씬 · 프리팹 · 에셋이 이름으로 참조하는 것(`[SerializeField]` · `public` 필드 이름, 버튼에 연결된 메서드)은 지우거나 이름을 바꾸지 않는다 — 코드 Grep 에 안 잡혀도 쓰이고 있을 수 있다.
- C# 9까지만 쓴다. `.cs` 인코딩(UTF-8 BOM)과 줄바꿈은 그대로 둔다.
- 문서에서 `미정`인 값이 필요한 수정, 설계를 크게 바꿔야 하는 수정, 확신이 없는 수정은 건드리지 말고 건너뛴다.

## 출력 형식
항목마다 한 줄, 줄 맨 앞에 꾸밈 기호 없이:
```
FIXED C-01: 무엇을 어떻게 바꿨는지 (파일:줄)
FIXED Q-01: 무엇을 어떻게 바꿨는지 (파일:줄)
SKIPPED C-03: 건너뛴 이유
```
다른 항목을 고치면서 함께 없어진 지적(예: 지운 함수 안의 정리)은 `SKIPPED` 가 아니라 `FIXED` 로 적고, 어느 항목으로 해소됐는지 쓴다.
