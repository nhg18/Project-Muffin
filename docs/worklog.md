## 2026-11-06 · 체인 · 카운터 · 반응 시간을 연출 시간과 맞춤 (기능 5 규칙, `feature/counter-chain`)

### 결정 (PM)
- **A안**: 방장이 카드 데이터에 적힌 연출 시간으로 반응 · 턴 시각을 계산해 알린다. 클라이언트의 「연출 끝」 보고를 기다리지 않는다.
  - 반응 시간 = 등록 + 등장 시간(1 ~ 3 단계) 뒤 5초. 그 전(연출 중)에 온 카운터는 **거절** (코드 6).
  - 다음 턴 = 체인 처리 + 체인 맨 아래 카드의 후처리 시간(4 단계 + 버림 이동). 체인 처리 중에는 턴 20초가 멈춘다.
  - 기본값 = 시험장 값: 등장 1.46초(0.46 + 2 단계 1.0) · 후처리 1.28초(0.9 + 0.38). 카드 에셋 Inspector 에서 카드마다 고친다.
- 카운터 반응 조건은 **체인 맨 위 카드의 종류**(행동 / 함정 / 카운터)만. 「피해를 줄 때」 같은 세부 조건은 기능 9.
- 판정은 방장, 클라이언트는 요청 → 결과 이벤트만 (09 2절 그대로).

### 한 것
- 문서: `04` 7 · 8절(반응 조건 · 연출 뒤 5초 · 연출 중 거절 · 다음 턴 시각) · `03` 4절(Resolving 중 턴 시간 멈춤) · `09` 4.3(코드 6 ~ 9) · 3절 반응 타이머 행 · `10` 5-1(「연출 시간과 규칙 시간」 표) · `05` 8절(CardData 항목).
- 규칙: `GameServer.Chain.cs`(체인 · `PlayCounter` · 위에서부터 처리 · 무효 · 받는 사람 계산) · `ChainEntry`. `PlayCard` 는 바로 처리하지 않고 체인 맨 아래로. `Tick` = 반응 마감 → 체인 처리 → 후처리 시간 → 다음 턴 → 턴 마감. 처리 중 뽑기 · 카드 내기는 코드 7.
- 나간 사람은 턴 순서에서 지우지 않고 `PlayerState.HasLeft` 로 — 턴 주인이 카드를 낸 뒤 나가도 체인을 끝까지 처리하고 그 자리 다음 사람에게 넘어간다 (09 11절).
- 효과: `CardEffect.Apply(server, entry)` 로 바꿈. 받는 사람은 `server.ReceiversOf` (본인 무효 · 나간 사람 제외). `NegateEffect`(`selfOnly` = C05 「본인에게만」).
- 이벤트 (기존 `OnCardPlayed` 시그니처는 그대로 — 게임 화면 PR #89 와 호환): `OnCardPlayed` = 체인에 올라감 · `OnReactionStarted(opensAt, deadline)` · `OnCardResolved`(4 단계 시작, 효과 결과가 뒤따름) · `OnCardNegated`(4 단계 없음). 요청 `RequestPlayCounter`. `PhotonServerSettings` RpcList 갱신.
- `CardData`: `reactsTo` · `revealSeconds` · `resolveSeconds`. `Card_C_002`(테스트 카운터)에 무효 효과 + 반응 대상 행동.
- `GameDebugInput`: C 키 = 손패 첫 카운터, 반응 · 처리 · 무효 로그.
- `multi-test`: rules 에 체인 시나리오(21개 확인), multi 에 반응 시간 카운터 요청(코드 8) · 체인 처리 줄 판정. Refresh 를 `MultiTest.cs` 컴파일 전에 하도록 고침. `script.run` 은 매번 새로 컴파일돼 static 이 안 남는다 → `SessionState`.
- 확인: `rules 4 8` 통과(체인 21개 ✓), `multi 2 4` 통과 — 두 화면의 턴 줄이 순서까지 같음, 거절 코드 1 · 8, 체인 처리 줄 8개, 콘솔 에러 0. **실제 카운터 카드로 네트워크 체인을 돌려 보지는 못했다** — 덱(`Deck_Default`)에 카운터가 없다. 4클론 기준 확인도 아직.
