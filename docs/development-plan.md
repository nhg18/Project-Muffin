## 0. 결론 먼저

**게임을 13개 기능으로 나누고, 플레이어가 겪는 순서대로 하나씩 끝낸다.** 기능 하나가 끝나면 4클론에서 그 기능이 실제로 돈다.

**모든 기능은 같은 흐름으로 만든다.**

| 순서 | 로직 | UI |
| --- | --- | --- |
| 1 | **약속** — 이 기능에 필요한 알림 · 요청을 먼저 올린다 (작은 PR, 양쪽 리뷰) | 약속 검토 |
| 2 | **상태 바꾸기** — 방장 기기의 원본에 동작을 추가한다. 검사 없이 먼저 돌게 | 로컬 서버(에디터 1개)로 화면 · 입력을 만든다 |

## 1. 역할과 경계

| 역할 | 소유 | 핵심 산출물 | 하지 않는 것 |
| --- | --- | --- | --- |
| 로직 개발 | `Game/` · `Network/` · `Core/` 의 `.cs` | 방장 기기 서버, 검사, 카드 효과, 에디터 테스트 | 씬 · 프리팹 편집, `Presentation` 참조 |
| UI 개발 | `Presentation/` · `UI/` · `DebugTools/` + **모든 씬 · 프리팹 · 스프라이트** | 화면 · 입력 · 연출 · 로컬 서버 · 배치 문서 | 규칙 판정 (9 카드 59장의 쉬운 효과만 예외) |
| 기획 · 디자인 | `plan-c-planning.md` · `plan-d-art.md` (보류) | 기능별 "기획 결정 필요" 항목을 확정 | — |

**약속 파일은 개발 2명의 공동 소유다**: `PlayerProps`/`RoomProps` · `GameEvents` · `IGameRequests` · `IGameState`. 바꾸는 PR 은 양쪽이 리뷰한다.

**로컬 서버**: UI 개발은 에디터 1개로 4인을 흉내 내는 로컬 서버(`DebugTools/FakeGameServer`)에 화면을 붙여 만든다. 로직의 서버 코어(순수 C#)가 나오면 흉내 코드를 지우고 **진짜 서버 코어를 에디터에서 그대로 돌린다.** 규칙 코드가 두 벌이 되지 않는다.

## 2. 일하는 방식

| 요일 | 무엇 | 길이 |
| --- | --- | --- |
| 월 | 이번 주 기능 · 막힌 것 공유 | 20분 |

* 기능 하나 = 브랜치 여러 개. 약속 PR 은 작게, 먼저.

## 3. 기능별 작업

표기: **←** = 상대 작업이 있어야 시작 · **⛔** = 기획 결정 필요 · 날짜는 목표일

### 기능 1 · 게임 시작하기 (9/28 ~ 10/9)

**플레이어가 겪는 것**: 방장이 시작을 누르면 4명 모두 게임 화면으로 넘어가고, 섞인 덱에서 5장씩 받고, 체력 100 으로 시작하며, 무작위로 정해진 사람부터 턴이 시작된다.
**기준 문서**: `01-game-flow.md` 3절 · `05-deck.md` 3절 · `09-network.md`
**기획 결정 필요**: 덱 구성(카드별 매수) ⛔ — 확정 전에는 카드 데이터 전부 × 1장으로 만든다 (가정)

| 순서 | 로직 | UI |
| --- | --- | --- |
| 1 | **약속 (10/1)** — 카드 이동 알림(어디서 어디로 1장, 비공개 영역으로 들어가면 주인에게만 카드 내용), 체력 · 턴 · 손패 장수 · 덱 장수 알림, `IGameState` 리뷰 | **지금 시작** — 인게임 씬 재구성, 영역 배치(덱 · 버림 더미 · 가운데 · 좌석 4 · 내 손패 · 턴 표시), 배치 문서 `systems/17-game-ui.md` |
| 2 | 서버 코어용 어셈블리 + 에디터 테스트 환경 | 약속 검토. 로컬 서버가 시작 상태를 흉내 |
| 3 | **서버 코어 (10/6)** — 순수 C#. 덱 · 손패 · 버림 더미 · 체력 · 턴 원본, 카드 번호 | 좌석 — 닉네임 · 체력 게이지 · 손패 장수. 좌석 계산을 한 곳으로 |
| 4 | 시작 순서 — 전원 로드 대기 → 섞기 → 카드 번호 → 체력 100 → 5장씩 → 첫 턴 무작위 | 내 손패 앞면 · 상대 손패 뒷면. 손패 정렬 코드 공통화, 장수 보정 |
| 5 | **Photon 연결 (10/9)** — 요청은 방장에게, 공개 알림은 전원, 손패 내용은 본인에게만 | ← 서버 코어: 로컬 서버가 흉내를 지우고 진짜 코어를 돌린다 |
| 6 | 옛 동기화 정리 — 덱 전체를 방 정보로 보내던 코드 삭제, 손패 장수 · 체력은 방장만 기록 | ← Photon: 씬의 서버를 Photon 으로 교체, 각자 5장 요청 · 체력 기록하던 옛 코드 삭제 |

**끝났다는 기준**: 4클론 시작 → 네 명의 손패가 서로 다르다(섞였다) · 상대 손패는 뒷면 5장 · 네 화면 모두 체력 100 · 장수 5 · 첫 턴 주인이 같다. 에디터 테스트로 섞기 · 시작 순서 통과.

### 기능 2 · 턴 넘기기 (기본 10/5 ~ 10/9, 20초 10/12 ~ 10/16)

**플레이어가 겪는 것**: 내 턴이면 내 좌석에 초록 테두리가 켜진다. 턴을 끝내거나 20초가 지나면 다음 사람에게 넘어간다.
**기준 문서**: `03-turn.md`
**기획 결정 필요**: 연속 미제출 강퇴 턴 수 ⛔ · 턴 방향 ⛔ · 턴 건너뛰기 중첩 ⛔ (이 셋은 뒤 기능에서 쓴다)

| 순서 | 로직 | UI |
| --- | --- | --- |
| 1 | 턴 순서 배열 — 시작 때 무작위로 만들어 1회 알림 | 턴 표시 — 좌석 초록 테두리, 상단 "○○의 턴" (지금 있는 턴 표시 화면 재사용) |
| 2 | 다음 사람 찾기 — 나간 사람 건너뛰기, 지금의 다음 턴 계산 버그 수정 | 턴 종료 버튼 (개발용) |
| 3 | 검사 — 턴 주인만 턴 종료 가능 | 거절 토스트 (모든 기능 공용) |
| 4 | **20초** — 방장 기기가 판정, 턴 마감 시각을 알림, 시간 초과 시 그냥 넘김 | ← 마감 시각: 20초 표시 (로컬에서 남은 시간 계산) |
| 5 | 연속 미제출 강퇴 ⛔ — 턴 수가 정해지면 | 강퇴 안내 |

**끝났다는 기준**: 턴 종료를 누르면 다음 사람 · 남의 턴에 누르면 거절 토스트 · 20초가 지나면 저절로 넘어감 · 네 화면 동일.

### 기능 3 · 카드 뽑기 (10/8 ~ 10/11)

**플레이어가 겪는 것**: 내 턴에 덱을 탭하면 1장을 뽑고 턴이 끝난다. 다른 사람 화면에는 뒷면 1장이 날아간다.
**기준 문서**: `05-deck.md` 4 · 5절 · `03-turn.md` 3절
**기획 결정 필요**: 덱과 버림 더미가 모두 0장일 때 ⛔

| 순서 | 로직 | UI |
| --- | --- | --- |
| 1 | 뽑기 요청 — 덱 맨 위 1장 → 요청자 손패 (내용은 본인에게만) | 덱 탭 → 뽑기 요청 |
| 2 | 덱이 비면 버림 더미를 섞어 새 덱으로 | 뽑기 연출 — 나는 앞면, 남은 뒷면 · 덱 장수 표시 |
| 3 | 검사 — 내 턴 · 이번 턴 행동 안 함. 뽑으면 턴 종료 (**한 턴에 행동 한 번**) | 거절 시 토스트 |
| 4 | 에디터 테스트 — 뽑기 · 소진 재생성 · 두 번 뽑기 거절 | 4클론 확인 |

**끝났다는 기준**: 내 턴에 덱 탭 → 1장 + 턴 넘어감 · 한 턴에 두 번 뽑기 거절 · 덱이 비면 버림 더미로 재생성.

### 기능 4 · 카드 내기 (10/12 ~ 10/20)

**플레이어가 겪는 것**: 손패를 올려 카드를 드롭 영역에 끌어다 놓고, 대상 좌석을 탭하면 카드가 가운데에 나타나고 효과가 적용된 뒤 버림 더미로 간다. 턴이 끝난다. (반응 5초는 기능 5)
**기준 문서**: `04-card.md` 5 · 10 · 11절 · `10-ui.md` 4 · 6절
**기획 결정 필요**: 대상 선택 취소의 모바일 입력 ⛔ (`10-ui.md` 11절 #4)

| 순서 | 로직 | UI |
| --- | --- | --- |
| 1 | **약속** — 카드 사용 알림(누가 · 무엇을 · 누구에게), 거절 이유 | 약속 검토 |
| 2 | 카드 내기 요청 — 손패 → 가운데 → 버림 더미, 턴 종료 | 손패 올리기 · 확대 · 드래그 · 드롭을 모바일 입력으로 정리 (우클릭 취소 대체, `async void` 제거) |
| 3 | 검사 — 내 턴 · 이번 턴 행동 안 함 · 손패에 있음 · 카드 조건 · 대상 유효 | 대상 선택 — 고를 수 있는 좌석 강조, 좌석 탭, 취소 |
| 4 | **효과 실행 틀** — 대상 0개여도 1회 실행, 여러 대상은 바뀌기 전 체력으로 한꺼번에. 데미지 효과 1개로 경로 검증 | 가운데 카드 표시 + 대상 화살표 · 버림 더미 표시 |
| 5 | 지금의 카드 관리자(각 기기가 따로 실행) 삭제 | **승인 뒤에만 손패에서 제거** (지금은 먼저 지움). 거절 시 원위치 |

**끝났다는 기준**: 공격 카드(A09)를 내면 대상 체력 감소가 네 화면 동일 · 남의 턴에 내면 거절되고 카드가 손패로 돌아온다 · 한 턴에 뽑기와 카드 내기를 둘 다 할 수 없다.

### 기능 5 · 카운터로 막기 (10/19 ~ 10/25)

**플레이어가 겪는 것**: 카드가 나오면 모두에게 5초가 흐른다. 그 사이 카운터를 내면 5초가 다시 시작되고, 쌓인 카드는 나중에 낸 것부터 처리된다.
**기준 문서**: `04-card.md` 7 ~ 9절
**기획 결정 필요**: 카운터 사용 흐름 · 체인 표시 방식 · 무효 연출 ⛔ (UI 3 · 4 전까지) · 체인 최대 깊이 ⛔

| 순서 | 로직 | UI |
| --- | --- | --- |
| 1 | **약속** — 반응 마감 시각(서버 시각), 체인 상태(쌓인 카드 · 처리 중 · 무효) | 약속 검토 |
| 2 | 카드가 올라가면 5초, 카운터가 오면 5초 재시작 | 반응 5초 타이머 (서버 마감 시각으로 로컬 계산) |
| 3 | 검사 — 5초 안 · 반응 조건 · 동시에 오면 먼저 온 1개만 | 카운터 내기 — 반응 시간에 손패 → 가운데 드래그 ⛔ |
| 4 | 역순 처리, 무효 효과(C05) | 체인 표시 — 쌓인 순서 · 처리 중 강조 · 무효 표시 ⛔ |
| 5 | 에디터 테스트 — A09 ← C05, 5초 지나 온 카운터 거절 | 4클론 확인 |

**끝났다는 기준**: A09 에 C05 를 걸면 결과가 테스트와 네 화면에서 같다 · 5초가 지나 낸 카운터는 거절된다.

### 기능 6 · 함정 쓰기 (10/22 ~ 10/30)

**플레이어가 겪는 것**: 내 턴에 함정을 뒷면으로 내 앞에 놓는다(행동 횟수와 무관, 3칸까지). 조건이 되면 내가 직접 발동하고, 공개된 뒤 체인에 올라간다.
**기준 문서**: `04-card.md` 6절
**기획 결정 필요**: 함정 설치 · 발동 입력 방식 ⛔

| 순서 | 로직 | UI |
| --- | --- | --- |
| 1 | **약속** — 함정 칸 알림(개수는 전원, 내용은 주인만), 발동 · 파괴 · 공개 | 약속 검토 |
| 2 | 설치 — 손패 → 빈 함정 칸. 여러 장 가능, 행동 한 번에 안 셈 | 좌석마다 함정 칸 3개 — 뒷면 · 공개 구분 |
| 3 | 검사 — 내 턴 · 빈 칸 | 설치 — 손패 → 내 함정 칸 드래그 ⛔ |
| 4 | 수동 발동 — 조건 확인, 동시 발동은 1개만, 처리 뒤 남은 함정 재확인. 파괴 · 공개 · 손패로 돌리기 동작 | 발동 — 발동 가능 표시 + 탭 ⛔ · 공개 연출 |
| 5 | 함정 효과 1개(T06)로 경로 검증 + 테스트 | 4클론 확인 |

**끝났다는 기준**: 설치한 함정이 남의 화면에는 개수만 보인다 · 발동하면 공개되고 체인에 올라간다 · 네 화면 동일.

### 기능 7 · 체력과 사망 (10/26 ~ 11/1)

**플레이어가 겪는 것**: 체력이 20 이하가 되면 경고색이 켜진다. 0이 되면 5초 동안 사망 대기(살아날 카드만 쓸 수 있음)를 거쳐 사망하고, 턴에서 빠진다.
**기준 문서**: `06-health.md`
**기획 결정 필요**: 게임 중 나간 사람 = 사망 처리인지 ⛔ (`01-game-flow.md` 7절, 제안)

| 순서 | 로직 | UI |
| --- | --- | --- |
| 1 | **약속** — 생존 상태 알림(살아 있음 · 사망 대기 · 사망), 사망 대기 마감 시각 | 약속 검토 |
| 2 | 체력 계산 — 감소 · 무효 · 전환을 모아 한 번만 반영, 처리 번호로 중복 방지. 회복은 100 까지, 죽은 사람은 불가 | 체력 숫자 · 게이지 변화 (확정 값만) · 20 이하 경고색 |
| 3 | 사망 대기 5초 → 사망. 동시 사망은 한꺼번에 | 사망 대기 카운트 |
| 4 | 죽은 사람 — 턴 순서에서 빼고, 손패 · 함정 버림. 게임 중 나간 사람 처리 ⛔ | 사망 좌석 비활성 + "사망" |
| 5 | 에디터 테스트 — 동시 사망 · 사망 대기 중 회복 | 4클론 확인 |

**끝났다는 기준**: 체력 0 → 5초 사망 대기 → 사망 → 그 사람 턴을 건너뛴다 · 네 화면 동일.

### 기능 8 · 찹츄와 승리 (10/29 ~ 11/4)

**플레이어가 겪는 것**: 손패가 정확히 10장이면 찹츄 버튼이 켜진다. 누르고 다음 내 턴까지 10장을 지키면 이긴다. 마지막 1명이 살아남아도 이긴다. 결과 화면이 뜨고 방으로 돌아간다.
**기준 문서**: `07-win-condition.md`
**기획 결정 필요**: 찹츄 선언 시점(언제든 vs 내 턴) ⛔ · 결과 화면 구성 · 재대전 ⛔ · 방장이 나가면 게임 종료인지 ⛔ (`09-network.md` 9절 제안)

| 순서 | 로직 | UI |
| --- | --- | --- |
| 1 | **약속** — 찹츄 상태 알림, 결과 알림(승자 · 승리 유형) | 약속 검토 |
| 2 | 찹츄 선언 — 검사(정확히 10장), 10장이 아니게 되면 즉시 해제 | 찹츄 버튼 (10장일 때만 켜지는 표시용) · 좌석 찹츄 아이콘 |
| 3 | 판정 — 내 턴 시작 때 찹츄면 승리, 생존 1명이면 처치 승리, 전원 사망이면 무승부. 체인이 끝난 뒤 판정 | 결과 화면 — 승자 · 유형 · 재대전 / 나가기 ⛔ |
| 4 | 방장 이탈 = 게임 종료 ⛔ | 결과 → 방 / 로비 복귀 |
| 5 | 에디터 테스트 — 세 가지 결말 | 4클론 확인 |

**끝났다는 기준**: 처치 승리 · 찹츄 승리 · 무승부가 각각 결과 화면까지 간다. **이 기능이 끝나면 게임이 처음부터 끝까지 돈다.**

## 7. 운영 규칙

1. 씬 · 프리팹 · Unity 에셋은 UI 개발만 만진다. 로직은 `.cs` 만.
2. 약속 파일 변경은 개발 2명 모두 리뷰한다. 약속 PR 은 기능 작업보다 먼저, 작게.
3. 서버 코어는 Photon 없이 에디터 테스트가 가능하게 만든다.
4. 로컬 서버는 끝까지 유지한다. 서버 코어가 나오면 흉내 코드를 지우고 진짜 코어를 돌린다.
5. UI 는 규칙을 판정하지 않는다. 표시용 조건(찹츄 버튼 켜기 등)만 예외, 최종 판정은 방장 기기.
6. 구현 근거는 `docs/systems/` 의 `확정` 뿐이다.
7. 코드를 바꾼 PR 이 문서의 "현재 구현 상태" 절도 같이 고친다.
8. 한 PR 에 폴더 이동과 로직 변경을 섞지 않는다.
9. 하지 말아야 할 것은 [`refactoring-plan.md`](refactoring-plan.md) 5부.
