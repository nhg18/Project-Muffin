# 01. 게임플레이 흐름

**최종 수정일**: 2026-09-17
**분류**: Core(플레이) / MVP(로비·방) / 미정(로그인)

---

## 1. 전체 흐름

```
게임 실행 → 로그인 → 메인 메뉴 → 방 생성/참가 → 로비(Room) → 게임 시작
         → 플레이(턴 진행) → 승리 판정 → 결과 화면 → 메인 메뉴
```

---

## 2. 단계별 정의

| 단계 | 진입 조건 | 플레이어 행동 | 종료 조건 | 다음 단계 | 구분 |
| --- | --- | --- | --- | --- | --- |
| 로그인 | 앱 실행 | 로그인 수단 선택 | 로그인 성공 | 메인 메뉴 | **미정** |
| 메인 메뉴 | 로그인 완료 | 방 생성/참가, 친구 목록 | 방 생성 또는 참가 선택 | 방(Room) | **미정** |
| 방(Room) | 방 생성/참가/초대 수락 | 대기, 설정, 초대, 나가기 | 방장이 시작 버튼 클릭 | 게임 시작 | 초안 |
| 플레이 | 게임 시작 | 턴 진행 (드로우 / 행동 카드 / 함정 설치) | 승리 조건 충족 | 결과 화면 | 확정 |
| 결과 화면 | 승리 판정 확정 | 결과 확인, 재대전/나가기 | 선택 완료 | 메인 메뉴 | **미정** |

---

## 3. 게임 시작 시퀀스 (확정 + 제안)

마스터 클라이언트가 순서대로 수행한다.

| # | 처리 | 담당 | 구분 |
| --- | --- | --- | --- |
| 1 | 게임 씬 로드 (모든 클라이언트) | 마스터 (`PhotonNetwork.LoadLevel`) | 확정 |
| 2 | 모든 클라이언트 씬 로드 완료 대기 | 마스터 | **제안** |
| 3 | 덱 생성 + 셔플 + 카드 인스턴스 ID 부여 | 마스터 | 확정(셔플) / 제안(인스턴스 ID) |
| 4 | 모든 플레이어 HP 100으로 초기화 | 마스터 | 확정 |
| 5 | 각 플레이어에게 초기 손패 5장 배분 | 마스터 | 확정 |
| 6 | 턴 순서 무작위 결정, 첫 턴 플레이어 지정 | 마스터 | 확정 |
| 7 | 좌석 배치 계산 (각 클라이언트 로컬) | 각 클라이언트 | 확정 |
| 8 | 플레이 시작 | — | 확정 |

> ⚠ 현재 코드는 2번(로드 완료 대기), 3번(셔플·인스턴스 ID), 4번(HP 초기화)이 없고,
> 5번은 각 클라이언트가 자기 몫을 각자 요청하는 방식이며, 6번은 무작위가 아니라 `PlayerList[0]` 고정이다.

## 5. 플레이 중 하위 흐름

```
턴 시작
  ↓
메인 행동 선택 (드로우 / 행동 카드)   ← 20초(제안) 제한
  ↓ 행동 카드인 경우
카드 처리 체인 (반응 5초 × N회)
  ↓
체인 처리 완료
  ↓
승리 조건 판정
  ↓ 미충족
턴 종료 → 다음 플레이어 턴 시작
```

함정 설치와 함정·카운터 발동은 위 흐름과 별개로 **언제든** 끼어들 수 있다 (`04-card.md`).

## 6. 예외

| 상황 | 처리 | 구분 |
| --- | --- | --- |
| 게임 중 플레이어 이탈 | 해당 플레이어를 턴 순서·대상 후보에서 제외. 손패·함정은 버림 더미로 | **제안** (최종 사망과 동일 처리) |
| 남은 인원이 1명 | 해당 플레이어 승리 | 확정 |
| 전원 최종 사망 | 무승부 | 확정 |
| 마스터 이탈 | **미정** (`09-network.md` 9절) | 미정 |
