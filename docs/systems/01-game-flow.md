# 01. 게임플레이 흐름

**최종 수정일**: 2026-11-28 (씬 빌드 순서 · 전역 매니저 4종 · 타이틀 접속 시점 — 지금 프로젝트대로). 2026-11-26 (2절 로비 = 「랜덤 매칭」(매치) · 방 생성 · 참가는 개발자 모드 · 매치 방은 저절로 시작 — `08-room` 4절, PM). 이전: 2026-11-07
**분류**: Core(플레이) / MVP(로비·방·로그인 — `23-login`)

---

## 1. 전체 흐름

```
게임 실행 → 로그인 → 메인 메뉴 → 방 생성/참가 → 방(Room) → 게임 시작
         → 플레이(턴 진행) → 승리 판정 → 결과 화면 ─「한 판 더!」 전원 준비→ 플레이 / ─「로비로」 · 45초→ 로비
                                              └「나가기」→ 메인 메뉴
```

결과 화면은 새 씬이다 — 게임이 끝나면 방은 닫힌 채 방장이 전원을 결과 씬으로 옮기고, 전원이 「한 판 더!」 로 준비하면 새 판, 「로비로」 · 45초 자동 이동이면 방을 나간다 (`07-win-condition` 11절, 확정 2026-11-17 — 2026-11-07 「방의 한 상태」 폐기).

## 3. 게임 시작 시퀀스 (확정 + 제안)

마스터 클라이언트가 순서대로 수행한다.

| # | 처리 | 담당 | 구분 |
| --- | --- | --- | --- |
| 1 | 게임 씬 로드 (모든 클라이언트) | 마스터 (`PhotonNetwork.LoadLevel`) | 확정 |
| 2 | 모든 클라이언트 씬 로드 완료 대기 | 마스터 | **제안** |
| 3 | 덱 생성 + 셔플 + 카드 인스턴스 ID 부여 | 마스터 | 확정(셔플) / 제안(인스턴스 ID) |
| 4 | 모든 플레이어 HP 100으로 초기화 | 마스터 | 확정 |
| 5 | 각 플레이어에게 초기 손패 5장 배분 | 마스터 | 확정 |
| 6 | 턴 순서 무작위 결정, 첫 턴 플레이어 지정 | 마스터 | 확정 |
| 7 | 좌석 배치 계산 (각 클라이언트 로컬) | 각 클라이언트 | 확정 |
| 8 | 플레이 시작 — 첫 턴은 **화면의 게임 시작 연출 + 시작 손패 배분 동안 멈춰 있다** (`10-ui` 5-2 「게임 시작」). 멈춘 동안 요청은 거절되고 봇도 기다리며, 턴 15초는 멈춤이 풀린 뒤부터 센다(알리는 마감 = 15초 + 멈춤). 길이 = 연출 3.1 + 0.48 × 인원 + 배분 0.15 × 5장 × 인원 + 틈 0.8초(화면 전환 덮개가 걷히는 시간 + 알림이 닿는 시간) (4인 8.8초 · 2인 6.4초, `GameServer.OpeningSeconds`). 시작 알림 묶음 맨 앞에 「게임 시작」 알림(섞은 턴 순서 · 멈춤 초)이 가고, 화면은 이것을 받았을 때만 시작 연출을 튼다. 대폭발 새 판은 멈추지 않는다 | — | 확정(플레이 시작) / 제안(첫 턴 멈춤, 2026-11-28) |

### 전역 매니저 (부트스트랩 씬 없음)

부트스트랩 씬은 없다. 전역 매니저는 `Resources/Bootstrap/` 의 프리팹으로 두고, 첫 씬이 로드되기 전에 자동으로 생성된다. 어느 씬에서 시작해도 매니저가 있다.

| 매니저 | 프리팹 | 비고 |
| --- | --- | --- |
| `NetworkManager` | `Resources/Bootstrap/NetworkManager.prefab` | 타이틀에서 시작하면 약관 동의 · 로그인 뒤에 접속한다 (`23-login` 3절 #9). 다른 씬(디버그 로비 등)에서 시작하면 `Start()` 에서 바로 접속 |
| `PopupManager` | `Resources/Bootstrap/PopupManager.prefab` | 팝업 캔버스 · 레이어 3종 포함 |
| `SoundManager` | `Resources/Bootstrap/SoundManager.prefab` | 배경음 · 효과음 |
| `ScreenTransition` | `Resources/Bootstrap/ScreenTransition.prefab` | 화면 전환 연출 (`15-screen` 9절) |

덕분에 **어느 씬에서 Play 를 눌러도 동일하게 동작한다.** 매니저를 씬에 배치할 필요가 없고,
씬에 이미 배치돼 있어도 싱글톤 중복 방지 로직이 씬 쪽 사본을 정리한다.
매니저를 추가할 때는 프리팹을 `Resources/Bootstrap/` 에 넣고 생성 목록에 이름을 추가한다.

## 5. 플레이 중 하위 흐름

```
턴 시작
  ↓
메인 행동 선택 (드로우 / 행동 카드)   ← 15초 제한 (확정, 03-turn)
  ↓ 행동 카드인 경우
카드 처리 체인 (반응 5초 × N회)
  ↓
체인 처리 완료
  ↓
승리 조건 판정
  ↓ 미충족
턴 종료 → 다음 플레이어 턴 시작
```

함정 **설치**는 자신의 턴, 메인 행동 전에 몇 장이든 할 수 있다 (`03-turn.md` 3절 · `04-card.md` 6절). 함정 · 카운터 **발동**은 위 흐름과 별개로 반응 시간에 끼어든다 (`04-card.md`).
