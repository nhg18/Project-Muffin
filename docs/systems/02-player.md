# 02. 플레이어 · 좌석

**최종 수정일**: 2026-09-17
**분류**: Core

---

## 1. 목적

방에 입장한 각 플레이어의 식별, 좌석 배치, 상태 데이터를 관리한다.

## 2. 플레이어 속성

| 속성 | 타입 | 기본값 | 원본 소유 | 공개 범위 | 구분 |
| --- | --- | --- | --- | --- | --- |
| `actorNumber` | int | Photon 발급 | Photon | 전체 | 확정 |
| `nickname` | string | 입력값 | Photon | 전체 | 확정 |
| `hp` | **int** | 100 | 마스터 | 전체 | 확정 |
| `seatIndex` | int | 계산값 | 각 클라이언트 로컬 | 로컬 | 확정 |
| `hand` | 카드 목록 | 5장 | 마스터 | **소유자만** | 확정 |
| `trapSlots` | 카드 목록(최대 3) | 비어 있음 | 마스터 | **소유자만** (개수는 전체) | 확정 |
| `lifeState` | Alive / DeathPending / Dead | Alive | 마스터 | 전체 | 확정 |
| `isChapChu` | bool | false | 마스터 | 전체 | 확정 |
| `handCount` | int | 5 | 마스터 | 전체 | 확정 |
| `trapCount` | int | 0 | 마스터 | 전체 | 확정 |

> 노션 원본의 **이름 없는 속성 4칸**은 위 `lifeState / isChapChu / handCount / trapCount` 로 해석한 것이다. → **확인 필요 (가정)**

> ⚠ 현재 코드는 HP가 `float`(`PlayerModel.CurrentHP`, `GameStatus.MaxHp`, `PlayerInfoData.HP`)이다. 기획은 정수이므로 `int`로 통일한다.

## 3. 좌석 배치

### 규칙 (확정)

1. 자신은 **항상 0번 자리**(화면 하단)에 배치한다. 모든 클라이언트에서 동일하게 동작한다.
2. 나머지 플레이어는 `actorNumber` 오름차순으로 정렬해 배치한다.

| 인원 | 배치 (인덱스) |
| --- | --- |
| 2명 | 상대 1명 → 2번 자리 (인덱스 2, 정면) |
| 3명 | 상대 2명 → 1번, 2번 자리 |
| 4명 | 상대 3명 → 1번, 2번, 3번 자리 |

### 구현 요구사항

* 좌석 배치는 **각 클라이언트가 로컬에서 계산**한다. 네트워크로 전송하지 않는다.
* 같은 입력(내 actorNumber + 참가자 목록)이면 항상 같은 결과가 나와야 한다.
* 좌석 계산은 **한 곳에서만** 수행하고, 손패 UI와 플레이어 정보 UI가 그 결과를 공유한다.

> ⚠ 현재 `SeatManager`와 `HandSeatManager`가 각각 `Start()`에서 좌석을 계산해 실행 순서에 의존한다.

## 4. 상태 흐름 (생존 상태)

```
Alive → (HP 0) → DeathPending → (대응 처리) → Alive 복귀
                                            → Dead (최종 사망)
```

상세 규칙은 [`06-health.md`](06-health.md).

## 5. UI

| UI 요소 | 표시 조건 | 표시 내용 | 갱신 시점 |
| --- | --- | --- | --- |
| 닉네임 | 항상 | 닉네임 | 입장 시 1회 |
| HP 텍스트 | 항상 | `현재 HP / 100` | HP 변경 브로드캐스트 |
| HP 게이지 | 항상 | 비율 바 | HP 변경 브로드캐스트 |
| HP 경고색 | HP 1~20 | 게이지·숫자 경고색 | 위험 상태 진입/해제 |
| 손패 장수 | 항상 | 숫자 | handCount 변경 |
| 함정 슬롯 | 항상 | 슬롯 개수 + 뒷면 카드 | trapCount 변경 |
| 턴 표시 | 자신의 턴일 때 | 프로필 초록색 외곽선 | 턴 변경 |
| 사망 대기 | DeathPending | "사망 대기" + 남은 대응 시간 | 상태 변경 |
| 최종 사망 | Dead | 영역 비활성 + "사망" | 상태 변경 |
| 찹츄 표시 | isChapChu | 찹츄 아이콘 | 상태 변경 |

상세는 [`10-ui.md`](10-ui.md).

## 6. 예외

| 상황 | 처리 | 구분 |
| --- | --- | --- |
| 게임 중 퇴장 | 좌석 UI 제거, 턴 순서·대상 후보에서 제외 | 확정(UI 제거만 구현됨) |

| 남은 플레이어가 1명 | 즉시 승리 판정 | 확정 |

## 7. 현재 구현 상태

| 항목 | 상태 |
| --- | --- |
| 좌석 배치 알고리즘 (`SeatManager.GetSeatAssignments`) | 구현됨. 기획과 일치 |
| 좌석 UI (닉네임 / 턴 표시) | 구현됨 |
| HP UI | **미동작** — HP를 쓰는 코드가 없고, 읽는 키(`"HP"` / `"PlayerHP"`)도 서로 다름 |
| 손패 장수 UI (`PlayerSeat.SetCardCountUI`) | 함수만 존재, **호출하는 곳 없음** |
| HP 게이지 (`PlayerSeat.SetHpGauge`) | 함수만 존재, **호출하는 곳 없음** |
| 함정 슬롯 | **미구현** |
| 생존 상태 | **미구현** |
| 찹츄 상태 | **미구현** (레거시 `GameRule.isChapChu` bool만 존재) |
| 좌석 계산 중복 | `SeatManager` + `HandSeatManager` 이중 호출 |

## 8. 미정 / 결정 필요

1. 플레이어 속성표 미명명 4칸의 실제 용도 (본 문서 2절의 해석 확인)
2. 재접속 시 좌석 / 손패 / 함정 복원 방식
3. 게임 중 퇴장이 "최종 사망"과 동일 처리인지
