# 05. 덱 · 손패 · 버림 더미

**최종 수정일**: 2026-09-30
**분류**: Core

---

## 1. 목적

카드를 무작위로 지급하고, 소진 시 재생성하는 규칙을 정의한다.

---

## 2. 핵심 수치

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 초기 지급 카드 수 | **5장** | 확정 |
| 드로우 위치 | 덱의 맨 위(Top) | 확정 |
| 1회 드로우 장수 | 1장 (메인 행동) | 확정 |
| 덱 총 구성 (카드별 매수) | — | **미정** |

> 초기 손패 수는 `GameServer.Deck.cs` 의 코드 상수 `InitialHandCount = 5` 한 곳이다 (옛 `GameStatus.StartHandCount` 는 삭제). 마스터가 `DealInitialHands` 로 일괄 배분한다.

---

## 3. 동작 — 게임 시작

| # | 처리 | 담당 |
| --- | --- | --- |
| 1 | `DeckRecipe`(카드 ID 목록)로 메인 덱 생성 | 마스터 |
| 2 | 카드 1장마다 **카드 인스턴스 ID** 부여 | 마스터 |
| 3 | 덱 무작위 셔플 | 마스터 |
| 4 | 각 플레이어에게 5장씩 배분 | 마스터 |
| 5 | 각 플레이어에게 **자기 손패 내용만** 전송 | 마스터 → 대상 지정 RPC |
| 6 | 모든 플레이어의 손패 **장수**를 공개 | 마스터 → Player CustomProperties |
| 7 | 덱 잔여 장수를 공개 | 마스터 → Room CustomProperties |

> 1 ~ 4 · 6 · 7 은 `GameServer.Deck.cs` 에 구현돼 있다. 5 는 드로우 1장마다 주인에게만 보낸다 (`SendDrawnCard`).

---

## 4. 동작 — 드로우

```
[클라이언트] 드로우 요청
     ↓
[마스터] 검증: 자신의 턴 + 메인 행동 미사용 + (덱 또는 버림 더미에 카드 존재)
     ↓ 실패 → 거절
[마스터] 덱 맨 위 1장 제거 → 요청자 손패에 추가
     ↓
[마스터] 요청자에게 카드 내용 전송 (비공개)
[마스터] 전체에 "actorNumber가 1장 드로우함" + 손패 장수 + 덱 잔여 장수 전파
     ↓
[전체]   드로우 연출 (뽑은 본인은 앞면, 나머지는 뒷면)
```

* 드로우는 **항상 덱 맨 위** 카드다.
* 카드 효과에 의한 드로우(A06, A12 등)도 같은 경로를 쓴다. 다만 메인 행동을 소비하지 않는다.

---

## 5. 예외 — 덱 소진

| 조건 | 처리 | 구분 |
| --- | --- | --- |
| 덱이 0장이 되고 드로우가 필요할 때 | 버림 더미 전체 회수 → 무작위 재셔플 → 새 덱 생성 → 진행 재개 | 확정 |
| 덱과 버림 더미가 **모두** 0장일 때 | **미정 — 결정 필요** | 미정 |

> 회수 · 재셔플은 구현돼 있다. 둘 다 0장이면 현재 코드는 **미정 확정 전 임시로** 상태 변경 없이 거절만 한다.

## 6. 손패

| 항목 | 규칙 | 구분 |
| --- | --- | --- |
| 손패 상한 | 없음 | **가정** (기획에 상한 언급 없음. 찹츄는 "정확히 10장" 조건) |
| 손패 내용 공개 | 소유자만 | 확정 |
| 손패 장수 공개 | 전체 | 확정 |
| 손패 정렬 | **미정** (타입별/ID순/드로우순) | 미정 |
| 최종 사망 시 | 손패 전부 버림 더미로 이동 | 확정 |

### 손패를 조작하는 카드 (요구사항)

`11-card-list.md`의 다수 카드가 다음을 요구한다. **마스터가 손패 내용을 알고 있어야만 구현 가능하다.**

| 요구 | 해당 카드 |
| --- | --- |
| 대상 손패에서 무작위 N장 획득 | A04, A24, T08 |
| 대상 손패에서 무작위 N장 강제 버림 | A05, A15, A23, T07, T11, T12, T14 |
| 손패 전체 교환 | A11, A18 |
| 손패에서 카드 1장 선택해 전달 | A24 |
| 덱 위 N장 확인 후 1장 선택 | A25 |
| 손패 무작위 1장 공개 | C14 |

> 마스터가 손패 내용 원본을 가진다 (`PlayerState.Hand`, 2026-10-01). 위 카드들은 이 원본 위에서 구현한다.

## 7. 버림 더미

| 항목 | 규칙 | 구분 |
| --- | --- | --- |
| 진입 | 사용·발동된 모든 카드 (무효화·불발 포함) | 확정 |
| 진입 | 강제 버림된 카드 | 확정 |
| 진입 | 최종 사망 플레이어의 손패·설치 함정 전부 | 확정 |
| 공개 | 전체 공개 | 확정 |
| 재사용 | 덱 소진 시 회수 후 셔플 | 확정 |
| 맨 위 카드 표시 | **미정** (UI에 마지막 버린 카드를 보여줄지) | 미정 |

> 버림 더미 원본은 마스터에 있다 (`GameServer.Deck.cs`). 카드는 방장이 승인한 카드 사용으로만 들어간다 — 클라가 보내는 버림 요청은 없다 (2026-10-06 임시 버림 경로 삭제).

## 8. 데이터 구조

| 에셋 | 역할 | 위치 |
| --- | --- | --- |
| `CardData` (ScriptableObject) | 카드 1종의 정의 (id, 이름, 이미지, 타입, 대상, 조건, 효과) | `Assets/Cards/*.asset` |
| `CardDatabase` (ScriptableObject) | id → `CardData` 조회 | `Assets/Cards/CardDatabase.asset` |
| `DeckRecipe` (ScriptableObject) | 덱 구성 (카드 ID 목록) | `Assets/Cards/Card pool/*.asset` |

* `DeckRecipe`는 **같은 ID를 여러 번** 넣어 매수를 표현한다.
* 덱 구성(어떤 카드를 몇 장)은 **미정**이다.

## 10. 현재 구현 상태

| 항목 | 상태 |
| --- | --- |
| 덱 원본 | 마스터 (`GameServer.Deck.cs`, 순수 C#). Photon 전송은 `PunGameServer` — `TempGameScene` 에만 배치 |
| `DeckRecipe`로 덱 초기화 · 인스턴스 ID 부여 | 구현됨 (`InitDeck`). 덱 구성은 미정이라 **임시 레시피(가정)** `NewDeckRecipe` — 행동 카드 ID 1 · ID 4 각 20장 = 40장 (2026-10-06). 덱이 비면 시작 배분 · 뽑기 · 카드 효과 뽑기 모두 `DrawOne` 에서 버림 더미를 섞어 다시 채우고 `GameEvents.OnDeckRefilled` 로 알린다(연출용) |
| 셔플 | 구현됨 (Fisher–Yates) |
| 초기 배분 | 구현됨 — 마스터가 `DealInitialHands` 로 전원에게 5장 일괄 배분 |
| 드로우 | 구현됨 — 요청 → 턴 검증 → 덱 맨 위 1장 → **드로우 후 턴 종료** (03 3절). 메인 행동 중 카드 사용 쪽 제한은 기능 4 |
| 덱 동기화 | 잔여 장수만 Room Property (`RoomProps.DeckCount`). 옛 덱 전체 배열 동기화는 삭제 |
| 손패 내용 비공개 | 구현됨 — 뽑은 카드(인스턴스 ID · 종류 ID)는 주인에게만 (`SendDrawnCard` → `RPC_OnDrawn`). UI 이벤트(`GameEvents.OnDrawn`)도 인스턴스 ID 를 넘긴다 (2026-10-06) |
| 손패 장수 동기화 | 구현됨 — 마스터만 기록 (`PlayerProps.HandCount`) |
| 손패 **내용** 원본 | 마스터 (`PlayerState.Hand`, 2026-10-01). 배분 · 드로우 때 넣고 버릴 때 꺼낸다 |
| 덱 소진 재생성 | 구현됨 — 버림 더미 회수 → 재셔플 |
| 버림 더미 | 마스터에 있음. 승인된 카드 사용(`GameServer.PlayCard`, 인스턴스 ID)으로만 들어간다 — 인스턴스 ID 유지. 임시 버림 요청(`RequestDiscard`, 종류 ID)은 삭제 (2026-10-06). 강제 버림은 카드 효과 구현 때 |
| 버림 더미 장수 공개 | 구현됨 — 방장이 `RoomProps.DiscardCount` 에 기록(시작 0 · 버릴 때 · 덱 재생성 때 0) → `GameEvents.OnDiscardCountChanged` (2026-10-06). 화면 표시 여부는 **미정** (11절 5) |
| 카드 사용 시 손패에서 제거 | 부분 — 요청한 클라이언트가 승인 전에 스스로 지운다 (04 현재 구현 상태와 같음) |
| 상대 손패 장수 보정 | 구현됨 (`OtherPlayerHandPresenter`, 늘 때 · 줄 때 모두 맞춘다) |
