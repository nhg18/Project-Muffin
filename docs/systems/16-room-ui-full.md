## 1. 목적

룸은 **같이 할 사람을 모으고, 모였는지 확인하고, 시작하는** 화면이다. 플레이어가 머무는 시간은 보통 수십 초. 룸이 바로 답해야 할 질문은 셋이다.

| 질문 | 답하는 요소 |
| --- | --- |
| 친구를 어떻게 데려오나 | 방 코드 + 「복사」 「공유」, 빈 칸 「초대」 (로그인 이후) |
| 누가 들어왔나 · 몇 명인가 | 플레이어 칸 4개 (캐릭터 + 이름표 + 방장 표시), 인원 표시, 로그 |
| 언제 시작하나 | 방장: 「게임 시작」 버튼 / 참가자: 같은 자리의 대기 안내 |

이 셋 밖의 것(설정 · 채팅 · 준비 · 방 옵션)은 두지 않는다 (10절).

## 2. 판정 주체

| 대상 | 판정 · 저장 | 룸 화면이 하는 일 |
| --- | --- | --- |
| 입장 · 퇴장 · 방장 교체 · 인원 | **네트워크 서버**(Photon) 가 방 상태를 가진다. 방장 판정 없음 | 콜백을 받아 칸 · 인원 · 로그 · 시작 버튼을 갱신한다 |
| 게임 시작 | **방장만** 요청할 수 있다. 방을 닫고 전원을 게임 씬으로 보내는 것도 방장 (08-room 4절) | 방장 화면: 버튼 / 참가자 화면: 대기 안내. 씬 이동은 받는다 |
| 방장 위임 | 네트워크 서버 기본 동작 — 남은 사람 중 먼저 들어온 사람 (08-room 5절 #5) | 표기 갱신 + 새 방장에게 토스트 |
| 플레이어 내보내기 (제안) | **방장만** 요청. 서버가 대상의 연결을 끊는다 | 방장 화면에만 입력. 대상은 로비로 + 안내 |
| 캐릭터 · 이펙트 공개 | **방 입장 때 1회**, 각자가 자기 장착 번호 5개를 모두에게 (19 2절). 방장 판정 없음 | 받은 번호로 칸의 캐릭터를 그린다. 모르는 번호는 기본 |
| 방 코드 복사 · 공유 | **로컬** (OS 클립보드 · OS 공유 시트) | 즉시 |
| 친구 초대 보내기 · 받기 · 30초 만료 | **친구 서버** (13-friend 4절) | 요청 · 배너 표시 · 수락 · 거절 |
| 친구 추가 (칸 탭 → 「친구 추가」) | 친구 서버 (13-friend 2절) | 요청 · 결과 토스트 |
| 연결 끊김 | 네트워크 서버 — 즉시 퇴장 (08-room 7절) | 로비로 이동 + 안내 |

**게임 규칙 판정은 룸에 없다.** 09-network 의 방장 원칙은 시작 요청 · 내보내기 두 입력에만 걸린다.

## 3. 핵심 규칙

| # | 규칙 | 구분 |
| --- | --- | --- |
| 1 | **동작하는 기능만 둔다.** 「로그인 이후」 요소는 친구 서버가 붙기 전에는 화면에 두지 않는다 | 확정 (14-lobby-ui 3절 #1 · 08-room 5절 #7) |
| 2 | **시작은 방장만, 2명 이상일 때.** 1명이면 버튼은 보이되 비활성 + 이유 글자 | 확정 (08-room 5절 #1 · #2) |
| 3 | 참가자에게는 시작 버튼 **자리에 대기 안내**("방장이 시작하면 바로 시작돼요")를 둔다. 눌리지 않는 비활성 버튼을 보이지 않는다 | 제안 — "보이는데 안 눌리는 UI" 금지와 같은 원칙 |
| 4 | **준비(Ready) 없음 · 방 설정 없음.** 인원 4 · 공개 고정 | 확정 (08-room 5절 #6 · #7) |
| 5 | 방장이 나가면 **위임**. 방장 표시 · 시작 버튼 · 대기 안내가 전원 화면에서 즉시 바뀌고, 새 방장에게만 토스트 | 확정 (위임, 08-room 5절 #5) / 제안 (토스트) |
| 6 | 플레이어 칸은 **4개 고정**, **입장 순서**로 채운다. 순서는 모든 클라이언트에서 같다 (방장 = 1번 칸이 아니다 — 방장은 표시로 구분). 내 칸에는 「나」 표시 | 제안 — 서로 말로 가리킬 때 "두 번째 칸" 이 같은 사람이어야 한다. 02-player 의 "나 = 0번" 은 인게임 좌석 규칙이고 룸에는 적용하지 않는다 |
| 7 | 칸마다 그 플레이어가 **장착한 캐릭터**(+ 오라)가 선다. 지금은 기본 캐릭터 1종 | 확정 (표시 — 19 3절 #8 합의 · 분류 MVP) / 제안 (오라 · 장착 반영은 로그인 이후) |
| 8 | 방 코드는 **항상 보이고**, 한 번 탭으로 **복사**, 모바일에서는 **OS 공유 시트**로 보낼 수 있다 | 제안 — 룸에 들어온 사람이 가장 먼저 하는 일이 "코드 보내기" 다 |
| 9 | 로그는 **입장 · 퇴장 · 방장 교체** 3종, 최대 30줄. 화면에는 **최근 몇 줄만** 보이고 탭하면 전부 펼친다 | 확정 (3종 · 30줄, 08-room 5절 #4) / 제안 (접기 · 펼치기) |
| 10 | 룸 안에서 **바꾸는 것은 없다** — 닉네임 · 캐릭터 · 이펙트 장착은 로비에서만. 룸은 보여 주기만 한다 | 확정 (19 3절 #7 합의 → 제안 승계) |
| 11 | 팝업은 **한 번에 하나.** 팝업이 열려 있으면 화면 안 버튼은 전부 무시. 팝업 위에 겹치는 것은 초대 배너 · 토스트 · 로딩 · 경고 팝업(공용)만 | 제안 (17 3절 #4 와 같음) |
| 12 | Android 뒤로가기 = ① 열린 팝업 닫기 → ② 팝업이 없으면 **나가기 버튼과 같은 동작** (확인 팝업 포함) | 제안 |
| 13 | 시작은 **방장 탭 → 방 닫힘(참가 · 랜덤 매칭 대상 제외) → 전원 「시작 중」 표시 → 게임 씬.** 시작이 걸린 뒤에는 누구도 나가기 · 초대 입력을 쓸 수 없다 | 확정 (방 닫기, 08-room 5절 #8) / 제안 (시작 중 표시 · 입력 잠금) |
| 14 | 입장 · 퇴장 때 칸은 **즉시** 바뀐다. 열림 · 닫힘 연출은 없다. 룸 입장 이펙트(19 5절 「입장」)를 룸에서도 재생할지는 미정 | 제안 / 미정 (19 미정 #6) |
| 15 | 터치 영역 44pt · 글자 11pt 이상 (15-screen 5절). 가장자리 요소는 Safe Area 안 | 확정 (기존) |
| 16 | 비공개 정보 없음 — 룸의 모든 표시(닉네임 · 캐릭터 · 방장 · 인원 · 로그)는 **방 안 전원에게 같다.** 친구 서버 정보(친구인지 · 친구 코드)는 본인 화면에만 | 제안 |

## 6. 화면 상태

## 7. UI 요소별 명세

요소마다 **무엇 · 언제 · 내용 · 동작 · 상태 · 시점**. 자리는 "어느 묶음에 속하는가" 만 적고 좌표 · 크기는 적지 않는다.

### 7-0. 구성 개요 (묶음만 — 배치 수치 · 디자인 아님)

```
[나가기]        방 코드 ABCD [복사] [공유]        인원 2 / 4
      ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐
      │캐릭터│ │캐릭터│ │ 빈 칸 │ │ 빈 칸 │     ← 입장 순서, 4칸 고정
      │이름표│ │이름표│ │ 초대  │ │ 초대  │
      │ 👑 나 │ │      │ │      │ │      │
      └──────┘ └──────┘ └──────┘ └──────┘
 로그 (최근 3줄, 탭 → 펼침)      [게임 시작] / "방장이 시작하면 바로 시작돼요"
                                              ↑ 같은 자리, 역할에 따라 바뀜
```

위쪽 = 방 정보 (코드 · 인원 · 나가기), 가운데 = 사람 (칸 4개), 아래쪽 = 진행 (로그 · 시작). 초대 배너 · 토스트 · 팝업은 그 위에 겹친다. 어느 묶음을 어디에 두는지는 디자인 때 정한다 — **제안**.

## 9. 예외
