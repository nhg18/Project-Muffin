# 14. 로비 화면 UI

**최종 수정일**: 2026-11-07
**분류**: MVP
**출처**: 2026-09-25 로비 개편 결정 (플랜 세션). 로비 전용 디자인 시안 없음 — 크기 · 배치는 이 문서, **비주얼과 구조는 타이틀([`12-title-ui.md`](12-title-ui.md))과 통일**한다 (2026-09-25 결정: 배경 · 버튼 스타일 · 화면 구조를 타이틀과 같게).

> 방 생성 · 참가의 **규칙**(코드 · 인원 · 실패 처리)은 [`08-room.md`](08-room.md)가 기준이다. 이 문서는 로비 **화면**만 다룬다.

---

## 1. 목적

접속을 마친 플레이어가 방을 만들거나 참가하는 화면. 타이틀([`12-title-ui.md`](12-title-ui.md)) 다음, 방([`08-room.md`](08-room.md)) 이전.

## 2. 판정 주체

로비 화면의 판정은 전부 **로컬**이다. 버튼은 `NetworkManager`에 방 생성 · 참가를 **요청**만 하고, 결과(성공 → 방 씬 이동 / 실패 → 안내)는 Photon 콜백으로 받는다.

## 3. 핵심 규칙

| # | 규칙 | 구분 |
| --- | --- | --- |
| 1 | 화면에는 **지금 동작하는 기능만** 둔다. 기능이 없는 버튼(설정 · 친구 · 프로필 편집 등)은 두지 않는다 — "보이는데 안 눌리는 UI" 금지 | 확정 (2026-09-25) |
| 2 | 로비에서 하는 일은 넷이다: **랜덤 매칭 · 방 만들기 · 방 참가 · 혼자 하기** | 확정 (2026-09-25) / 확정 (혼자 하기, 2026-11-06 `18-bot` 10절) |
| 3 | 방 참가 코드 입력과 실패 안내는 **공용 팝업**을 쓴다 (`InputPopup` · `WarningPopup`). 로비 전용 팝업을 만들지 않는다 | 확정 |
| 4 | 로비 화면은 닉네임 외에 플레이어 정보를 표시하지 않는다 (전적 · 친구 코드 · 프로필 이미지는 기획 미확정) | 확정 (2026-09-25) |
| 5 | **타이틀과 같은 구조 · 같은 비주얼 언어.** 배경은 타이틀 일러스트 + 오버레이, 버튼은 `PillButton` 프리팹 | 확정 (2026-09-25) |

## 4. 주요 수치

### 4-1. 캔버스

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 기준 해상도 | 1920 × 1080 | 확정 (타이틀과 동일) |
| 스케일 방식 | Scale With Screen Size · **Expand** (`15-screen.md` 3절) | 확정 |
| 화면 방향 고정 | **가로 고정** (`15-screen.md`) | 확정 (2026-09-25) |

> 아래 px 값은 전부 **1080 높이 기준 캔버스 좌표**다. 폰(가로, 화면 높이 ≈ 390pt)에서는 캔버스 1 ≈ 0.36pt.

### 4-2. 크기 기준 (모바일 가독성)

터치 영역 44pt 이상, 글자 11pt 이상 (Apple HIG. 타이틀 4-3절과 같은 기준).

| 요소 | 캔버스 값 | 폰 실제 크기 (390pt 높이 기준) | 구분 |
| --- | --- | --- | --- |
| 메인 버튼 | 480 × 200 | ≈ 173 × 72pt | 확정 (2026-09-25) |
| 메인 버튼 글자 | 56 | ≈ 20pt | 확정 (2026-09-25) |
| 닉네임 글자 | 48 | ≈ 17pt | 확정 (2026-09-25) |

## 5. 입력

| 입력 | 동작 | 조건 |
| --- | --- | --- |
| 랜덤 매칭 탭 | `NetworkManager.JoinRandomRoom()` 요청. 빈 방이 있으면 참가, 없으면 새 방 생성 (08-room 4절) | 항상 |
| 방 만들기 탭 | **방 만들기 팝업**(`22-popup-ui` 2-1 · 5-2-1) 열기 — 「공개」 「비공개」 선택 + 「만들기」. 기본 선택 비공개 (제안) | 항상 (확정 2026-11-07, `08` 5절 #7) |
| 방 만들기 팝업 「만들기」 | 고른 공개 여부로 `NetworkManager.CreateRoom()` 요청. 버튼 글자 「만드는 중…」 (7절) | 팝업 열림 |
| 방 만들기 팝업 닫기 | 팝업 닫기, 로비 유지 | 항상 |
| 혼자 하기 탭 | **비공개**로 방 생성 + 봇 3 추가 → 방 화면. 자동 시작하지 않는다. 방장이 방 안에서 공개로 바꿀 수 있다 (`18-bot` 10절, 2026-11-06 확정 / 비공개 기본은 2026-11-07 제안) | 항상 |
| 방 참가 탭 | 방 코드 입력 팝업(`InputPopup`) 열기 | 항상 |
| 코드 입력 팝업 제출 | `NetworkManager.JoinRoom(code)` 요청 | 코드 입력됨 |
| 코드 입력 팝업 닫기 | 팝업 닫기, 로비 유지 | 항상 |

## 6. 화면 상태

| 현재 | 조건 | 다음 | 화면 변화 |
| --- | --- | --- | --- |
| 대기 | 방 만들기 탭 | 팝업 열림 | 방 만들기 팝업 (공개 / 비공개 · 「만들기」) |
| 팝업 열림 | 닫기 · 뒤로가기 | 대기 | 팝업 닫힘 |

**요청 중 문구** (확정 2026-11-07)

| 버튼 | 평소 글자 | 요청 중 글자 |
| --- | --- | --- |
| 랜덤 매칭 | 랜덤 매칭 | 찾는 중… |
| 방 만들기 팝업 「만들기」 | 만들기 | 만드는 중… (로비의 「방 만들기」 버튼은 팝업이 모달이라 그대로) |
| 혼자 하기 | 혼자 하기 | 만드는 중… (방 만들기와 같은 요청) |
| 코드 입력 팝업 「참가」 | 참가 | 들어가는 중… |

- 글자만 바뀌고 버튼 크기 · 색은 그대로. 「…」 는 말줄임표 한 글자(U+2026).
- 요청 중인 버튼이 아닌 버튼도 눌리지 않는다 (요청이 둘 겹치지 않게). 팝업 안 요청이면 팝업의 닫기 · 선택지도 잠긴다. 꺼진 모양은 `12-title-ui` 버튼의 비활성 상태와 같다.

**하이어라키** (TitleScene 과 같은 구조)

```
LobbyCanvas            1920×1080 · Expand
├ BG_Illust            타이틀과 같은 키 아트 (cover)
├ BG_Overlay           타이틀과 같은 세로 오버레이

└ MainButtons          정중앙 1560×200 · 간격 60
   ├ RandomMatchButton  PillButton 480×200 「랜덤 매칭」
   ├ CreateRoomButton   PillButton 480×200 「방 만들기」
   └ JoinRoomButton     PillButton 480×200 「방 참가」
```


- 총 폭 1560은 16:9(1920) 안에 들어가고, 넓은 폰(19.5:9 → 2340 폭)에서는 좌우 여백이 늘어날 뿐이다.
- ⚠ **4:3 태블릿(iPad)** 에서는 높이 기준 스케일 때문에 캔버스 폭이 1440으로 줄어 **양 끝 버튼이 60씩 잘린다** (2026-09-25 캡처로 확인). → **Expand 로 확정 · 적용** (2026-09-25, `15-screen.md`). iPad 캔버스 1920×1440 — 버튼 줄 x 192~1856 / 2048, 잘림 없음 (bounds 확인).
- 가장자리 요소(닉네임)는 모서리에 앵커한다. 화면이 늘어나면 같이 바깥으로 이동한다.
- 16:9 보다 넓은 화면(폰)에서는 Expand 가 높이 기준과 같아 세로 배치가 그대로다. 4:3 태블릿은 캔버스가 위아래로 늘어나 중앙 묶음 위아래 여백이 커진다.
