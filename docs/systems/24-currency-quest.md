## 1. 목적 · 범위

플레이를 계속할 이유(퀘스트)와 그 보상으로 **보이는 것**(치장)을 여는 길을 만든다. 재화는 게임 결과에 영향을 주지 않는다(19 3절 #1, P2W 금지).

| --- | --- |
| 재화 1종 — 이름 · 상한 · 표시 · 저장 · 누가 바꾸나 | 아이템 자체(종류 · 등급 · 장착 · 공개) — 19 |
| 획득 경로 — 판 종료 보상 · 일일 / 주간 / 업적 퀘스트 | 통계 항목의 정의 · 집계 — `07-win-condition` (결과 화면 통계) |
| 사용 경로 — 상자 1종(가격 · 확률 · 천장 · 중복 · 확률 표시 · 연출) | 로비 화면의 자리 · 크기 — `17-lobby-ui-full` 7-6 · 7-7 · 4-1 (이 문서는 요구 사항만, 6절) |
| 수급 균형표 (아이템 수 ↔ 모으는 데 걸리는 주 수) | 로그인 · 계정 · Cloud Save 계정 단위 — 23 |
| 유료 전환 때 바뀌는 것 (9절, 한 문단) | 결제 · 사업자 등록 · 확률형 아이템 법정 표시 — `store-release.md` (유료화 때) |

### 5-3. 전부 모으는 데 걸리는 주 수

전부 모을 때까지의 **순지출**(가격 − 환급) 을 4-6 수치(가격 150 · 70/25/5 · 천장 20 · 환급 50/100/250)로 2만 번 시뮬레이션한 값이다 (5-1 확정 뒤 16개 · 상자 대상 14 기준으로 2026-11-07 다시 돌림). 수치가 바뀌면 이 표만 다시 계산한다 (방법: 등급 뽑기 → 천장 적용 → 미보유 우선 또는 완전 무작위 → 환급, 상자 대상이 다 모일 때까지 반복. 주 수 = 평균 순지출 ÷ 5-2 주당 수입).

- 가격을 100 으로 내리면(환급 30/60/150) 평균 순지출 2,490 → 주 수는 약 **0.69배** (미보유 우선: 평균 플레이어 3.9주). 재조정 때 참고.

결과 화면의 순위 표 아래 **보상 줄** 한 줄: 「**+N 뼈다귀 · 퀘스트 n개 완료**」 (07 11-2 · `10-ui` 10절). N = 「판 결과 보고」 응답의 실제 지급액(하루 상한 · 최소 턴 수 · 봇 판 절반을 적용한 뒤 값), n = 이 판으로 조건을 채운 퀘스트 수(「받기」 는 로비 퀘스트 팝업에서). 응답 전에는 「보상 확인 중」, 보고가 실패하면 7-4. 자리 · 크기는 `10-ui` 10절 (미정 — 디자인). 확정 (2026-11-07, 1차).

## 9. Future — 유료 전환 때 바뀌는 것 (`1.0` 규칙이 아니다)
