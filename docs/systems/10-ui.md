# 10. 인게임 UI

**최종 수정일**: 2026-11-02
**분류**: Core

---

> 이 문서는 인게임 UI만 다룬다. 타이틀 화면은 [`12-title-ui.md`](12-title-ui.md).

## 1. 원칙

1. **UI는 판정하지 않는다.** 마스터가 브로드캐스트한 결과만 표시한다.
2. UI는 `GameEvents` 또는 Photon 콜백을 **구독**해서 갱신한다. 매 프레임 폴링하지 않는다.
3. 확정 전 값(예: 계산 중인 HP)을 최종 수치처럼 표시하지 않는다.
4. 연출(트윈·확대·이동)은 로컬 자유. 규칙에 영향을 주지 않는다.

### PC · 모바일 카드 입력 (2026-10-30 확정)

PC 는 마우스 커서가 있어 "올려만 둔" 상태가 있으므로 모바일과 단계 수가 다르다.

| 단계 | PC (마우스) | 모바일 (터치) |
| --- | --- | --- |
| 1 | 커서를 올리면 카드 자동 확대 | 탭 → 손패 펼침 (HandMode ON) |
| 2 | 드래그 앤 드롭으로 바로 대상 선택 · 사용 | 카드 탭 → 선택 + 확대 |
| 3 | — | 드래그 → 대상 선택 또는 사용 |

> 드롭한 카드는 **마스터 승인(`OnCardUsed`) 뒤에만** 손패에서 지운다 (2026-10-10). 요청 뒤 카드는 손패에 남아 있고, 거절되면 그대로다. 승인 대기 중 다른 카드를 드롭해도 UI 는 막지 않는다 — 서버가 거절한다.

| 카운터 사용 안내 | 반응 가능한 카드 보유 | **미정** — 어떻게 알리고 어떻게 고르는가 |
| 무효화 연출 | 카드가 무효화됨 | **미정** |

## 6. 대상 선택 UI

| 단계 | 동작 | 구분 |
| --- | --- | --- |

> 차단 범위는 **드롭 → 대상 확정(또는 취소·타임아웃)** 까지다. 마스터의 5초 반응 시간에는 카운터 카드를 내야 하므로 잠그지 않는다.

## 8. 팝업 / 토스트

| 종류 | 용도 |
| --- | --- |
| `WarningPopup` | 경고·에러 |
| `InputPopup` | 입력(방 코드 등) |

| `LoadingPopup` | 대기 — 로비의 방 만들기 · 참가 · 랜덤 매칭 대기 |
| 카드 거절 사유 | 마스터가 요청을 거절했을 때 — `MessageToast` 사용 |

### 8-1. 토스트 규칙

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 표시 시간 | 3초 후 스스로 닫힘 | 확정 |
| 누르면 | 즉시 닫힘 | 확정 |
| 위치 | 화면 아래 가운데, 아래에서 48 위 | 제안 (디자인 기준 없음) |
| 동시에 여러 개 | 쌓여서 각자 닫힘 | 확정 |
| 씬 전환 | 모든 팝업 · 토스트를 닫는다 | 확정 |

호출: `PopupManager.ShowToast("문구")`. 모달은 `OpenModal<T>()`, 닫기는 `popup.Close()` (API 전체는 `worklog.md` 2026-09-24 팝업 항목).

### 8-2. 요청 거절 문구 (2026-11-02 확정)

방장이 내 요청을 거절하면 거절 코드([`09-network.md`](09-network.md) 4.3)를 이 문구로 바꿔 `MessageToast` 로 띄운다. 요청 종류(드로우 · 카드 사용 등)와 무관하게 한 곳에서 받는다 — `RejectToastPresenter` · 문구 표 `RejectText`.

| 코드 | 이름 | 문구 |
| --- | --- | --- |
| 1 | `NotYourTurn` | 내 턴이 아닙니다. |
| 2 | `NotInHand` | 손패에 없는 카드입니다. |
| 3 | `NoCardToDraw` | 뽑을 카드가 없습니다. |
| 4 | `NotActionCard` | 행동 카드만 낼 수 있습니다. |
| 5 | `InvalidTarget` | 대상이 올바르지 않습니다. |
| 그 외 | — | 거절 (코드 n) |
