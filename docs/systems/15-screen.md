**최종 수정일**: 2026-11-11
**분류**: MVP

**상태**: **확정** (2026-09-25 승인). 모든 씬 캔버스가 이 문서를 따른다. 9절 화면 전환은 방식만 확정 (2026-11-11), 값은 제안.

## 1. 목적

폰 · 태블릿 · 폴더블 어느 비율에서도 UI 가 잘리거나 겹치지 않게, 한 가지 규칙으로 모든 씬을 만든다.

## 2. 근거 — 실제 기기 비율

Statcounter 2026-08, 모바일 웹 기준. 게임 사용자 분포와 같지는 않지만 비율 경향은 충분히 보여준다.

| 비율 | 대표 기기 | 한국 점유 | 세계 점유 |
| --- | --- | --- | --- |
| **19.5:9** (2.16~2.17) | iPhone 11~15, Galaxy S | 상위 6개 중 5개 (약 52%) | 상위 6개 중 4개 |
| **20:9** (2.22) | Galaxy A | 약 3% | 약 15% |
| 16:9 (1.78) | 구형 폰 | 상위권 없음 | 상위권 없음 |
| 16:10 · 4:3 | Galaxy Tab · iPad | — | — |
| 약 1.2 / 약 2.45 | 폴더블 펼침 / 커버 | — | — |

**16:9 폰은 사실상 없다.** 16:9 는 설계 기준으로만 쓴다.

### 3-1. 왜 Expand 인가

높이 기준(Match 1)은 폰에서는 Expand 와 결과가 **같다.** 차이는 화면이 16:9 보다 **좁을 때**(태블릿)만 난다.

| 기기 | 비율 | 높이 기준 | Expand |
| --- | --- | --- | --- |
| iPad 4:3 | 1.33 | 캔버스 폭 1440 → **1920 폭 레이아웃 좌우 240 잘림** (로비 버튼 양끝 60px 잘림 확인, `14-lobby-ui` 7-1) | 1920 × 1440 — 위아래가 넓어지고 잘림 없음 |
| Galaxy Tab 16:10 | 1.6 | 폭 1728 → 좌우 96 잘림 | 1920 × 1200 |
| 폰 19.5:9 · 20:9 | 2.16~2.22 | 2340~2400 × 1080 | 동일 |

Expand 로 바꾸면 **폰에서는 아무것도 달라지지 않고**, 태블릿 잘림만 사라진다.

> 3D 층(`10-ui` 2-1 「3D 층 구현」)은 카메라 수직 FOV 40° 고정 — 세로 1080 기준으로 맞추고 가로는 비율만큼 더 보인다. Expand 캔버스와 같은 결과 (2026-11-06).

## 5. 레이아웃 규칙

- **중앙 묶음**(타이틀 로고 · 입력, 인게임 테이블)은 1920×1080 안에 설계하고 화면 중앙 앵커.
- **가장자리 UI**(버전 · 시스템 버튼 · 좌석 · 손패 · 닉네임 · 로비 플레이 묶음 · 로비 왼쪽 아래 줄)는 해당 모서리 · 변 앵커. 화면이 늘어나면 같이 바깥으로 이동.
- 가로 폭을 고정 px 로 채우는 UI 는 만들지 않는다. 늘어나는 방향은 Stretch 앵커.
- 폰 실제 크기 환산: 가로 폰 화면 높이 ≈ 390pt → **캔버스 1 ≈ 0.36pt.** 터치 44pt = 캔버스 122, 글자 11pt = 캔버스 30 이상 (`12-title-ui` 4-3 과 같은 기준).

## 6. 배경 안전 영역

16:9 배경 한 장이 기기별로 잘리는 양:

| 기기 | 잘리는 곳 |
| --- | --- |
| 20:9 폰 | 위 · 아래 각 약 10% |
| 19.5:9 폰 | 위 · 아래 각 약 9% |
| 4:3 iPad | 좌 · 우 각 약 12.5% |

→ **중앙 가로 75% × 세로 80%** 안에 캐릭터 얼굴 · 주요 그림을 둔다. 배경 원본은 16:9 그대로.

## 7. Safe Area

- 가로 모드에서 노치 · 펀치홀은 **왼쪽 또는 오른쪽**, 홈 인디케이터는 **아래**.
- 가장자리 UI 컨테이너에 `Screen.safeArea` 로 영역을 줄이는 `SafeArea` 컴포넌트 1개 (공용). 배경 · 중앙 묶음은 적용하지 않는다.
- Android Player Settings → **Render outside safe area 켬** (배경이 노치 옆까지 차도록).

## 9. 화면 전환

화면(씬)이 바뀌는 순간의 연출. 기준 시안: 아티팩트 「화면 전환 시안」 https://claude.ai/artifact/CVBrhCyKWPbYZDrqFxGu4b — 기준: 게시본 `1794402421-3a71` 의 「다」.

**방식은 확정 (2026-11-11, PM)**, 시간 · 크기 값은 시안 값이라 **제안**. 크기는 캔버스 1920 × 1080 기준.

전환은 각 클라이언트가 자기 화면에서 재생하는 **표시 전용** 연출이다 — 판정 · 동기화가 없다. 화면이 언제 넘어가는지는 각 화면 문서가 정한다 (룸 → 인게임은 방장의 시작 전파, `08-room` 4절).

### 9-1. 어떤 전환에 무엇을

타이틀 → 로비 → 룸 → 인게임 순서가 「앞」, 그 반대가 「뒤」 다.

| 전환 | 방식 | 방향 | 구분 |
| --- | --- | --- | --- |
| 타이틀 → 로비 | 겹쳐 바뀜 0.3초 (`20-title-ui-full` 3절 #11) | — | 확정 (2026-11-07) |
| 로비 → 타이틀 | 겹쳐 바뀜 0.3초 — 로비 화면 전체가 사라지며 타이틀이 나타난다 | — | 확정 (방식) / 제안 (값) |
| 로비 → 룸 | 부품 갈아 끼우기 (9-2) | 앞 | 확정 (방식) |
| 룸 → 로비 | 부품 갈아 끼우기 (9-2) | 뒤 | 확정 (방식) |
| 룸 → 인게임 · 결과 화면을 보는 중 방장이 다음 판 시작 (`10-ui` 10절) | 게임 시작 (9-4) | 앞 | 확정 (방식) |
| 인게임 → 룸 (결과 화면 「방으로」) · 인게임 → 로비 (「나가기」 · 「게임 나가기」) | 카드 뒷면 덮개 (9-3) | 뒤 | 확정 (방식) |

결과 화면은 인게임 위에 덮는 판이라 화면 전환이 아니다 (`10-ui` 10절).

### 9-2. 부품 갈아 끼우기

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 무엇 | 배경은 움직이지 않는다. 앞 화면의 부품(배경을 뺀 전부)이 사라지고 다음 화면의 부품이 나타난다 | 확정 |
| 나감 | 0.14초 동안 투명해지며 가로로 32 이동 — 앞이면 왼쪽으로, 뒤면 오른쪽으로 | 제안 |
| 들어옴 | 나감이 끝난 직후 0.2초 동안. 나간 방향의 반대쪽 32 떨어진 곳에서 제자리로 오며 나타난다 | 제안 |
| 시작 시점 | 다음 화면을 그릴 준비가 된 뒤에 시작한다. 그 전까지 앞 화면은 그대로 있고, 기다림은 그 화면의 로딩 표시가 알린다 (로비 → 룸: `14-lobby-ui` 6절) | 제안 |
| 두 화면의 배경이 다를 때 | 배경은 같은 시간(0.34초) 동안 겹쳐 바뀐다 | 제안 |

### 9-3. 카드 뒷면 덮개

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 무엇 | 카드 뒷면으로 된 판이 화면 전체를 덮고, 그 뒤에서 다음 화면을 준비한 다음 걷힌다 | 확정 |
| 그림 | 카드 뒷면의 파랑 `#009DFE` + 낙서 무늬(똥 · 리본 · 왕관 · 뼈다귀). 무늬 · 얼굴은 카드 뒷면 원본 그림에서 따 온다 | 확정 (카드 뒷면) / 제안 (무늬 크기 — 한 무늬 약 160) |
| 꼴 | 화면보다 큰 평행사변형 (9° 기울임). 좌 · 우 가장자리에 잉크 `#2a2420` 선 8 | 제안 |
| 덮기 | 0.28초. 앞이면 오른쪽 밖에서, 뒤면 왼쪽 밖에서 들어온다 | 제안 |
| 화면 바꾸기 | 판이 화면을 다 덮은 뒤에 바꾼다. 걷히기 시작할 때 다음 화면은 이미 그려져 있다 | 확정 |
| 머묾 | 최소 0.2초, 다음 화면이 준비될 때까지 | 제안 |
| 머묾이 0.3초를 넘으면 | 판 가운데에 카드 뒷면의 얼굴(원, 지름 410)이 0.22초에 톡 나타나 좌우로 갸웃한다 (±6°, 한 번에 1.1초). 다음 화면이 준비되면 0.35초 더 보여 주고 사라진 뒤 걷는다 | 제안 |
| 걷기 | 0.28초. 들어온 방향으로 계속 나아가 반대쪽 밖으로 나간다 | 제안 |

### 9-4. 게임 시작

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 무엇 | 「게임 시작!」 띠와 집중선이 뜬 뒤 카드 뒷면 덮개(9-3, 앞)가 덮고, 걷히면 인게임이다 | 확정 |
| 언제 | 룸이 「시작 중」(`16-room-ui-full` 7-12)에 들어간 순간. 방의 모든 사람이 각자 재생한다 | 제안 |
| 띠 | 화면 가운데를 가로지르는 띠 — 턴 색 `#ffc12e`, 위 · 아래 잉크 선 8, 높이 162, −3° 기울임. 글자 「게임 시작!」 잉크색 · 크기 100. 0.2초 동안 세로로 펼쳐진다 (0 → 125% → 100%) | 제안 |
| 집중선 | 화면 가장자리에서 가운데를 향하는 잉크 쐐기 40개 (바깥쪽 굵기 0.6 ~ 2.2°, 안쪽 끝은 가운데에서 가장자리까지 거리의 62 ~ 92% 지점). 0.09초마다 다시 그려 떨린다 | 제안 |
| 순서 | ① 띠 · 집중선 0.2초 → ② 머묾 0.45초 → ③ 덮기 0.28초 — 띠는 덮개 위에 남고, 집중선은 덮기 시작 0.14초 뒤 사라진다 → ④ 머묾 (9-3) → ⑤ 띠가 0.14초에 접히며 걷기 0.28초 | 제안 |
| 걷힌 뒤 | 캐릭터 입장 연출이 시작된다 (`19-character-items` 5절) | 제안 |
| 룸의 「시작 중」 표시 | 띠가 떠 있는 동안에도 「시작 중」 의 글 · 입력 잠금은 그대로다 (`16-room-ui-full` 7-12) | 제안 |
