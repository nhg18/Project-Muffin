# 23. 로그인 · 계정

**최종 수정일**: 2026-11-07
**분류**: MVP (`development-plan` 기능 12 「로그인 · 친구」 — **출시 `1.0` 에 포함**, 2026-11-06 확정)
**출처**: 2026-11-07 PM 결정 (플랜 세션). 같은 날 뒤에 금칙어(8절) · 로그아웃 없음 · 식별자 · 닉네임 저장 시점 · Cloud Code · 연령 A 안 승인. 같은 날 PM: 동의를 약관마다 체크 + 「모두 동의하기」 로 (7-5). [`../store-release.md`](../store-release.md) 결정 3(계정 삭제 · Sign in with Apple) · 4절(방침 링크) · [`20-title-ui-full.md`](20-title-ui-full.md) · [`17-lobby-ui-full.md`](17-lobby-ui-full.md) 의 `가정` 을 이 문서가 확정으로 바꾼다.
**범위**: 계정의 **규칙**만. 화면(타이틀 · 로비 설정 「계정」)은 [`20-title-ui-full.md`](20-title-ui-full.md) · [`17-lobby-ui-full.md`](17-lobby-ui-full.md) 7-4, 친구 규칙은 [`13-friend.md`](13-friend.md), 장착 · 보유 데이터의 내용은 [`19-character-items.md`](19-character-items.md), 재화 · 퀘스트는 `24-currency-quest.md`(작성 중).

> 한 줄 요약: **로그인 화면이 없다.** 처음 켜면 약관에 동의하고 닉네임을 정하면 끝 — 계정은 뒤에서 자동으로 만들어진다. 기기를 바꿔도 이어 쓰고 싶은 사람만 로비 설정에서 Google · Apple 을 연동한다.

---

## 1. 목적

플레이어가 **가입 절차 없이** 게임을 시작하고, 원하면 계정을 기기 밖으로 옮길 수 있게 한다. 닉네임 · 장착 · 통계 · 친구가 **서버에** 남아 앱을 다시 설치하거나 기기를 바꿔도 이어진다(연동한 경우). 스토어가 요구하는 계정 삭제 · 약관 동의 · 최소 버전 · 점검을 여기서 정한다.

## 2. 판정 주체

**방장(마스터 클라이언트) 판정은 없다.** 계정은 게임 규칙이 아니다. 판정은 **UGS 서버**와 **클라이언트(해당 플레이어 기기)** 둘로 나뉜다.

| 대상 | 판정 | 클라이언트가 하는 일 | 구분 |
| --- | --- | --- | --- |
| 계정 생성 · 세션 유지 · 만료 | **UGS Authentication** | 앱 시작 때 요청, 결과 표시 | 확정 (2026-11-07) |
| Google · Apple 연동 성공 · 실패 | UGS Authentication + OS 계정 창 | 설정 「계정」 에서 요청, 결과 표시 | 확정 (2026-11-07) |
| 계정 삭제 | UGS (Authentication · Cloud Save · Friends) | 확인 뒤 요청, 끝나면 타이틀로 | 확정 (2026-11-07) |
| 닉네임 **길이 · 문자** | **클라이언트** ([`12-title-ui.md`](12-title-ui.md) 4-2 규칙) | 입력 즉시 검사, 에러 문구 (12 10-3) | 확정 (기존) |
| 닉네임 **중복** | 검사하지 않는다 — 허용 | — | 확정 (2026-11-07) |
| 닉네임 **금칙어** | 클라이언트가 **먼저**, 저장 시점에 **UGS Cloud Code 가 다시** (8절) | 즉시 안내, 서버 거절도 같은 문구 | 확정 (2026-11-07) |
| 최소 버전 · 점검 | **클라이언트**가 Remote Config 값과 자기 버전을 비교 | 접속 전에 읽고, 걸리면 팝업 · 접속 안 함 (7-6) | 확정 (2026-11-07) |
| 장착 · 보유 · 통계 · 재화 저장 | **UGS Cloud Save** (플레이어 자기 데이터) | 장착은 클라이언트가 자기 값을 쓴다. 통계 · 재화 · 퀘스트 진행은 Cloud Code 「판 결과 보고」 · 「보상 받기」 · 「상자 열기」 가 쓰고 클라이언트는 읽기만 (`07` 11-6 · `24` 2절) | 확정 (Cloud Save · Cloud Code 쓰기, 2026-11-07) |
| 친구 · 요청 · 차단 | **UGS Friends** | [`13-friend.md`](13-friend.md) | 확정 (2026-11-07) |
| 약관 동의 여부 | **클라이언트**(기기 저장) — 동의 시각은 계정에도 기록 | 동의 전엔 어디에도 접속하지 않는다 | 확정 (동의 1회) / 제안 (저장 위치) |

**비공개 정보**: 연동한 소셜 계정의 이메일 · 이름은 **화면에 보이지 않고 저장하지 않는다.** 보이는 것은 연동 상태(게스트 / Google / Apple)뿐. 친구 코드 · 통계 · 차단 목록은 본인에게만 (17 3절 #9).

## 6. 상태 · 흐름

### 6-1. 처음 실행

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| (앱 시작) | 기기에 동의 기록 없음 | **동의 대기** | 타이틀에 약관 동의 팝업 → 「동의하고 계속」 → 닉네임 입력 묶음 (20 7-11 · 7-6). 어디에도 접속하지 않는다 |
| 동의 대기 | 두 약관 동의 + 닉네임 통과 + 「시작」 | **계정 만드는 중** | 동의 기록(기기) → UGS 익명 로그인 요청. 로딩 묶음 "로그인 중…" |
| 계정 만드는 중 | 성공 | **설정 읽는 중** | Remote Config 읽기 (`minVersion` · `maintenance` · 금칙어 목록) |
| 계정 만드는 중 | 실패 · 15초 초과 | **로그인 실패** | 제목 + 설명 + 오류 코드 + 「다시 시도」 (20 7-5 · 8절). 다시 시도 → 계정 만드는 중 |
| 설정 읽는 중 | `minVersion` > 내 버전 | **업데이트 필요** | 닫을 수 없는 팝업 + 「스토어로」. 접속하지 않는다 |
| 설정 읽는 중 | `maintenance` = 참 | **점검** | 닫을 수 없는 팝업 + 안내 문구. 30초마다 다시 읽어 풀리면 이어서 진행 |
| 설정 읽는 중 | 통과 | **접속 중** | 네트워크 서버 접속 (12 6절 「연결 중」) |
| 접속 중 | 연결됨 | **닉네임 저장 중** | 닉네임 저장 요청 (서버 금칙어 재검사 포함) |
| 닉네임 저장 중 | 성공 | — | 로비로 이동 |
| 닉네임 저장 중 | 금칙어 거절 | 동의 대기 (닉네임 묶음) | 에러 문구 "사용할 수 없는 단어가 있어요." — 접속 · 계정은 그대로 |

> **닉네임 저장은 접속 뒤 — 확정 (2026-11-07).** 이유: 금칙어 목록을 Remote Config 로 받아야 로컬 검사가 가능하고, 네트워크 서버에 보낼 표시 이름도 저장이 끝난 값이어야 한다. 사용자가 보기에는 「시작」 한 번에 로딩 → 로비다. 저장 실패 때만 닉네임 묶음으로 되돌아온다.

### 6-3. 연동

| 현재 상태 | 조건 | 다음 상태 | 결과 |

| 게스트 | 「Google 연동」 · 「Apple 연동」 탭 | **연동 중** | OS 계정 창. 설정 팝업은 열린 채 버튼만 비활성 |
| 연동 중 | OS 창 취소 | 게스트 | 아무 변화 없음 |

### 8-2. 검사 — 정규화 뒤 부분 일치

입력을 아래 순서로 바꾼 뒤 금칙 목록의 단어가 **부분 문자열로 들어 있으면** 거절한다. 통과 목록의 단어가 들어 있으면 그 부분은 검사에서 뺀다.

| 순서 | 처리 | 예 |
| --- | --- | --- |
| 1 | 공백 · 특수문자 · 이모지 제거 | 「시 발」 → 「시발」 |
| 2 | 영문 소문자로 | 「FUCK」 → 「fuck」 |
| 3 | 숫자 · 영문 유사문자 치환: `1` → `ㅣ` 또는 `l`, `0` → `o`, `5` → `s`, `8` → `b`, `3` → `e`, `4` → `a`, `7` → `t`, `@` → `a`, `$` → `s` (두 갈래가 있는 것은 **둘 다** 만들어 검사) | 「sh1t」 → 「shit」 · 「ㅅ1발」 → 「시발」 |
| 4 | 한글 **자모 분리 결합**: 연속된 자모를 완성형으로 합친다 | 「ㅅㅣㅂㅏㄹ」 → 「시발」 |
| 5 | 정규화한 문자열에서 통과 목록 단어를 지운다 | 「시발점」 → 「」 (통과) |
| 6 | 남은 문자열에 금칙 목록 단어가 부분 일치하면 거절 | 「개시발놈」 → 걸림 |
| 7 | 원문(1 ~ 4 적용 전)이 **초성만**으로 되어 있으면 초성 목록과 정확 일치 검사 | 「ㅅㅂ」 → 걸림, 「ㅅㅂㄴ」 → 목록에 있으면 걸림 |

- 12 4-2 가 허용 문자를 한글 완성형 · 영문 · 숫자로 막으므로, 실제 입력에서 1 · 4 · 7 은 조합 중이거나 붙여넣기한 경우에만 의미가 있다. 그래도 **서버는 같은 순서를 전부** 돈다 (클라이언트 우회 대비).
- 검사는 **같은 규칙 · 같은 목록**을 클라이언트와 서버가 쓴다. 규칙이 바뀌면 둘을 같이 고친다.

| 입력 중 · 「시작」 「변경」 탭 | **클라이언트** (Remote Config 로 받은 목록) | 걸리면 즉시 에러 문구, 서버에 보내지 않는다 |
| 저장 요청 | **UGS Cloud Code** — 저장 직전에 같은 검사 | 걸리면 거절, 저장하지 않는다. 클라이언트는 같은 에러 문구 |
| 닉네임 저장 경로 | 클라이언트는 Cloud Save 에 닉네임을 **직접 쓰지 않는다** — Cloud Code 만 쓴다 | 서버 검사를 건너뛸 수 없다 |

### 8-4. 문구 · 사후 처리

| 항목 | 내용 |
