## 0. 레퍼런스 (2026-11-03 조사)

가로 화면 모바일 게임의 로비가 어떻게 생겼는지 보고 구조를 정했다. 세로 게임의 패턴(하단 탭 + 좌우 넘김)은 **가로에서는 쓰지 않는다**는 결론.

| --- | --- | --- | --- |

## 1. 목적

로그인 · 친구가 생긴 뒤의 로비. 플레이어가 **자기 정보를 확인하고(프로필), 친구를 맺고 초대를 받고(친구), 캐릭터와 이펙트를 꾸미고(보관함), 사고(상점), 소리 · 계정을 관리한다(설정).** 방을 만들고 참가하는 버튼의 **동작**은 14-lobby-ui 5절 그대로이고, **자리와 크기**는 이 문서가 다시 정한다.

로비는 **홈 허브 1장 + 전체 화면 섹션 2장(보관함 · 상점)** 이다. 섹션은 왼쪽 열 버튼으로 열고, 씬은 하나(로딩 없음). 짧은 일(설정 · 프로필 · 친구)은 어디서든 **팝업**, 방 · 게임은 지금처럼 **씬 이동**. 좌우 넘김(스와이프) 페이지는 두지 않는다 (0절).

모바일 로비에 흔히 있는 것 중 **이 게임에 지금 필요한 것만** 고른다. 뺀 것과 이유는 11절.

## 2. 판정 주체

| 대상 | 판정 · 저장 | 로비 화면이 하는 일 |
| --- | --- | --- |
| 친구 목록 · 요청 · 차단 · 친구 코드 · 전적 · 닉네임 | **친구 서버(백엔드)** 가 저장하고 판정한다 | 요청만 보내고 결과를 **표시**한다 |
| 보유 · 장착 아이템 | 서버 (19-character-items 2절) | 보관함에서 요청 · 표시 |
| 온라인 · 게임 중 · 어느 방인지 | 네트워크 서버(접속 여부 · 방 이름) + 친구 서버(상태) | 표시 |
| 초대 보내기 · 받기 · 30초 만료 | 친구 서버 (13-friend 4절) | 배너 표시 · 수락 · 거절 |
| 초대 수락 뒤 방 참가 | 네트워크 서버 — 08-room 4절 「방 참가」 와 같은 경로 | 로딩 팝업 → 결과 표시 |
| 소리 · 알림 켜기/끄기 | **로컬**(기기 저장) | 즉시 적용 |

**방장(마스터 클라이언트) 판정은 없다.** 로비에는 방이 없다. 09-network 의 방장 원칙은 방 · 게임에만 적용된다.

## 3. 핵심 규칙

| # | 규칙 | 구분 |
| --- | --- | --- |
| 1 | **동작하는 기능만 둔다** (14-lobby-ui 3절 #1). 로그인 · 친구 서버가 붙기 전에는 이 문서의 버튼 · 칩 · 배너를 화면에 두지 않는다. 상점 버튼은 수익화 결정 전까지 두지 않는다 | 확정 (기존 규칙) |
| 2 | 버튼 3개(랜덤 매칭 · 방 만들기 · 코드로 참가)는 **우하단 플레이 묶음**. 주 버튼(랜덤 매칭)이 가장 크고 맨 아래, 보조 2개는 그 위 한 줄. 동작은 14-lobby-ui 5절 그대로 | 제안 — 0절 「엄지 영역」, Brawl Stars · Stumble Guys 의 Play 자리 |
| 2-1 | 홈 **왼쪽에 플레이어 캐릭터**가 선다. 로비에서 내 캐릭터가 보이는 자리이며, 가운데는 비워 배경이 보인다 | 확정 (2026-11-03, 사용자) — 캐릭터 종류는 [`19-character-items.md`](19-character-items.md), 지금은 **기본 캐릭터 1종** |
| 2-2 | 섹션으로 가는 버튼은 **왼쪽 열**(세로)에 둔다 — 「보관함」 「상점」. 섹션은 로비 씬 안의 **전체 화면**이며, 왼쪽 열 맨 위의 「← 홈」 으로 돌아온다 | 확정 (2026-11-03, 보관함 · 상점 필요 — 사용자) / 제안 (왼쪽 열 · 전체 화면 — 0절 Brawl Stars) |
| 2-3 | 섹션 안에서도 왼쪽 열은 남는다: 「← 홈」 + **다른 섹션 버튼** (보관함에서는 상점, 상점에서는 보관함). 홈을 거치지 않고 오간다 | 제안 |
| 2-4 | 어디서나 **항상 보이는 것**: 프로필 칩 · 친구 · 설정 버튼 · 초대 배너 · 왼쪽 열. 홈에만 있는 것: 캐릭터(섹션에서는 미리보기로 같은 자리) · 플레이 묶음 · 버전 표기 | 제안 |
| 2-5 | 배경은 **화면마다 따로** — 홈 · 보관함 · 상점 각 1장. 섹션이 들어올 때 배경도 섹션과 함께 들어온다 | 확정 (2026-11-03, 사용자 「개별」) / 제안 (움직임) |
| 3 | 가장자리 UI 는 15-screen 5절 — 해당 모서리 앵커 + Safe Area. 중앙 1920 × 1080 밖으로 나가도 된다 | 확정 (기존 규칙) |
| 4 | 팝업은 **한 번에 하나.** 팝업이 열려 있으면 화면 안 버튼 · 가장자리 버튼 · 왼쪽 열을 전부 무시한다. 팝업 위에 겹칠 수 있는 것은 **초대 배너 · 토스트 · 로딩 팝업(공용) · 경고 팝업(공용)** 뿐이다 | 제안 |
| 5 | Android 뒤로가기 = ① 열린 팝업 닫기 → ② 섹션이면 홈으로 → ③ 홈이면 아무것도 하지 않는다 (타이틀로 돌아가지 않는다) | 제안 |
| 6 | 친구 · 프로필 · 보유 데이터는 **로비 진입 때 한 번** 불러오고, 그 뒤 변화(요청 도착 · 상태 변화 · 초대)는 **서버 알림으로 즉시** 받는다. 주기적으로 다시 묻지 않는다 | 제안 |
| 7 | 불러오기에 실패해도 버튼은 보인다. 탭하면 실패 팝업 + 다시 시도 (6절). 기능을 숨겨서 "없는 것처럼" 보이게 하지 않는다 | 제안 |
| 8 | 터치 영역 44pt(캔버스 122) · 글자 11pt(캔버스 30) 이상 (15-screen 5절) | 확정 (기존 규칙) |
| 9 | **비공개 정보**: 친구 코드 · 전적 · 차단 목록 · 받은 / 보낸 요청 · 보유 목록은 **본인에게만** 보인다. 닉네임 · 온라인 상태 · 장착한 캐릭터는 친구에게 보인다 | 제안 |
| 10 | 팝업 · 배너의 열림 · 닫힘 연출은 없다 — 즉시 교체 (12-title-ui 6절과 같은 원칙). 섹션 전환만 0.25초 미끄러짐 (7-1) | 제안 |
| 11 | 주 행동 색은 **하나**(`#B18AE0` 채움). 화면에서 그 색으로 채운 버튼은 랜덤 매칭 · 장착 · 구매처럼 "그 화면의 주 행동" 뿐이다 | 제안 — 0절 Clash Royale 의 노란 버튼 원칙 |
