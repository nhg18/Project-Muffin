# 17. 로비 화면 UI — 확장 (로그인 · 친구 이후)

**최종 수정일**: 2026-11-03
**분류**: Optional (`development-plan` 기능 12 「로그인 · 친구」 이후에 켠다. 그 전에는 이 문서의 요소를 화면에 두지 않는다)
**출처**: 2026-11-03 플랜 세션 초안. 노션 「📋 개발 기획서」 11절(친구 — [`13-friend.md`](13-friend.md) 로 이관됨) · 12절(설정 / 프로필 **제안**) · 「➡️ Game Flow」 2-2 점선 노드 · [`store-release.md`](../store-release.md) 결정 3 · 4절
**전제**: 로그인 문서(미작성)와 백엔드 선택이 먼저다. 이 문서는 **백엔드 = Unity Gaming Services Authentication + Friends** 를 `가정` 하고 쓴다. 전제가 바뀌면 2절 · 5절 · 12절을 고친다.

> MVP 로비([`14-lobby-ui.md`](14-lobby-ui.md))의 중앙 버튼 줄 · 배경 · 캔버스는 **그대로 둔다.** 이 문서는 그 위에 **가장자리 UI 와 팝업만 더한다.** 친구 **규칙**(요청 · 차단 · 초대 조건)은 [`13-friend.md`](13-friend.md), 방 **규칙**은 [`08-room.md`](08-room.md) 가 기준이고, 이 문서는 로비 **화면**만 다룬다.

---

## 1. 목적

로그인 · 친구가 생긴 뒤의 로비. 플레이어가 **자기 정보를 확인하고(프로필), 친구를 맺고 초대를 받고(친구), 소리 · 계정을 관리한다(설정).** 방을 만들고 참가하는 일은 14-lobby-ui 그대로다.

모바일 로비에 흔히 있는 것 중 **이 게임에 지금 필요한 것만** 고른다. 뺀 것과 이유는 11절.

## 2. 판정 주체

| 대상 | 판정 · 저장 | 로비 화면이 하는 일 |
| --- | --- | --- |
| 친구 목록 · 요청 · 차단 · 친구 코드 · 전적 · 닉네임 | **친구 서버(백엔드)** 가 저장하고 판정한다 | 요청만 보내고 결과를 **표시**한다 |
| 온라인 · 게임 중 · 어느 방인지 | 네트워크 서버(접속 여부 · 방 이름) + 친구 서버(상태) | 표시 |
| 초대 보내기 · 받기 · 30초 만료 | 친구 서버 (13-friend 4절) | 배너 표시 · 수락 · 거절 |
| 초대 수락 뒤 방 참가 | 네트워크 서버 — 08-room 4절 「방 참가」 와 같은 경로 | 로딩 팝업 → 결과 표시 |
| 소리 · 알림 켜기/끄기 | **로컬**(기기 저장) | 즉시 적용 |

**방장(마스터 클라이언트) 판정은 없다.** 로비에는 방이 없다. 09-network 의 방장 원칙은 방 · 게임에만 적용된다.

## 3. 핵심 규칙

| # | 규칙 | 구분 |
| --- | --- | --- |
| 1 | **동작하는 기능만 둔다** (14-lobby-ui 3절 #1). 로그인 · 친구 서버가 붙기 전에는 이 문서의 버튼 · 칩 · 배너를 화면에 두지 않는다 | 확정 (기존 규칙) |
| 2 | 중앙 버튼 줄(랜덤 매칭 · 방 만들기 · 방 참가)은 14-lobby-ui 7-1 그대로. 위치 · 크기를 바꾸지 않는다 | 제안 |
| 3 | 가장자리 UI 는 15-screen 5절 — 해당 모서리 앵커 + Safe Area. 중앙 1920 × 1080 밖으로 나가도 된다 | 확정 (기존 규칙) |
| 4 | 팝업은 **한 번에 하나.** 팝업이 열려 있으면 중앙 버튼 · 가장자리 버튼 탭은 무시한다. 팝업 위에 겹칠 수 있는 것은 **초대 배너 · 토스트 · 로딩 팝업(공용) · 경고 팝업(공용)** 뿐이다 | 제안 |
| 5 | Android 뒤로가기 = 열린 팝업 닫기. 팝업이 없으면 아무것도 하지 않는다 (로비에서 타이틀로 돌아가지 않는다) | 제안 |
| 6 | 친구 · 프로필 데이터는 **로비 진입 때 한 번** 불러오고, 그 뒤 변화(요청 도착 · 상태 변화 · 초대)는 **서버 알림으로 즉시** 받는다. 주기적으로 다시 묻지 않는다 | 제안 |
| 7 | 불러오기에 실패해도 버튼은 보인다. 탭하면 실패 팝업 + 다시 시도 (6절). 기능을 숨겨서 "없는 것처럼" 보이게 하지 않는다 | 제안 |
| 8 | 터치 영역 44pt(캔버스 122) · 글자 11pt(캔버스 30) 이상 (15-screen 5절) | 확정 (기존 규칙) |
| 9 | **비공개 정보**: 친구 코드 · 전적 · 차단 목록 · 받은 / 보낸 요청은 **본인에게만** 보인다. 닉네임 · 온라인 상태 · 기본 캐릭터는 친구에게 보인다 | 제안 |
| 10 | 팝업 · 배너의 열림 · 닫힘 연출은 없다 — 즉시 교체 (12-title-ui 6절과 같은 원칙). 연출은 디자인 확인 뒤 | 제안 |

### 5-1. 가장자리

| 입력 | 동작 | 조건 |

### 5-2. 프로필 팝업

| 입력 | 동작 | 조건 |
| --- | --- | --- |

### 5-3. 친구 팝업

| 입력 | 동작 | 조건 |
| --- | --- | --- |
| 탭 「친구」 「요청」 「추가」 | 목록 교체 | 항상 |
| 친구 행 「⋯」 | 행 아래에 작은 메뉴: 「친구 삭제」 「차단」 | 친구 탭 |
| 「친구 삭제」 | 경고 팝업(공용) "{닉네임} 님을 친구에서 삭제할까요?" → 확인: 서버 요청 → 행 제거 | |
| 「차단」 | 경고 팝업(공용) "{닉네임} 님을 차단할까요? 요청 · 초대가 막히고 목록에서 사라집니다." → 확인: 서버 요청 → 행 제거 (13-friend 3절) | |
| 받은 요청 「수락」 | 서버 요청 → 친구 탭으로 이동 · 배지 -1 | 요청 탭 |
| 받은 요청 「거절」 | 서버 요청 → 행 제거 · 배지 -1 | 요청 탭 |
| 보낸 요청 「취소」 | 서버 요청 → 행 제거 | 요청 탭 |
| 검색창 제출 | 닉네임 **또는** 친구 코드로 서버 검색 → 결과 목록 (본인 · 차단 유저 제외, 13-friend 2절) | 추가 탭 · 입력 1자 이상 |
| 결과 행 「요청」 | 서버 요청 → 버튼이 "요청됨"(비활성) 으로 · 보낸 요청에 추가. 상대도 나에게 보낸 상태면 서버가 바로 친구로 만든다 (13-friend 2절 동시 요청) | 이미 친구 · 이미 요청한 상대는 버튼 대신 "친구" / "요청됨" 글자 |
| 닫기 | 팝업 닫기 | 항상 |

> 친구 행에서 **방으로 초대**하는 입력은 로비에 없다. 초대는 방 안에서 보낸다 ([`16-room-ui.md`](16-room-ui.md) 미정 #2 와 함께 정한다). 친구가 있는 방에 **따라 들어가기**는 12절 #4.
