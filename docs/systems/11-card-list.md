# 11. 카드 목록

**최종 수정일**: 2026-09-17
**분류**: Core
**출처**: 노션 「🃏 카드 DB」 (개발용 데이터 소스)
**총 59장** — 행동 27 / 카운터 15 / 함정 17

---

## 0. 읽는 법

* `N`, `M` 은 **아직 정해지지 않은 수치**다. 전부 **미정**이며 밸런싱 단계에서 확정한다.
* `구현` 열은 Unity 에셋(`Assets/Cards/*.asset`) 존재 여부다. **현재 전부 미구현이다.**
* 카드 처리 규칙(반응 시간, 체인, 무효화)은 [`04-card.md`](04-card.md)를 따른다.
* 카드 ID 규칙: `A**` 행동 / `C**` 카운터 / `T**` 함정.

> **이 목록의 모든 카드는 마스터가 효과를 실행한다.** 클라이언트는 사용 요청만 보낸다.

## 1. 행동 카드 (Action, 27장)

사용 조건은 전부 **본인 턴 + 메인 행동 미사용**이다.

| A11 | 본인 + 다른 플레이어 선택 | 본인과 대상 플레이어의 손패 전체 교환 |

| A24 | 플레이어 선택 | 본인이 선택한 카드 1장을 대상에게 주고 대상 패에서 무작위 N장 획득 (선택할 카드가 없으면 카드만 소비되고 효과 불발) |

| A27 | 본인 | 덱에서 N장 드로우 후 손패의 함정 카드 1장을 즉시 빈 함정 슬롯에 설치 가능 |

## 2. 카운터 카드 (Counter, 15장)

전부 **반응 5초 이내 + 손패에 존재**가 공통 조건이다.

| ID | 사용 조건 | 대상 | 효과 |
| --- | --- | --- | --- |
| C01 | 행동카드 효과 발동 시 | 행동카드 시전 플레이어 | 해당 행동카드를 시전자 패로 반환 |
| C02 | 다른 플레이어가 행동카드 효과 발동 시 | 다른 플레이어 선택 | 행동카드 대상을 선택한 플레이어로 변경 |
| C03 | 자신에게 데미지를 주는 행동카드 발동 시 | 본인 | 데미지 수치만큼 본인 HP 회복 (데미지 미적용) |
| C04 | 다른 플레이어가 행동카드 효과 발동 시 | 시전 플레이어 | 해당 행동카드 효과를 시전 플레이어에게 적용 |
| C05 | 행동카드 효과 발동 시 | 본인 | 해당 행동카드 효과를 본인에게만 무효화 |
| C06 | 함정카드 효과 발동 시 | **현재 함정카드** | 해당 함정카드 효과 무효화 |
| C07 | 다른 플레이어가 카운터카드 사용 시 | **현재 카운터카드** | 해당 카운터카드 효과 무효화 |
| C08 | 본인 손패를 훔치거나 버리게 하는 효과 발동 시 | 본인 | 손패 변경 효과 무효화 후 덱에서 N장 드로우 |
| C09 | 다른 플레이어에게 HP 회복 효과 발동 시 | HP 회복 대상 | 해당 회복을 동일 수치의 HP 감소로 변경 |
| C10 | 본인이 피해를 받을 때 | 본인 | 본인이 받을 피해 N 감소 |
| C11 | 현재 카드의 피해로 본인이 사망할 때 | 본인 | 피해는 적용하되 사망하지 않고 HP N으로 생존 |
| C12 | 다른 플레이어의 효과로 본인 설치 함정이 파괴될 때 | **파괴될 본인 함정** | 파괴 대신 본인 손패로 반환 |
| C13 | 본인의 다음 턴 스킵 효과가 적용될 때 | 본인 | 해당 턴 스킵 효과 무효화 |

| C15 | 다른 플레이어가 본인에게 찹츄 상태를 부여할 때 | **현재 찹츄 부여 효과** | 본인에게 적용되는 찹츄 부여 무효화 |

## 3. 함정 카드 (Trap, 17장)

전부 **설치되어 있어야 하고, 조건 충족 시 소유자가 수동 발동**한다.

| ID | 발동 조건 | 대상 | 효과 |
| --- | --- | --- | --- |
| T01 | 본인 사망 시 | 생존한 모든 플레이어 | 전원 HP - N |
| T02 | 본인 HP 20 이하 | 본인 | 본인 HP + N |
| T03 | 다른 플레이어가 카운터카드 사용 시 | 카운터 사용 플레이어 | 해당 플레이어 HP - N |
| T04 | 찹츄 상태 플레이어 존재 시 | 찹츄 상태 플레이어 전원 (본인 제외) | 패에서 카드 3장 강제 버림 |
| T05 | 상대가 본인을 대상으로 행동카드 사용 시 | 행동카드 시전 플레이어 | 해당 행동카드 효과 취소 + 시전자 다음 턴 스킵 |
| T06 | 다른 플레이어에게 피해를 받은 후 | 피해를 준 플레이어 | 원래 피해 처리 후 해당 플레이어 HP - N |
| T07 | 다른 플레이어에게 피해를 받은 후 | 피해를 준 플레이어 | 원래 피해 처리 후 해당 플레이어 패에서 무작위 N장 강제 버림 |
| T08 | 다른 플레이어가 본인의 카드를 훔친 후 | 카드를 훔친 플레이어 | 원래 강탈 처리 후 해당 플레이어 패에서 무작위 N장 획득 |
| T09 | 다른 플레이어의 효과로 본인 패를 버린 후 | 본인 | 원래 버림 처리 후 버린 장수만큼 덱에서 드로우 |
| T10 | 다른 플레이어가 본인의 설치 함정을 파괴한 후 | 함정을 파괴한 플레이어 | 원래 파괴 처리 후 해당 플레이어 HP - N |
| T11 | 다른 플레이어가 본인의 설치 함정을 공개한 후 | 함정을 공개한 플레이어 | 공개 상태 유지 후 해당 플레이어 패에서 무작위 N장 강제 버림 |
| T12 | 본인이 발동한 다른 함정이 카운터로 무효화된 후 | 해당 카운터 사용 플레이어 | 무효화 결과 유지 후 해당 플레이어 패에서 무작위 N장 강제 버림 |
| T13 | 행동카드가 시전자 손패로 반환된 후 | 반환된 행동카드의 시전자 | 원래 반환 처리 후 해당 플레이어 HP - N |
| T14 | 다른 플레이어가 한 번에 N장 이상 드로우한 후 | 해당 플레이어 | 원래 드로우 처리 후 해당 플레이어 패에서 무작위 M장 강제 버림 |
| T15 | 본인의 턴이 스킵된 후 | 본인 | 턴 스킵은 유지하고 본인의 다음 실제 턴 시작 시 덱에서 N장 추가 드로우 |
| T16 | 다른 플레이어가 본인에게 찹츄 상태를 부여한 후 | 찹츄를 부여한 플레이어 | 본인의 찹츄 상태는 유지하고 해당 플레이어에게도 찹츄 상태 부여 |
| T17 | 본인이 사망 대기 상태일 때 | 본인 | 본인 손패와 다른 설치 함정을 모두 버리고 HP N으로 생존 |

## 5. 카드 효과의 분류 (구현 설계용)

효과를 개별 구현하지 않고 **파라미터화된 효과 타입**으로 묶는다. (제안)

| 효과 타입 | 파라미터 | 해당 카드 예 |
| --- | --- | --- |
| `Damage` | amount | A09, A14, A22, T01 |
| `Heal` | amount | A08, A13, T02 |
| `Drain` | amount | A19 |
| `Draw` | count | A06, A12, A13, A27, C08, T09, T15 |
| `Discard` | count, random 여부 | A05, A21, A23, T04, T07 |
| `Steal` | count | A04, A24, T08 |
| `SwapHand` | — | A11, A18 |
| `PassHand` | count, 방향 | A10 |
| `DestroyTrap` | count | A03 |
| `ReturnTrap` | count | A16, C12 |
| `StealTrap` | count | A17 |
| `SkipTurn` | count | A01, T05 |
| `ReverseDirection` | — | A07 |
| `SetChapChu` / `ClearChapChu` | — | A20, A21, T16 |
| `Negate` | 범위(전체/본인만) | C05, C06, C07, C15 |
| `Redirect` | 새 대상 | C02, C04 |
| `ReturnToHand` | — | C01 |
| `ConvertDamageToHeal` | — | C03 |
| `ConvertHealToDamage` | — | C09 |
| `ReduceDamage` | amount | C10 |
| `SurviveAt` | hp | C11, T17 |
| `Peek` | count, pick | A25 |
| `Reveal` | count | C14 |
| `Choice` | 선택지 목록 | A15 |

`CardEffect` ScriptableObject를 위 타입별로 만들고, 카드는 효과를 **조합**한다.
카드 59장에 대해 스크립트 59개를 만들지 않는다.

## 6. 미정 / 결정 필요

1. **모든 N / M 수치** — 카드 구현의 전제
2. 카드 이름 (현재 개발 DB에 이름 없음. 노션 별도 DB에 「물어뜯기」, 「짖기」, 「핥아주기」, 「낚아채기」 등 존재)
3. 카드별 덱 매수
4. 우선 구현 대상 카드 셋 (MVP에 몇 장을 넣을 것인가)
5. 카드 이미지 / 디자인 완료 여부

### 제안 — MVP 카드 셋

구조 검증에 필요한 최소 조합만 먼저 구현한다. (제안)

| 목적 | 카드 |
| --- | --- |
| 기본 피해 | A09 |
| 기본 회복 | A08 |
| 드로우 | A06 |
| 손패 조작 | A05 |
| 무효화 (카운터 체인 검증) | C05 |
| 피해 반응 (함정 검증) | T06 |

6장이면 **행동 / 카운터 / 함정 / 체인 / 손패 조작 / HP** 전부를 검증할 수 있다.
