# 12. 타이틀 화면 UI

**최종 수정일**: 2026-09-24
**분류**: MVP
**출처**: Claude Design 「찹츄 타이틀 화면」을 게시한 아티팩트 `https://claude.ai/artifact/7hXwuwxuZfL7ZXW7VSyoRv` — **기준: 2026-09-24 게시본(`1790251827-b3ed`)에 폰트(학교안심 둥근미소 B/R, 기존 TitleScene 굵기 배분)·배경(게임과 같은 일러스트)만 교체한 판 (Version 8)**
**이전 출처**: 노션 「🎬 타이틀 화면 개발 문서(UI 구현 스펙)」 — 이 문서 기준으로 갱신됨

> 아티팩트가 수정되더라도 **이 문서를 고치기 전까지는 이 문서가 기준이다.** 아티팩트를 갱신했다면 버전 ID와 바뀐 수치를 이 문서에 먼저 반영한다.

---

## 1. 목적

게임의 첫 화면. 플레이어가 닉네임을 입력하고 접속을 요청한다.

## 2. 판정 주체

**타이틀 화면의 모든 판정은 로컬(해당 클라이언트)이다.** 마스터 판정 없음.
닉네임 검증은 입력한 클라이언트가 직접 하고, 서버는 닉네임을 다시 검사하지 않는다.

## 3. 핵심 규칙

| # | 규칙 | 구분 |
| --- | --- | --- |
| 1 | 닉네임 검증을 통과해야만 접속을 요청할 수 있다 | 확정 |
| 2 | 검증 실패 사유는 입력창 아래 에러 문구로만 표시한다 (팝업 사용 안 함) | 확정 |
| 3 | 에러 문구는 닉네임 입력이 바뀌면 즉시 사라진다 | 확정 |
| 4 | 에러 문구가 없을 때도 그 자리(높이)는 유지한다 — 버튼 위치가 움직이지 않는다 | 확정 |
| 5 | 접속 이후 흐름(서버 연결, 로비 이동, 닉네임 저장)은 이 문서가 정하지 않는다 → [`01-game-flow.md`](01-game-flow.md) | 확정 |

## 4. 주요 수치

### 4-1. 캔버스

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 기준 해상도 | 1920 × 1080 | 확정 |
| 스케일 방식 | 화면 크기에 맞춰 스케일, **높이 기준**(Match 1) | 확정 |
| 화면 방향 고정 (가로/세로) | — | **미정** |

> 아티팩트는 `vh`/`vw` 반응형이다. 아래 모든 px 값은 **1080 높이에서 환산한 값**이다.

### 4-2. 닉네임

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 최소 길이 | 2자 | 확정 |
| 최대 길이 | 16자 (입력 자체가 16자에서 막힌다) | 확정 |
| 허용 문자 | 한글 완성형 · 영문 · 숫자 | 확정 |
| 공백 | 불가 (앞뒤 공백은 검사 전에 제거) | 확정 |
| 특수문자 | 전부 차단 | 확정 |
| 중복 닉네임 허용 | — | **미정** (로그인 시스템 보류) |

### 4-3. 모바일 확대 배율

아티팩트는 1920×1080 모니터 기준이라 폰에서는 글자 · 버튼이 너무 작다
(가로 폰 화면 높이 ≈ 390pt → 캔버스 1 ≈ 0.36pt. 입력 글자 22 ≈ 7.9pt, 버튼 높이 84 ≈ 30pt).
**중앙 묶음만 통째로 확대한다.** 7 · 8 · 9절의 수치는 모두 **확대 전(아티팩트 그대로)** 값이고, 화면에는 아래 배율이 곱해져 보인다.

| 대상 | 배율 | 폰 실제 크기 (390pt 높이 기준) | 구분 |
| --- | --- | --- | --- |
| 로고 · 부제 묶음 | **× 1.3** | 로고 화면 높이의 22%, 부제 ≈ 17pt | 확정 (2026-09-24) |
| 입력 묶음 (입력창 · 접속 버튼 · 에러 문구) | **× 1.7** | 입력 글자 ≈ 13.5pt, 버튼 높이 ≈ 52pt, 입력창 높이 ≈ 45pt, 에러 ≈ 11pt | 확정 (2026-09-24) |
| 로고 묶음 ↔ 입력 묶음 간격 | 56 (확대 후 값) | | 확정 (2026-09-24) |
| 버전 표기 · 시스템 버튼 (가장자리) | 배율 없음 | | 현행 유지 · 별도 검토 |

- 기준: 터치 영역 44pt 이상, 글자 11pt 이상 (Apple HIG).
- 아티팩트와 **의도적으로 다르다.** 아티팩트 대조(S6)는 배율을 빼고 비교한다.

## 5. 입력

| 입력 | 동작 | 조건 |
| --- | --- | --- |
| 닉네임 입력창 탭 | 입력 시작 (모바일 키보드 표시) | 항상 |
| 글자 입력 | 카운터 `n / 16` 갱신, 에러 문구 지움 | 16자 미만 |
| 접속 버튼 탭 | 닉네임 검증 → 실패: 에러 표시 / 통과: 에러 지우고 버튼 글자를 "접속 중…"으로 바꾼 뒤 접속 요청 | 접속 중이 아닐 때 |
| 접속 버튼 탭 | **무시** (중복 요청 차단) | 접속 중 |
| 사운드 버튼(♪) 탭 | **미정** | — |
| 메뉴 버튼(≡) 탭 | **미정** | — |

## 6. 화면 상태

| 현재 | 조건 | 다음 | 화면 변화 |
| --- | --- | --- | --- |
| 입력 대기 | 접속 탭 + 검증 실패 | 에러 표시 | 에러 문구 표시 |
| 에러 표시 | 닉네임 입력 변경 | 입력 대기 | 에러 문구 지움 |
| 입력 대기 | 접속 탭 + 검증 통과 | 접속 중 | 에러 문구 지움, 버튼 글자 "접속 중…" |
| 접속 중 | 접속 실패 (사유 전달) | 에러 표시 | 버튼 글자 "접속"으로 복귀, 10-5 문구 표시 |
| 에러 표시 (접속 실패) | 접속 탭 + 검증 통과 | 접속 중 | **재시도** — 서버 접속을 다시 시작한다 |
| 접속 중 | 접속 성공 | — | 로비(`LobbyScene`)로 이동 |

> 접속 중에도 버튼은 **비활성화하지 않는다**(디자인 그대로). 대신 접속 중의 탭은 무시한다. 로딩 표시는 버튼 글자 "접속 중…"으로 충분하다 (확정 2026-09-24).
>
> 서버 접속은 앱 시작 때 이미 시작된다(`01-game-flow.md`). 접속 버튼은 **그 접속이 끝나기를 기다렸다가** 로비로 넘어간다. 앱 시작 직후 접속이 실패했으면, 버튼을 누를 때 다시 시도한다. 누르기 전에 난 실패는 화면에 띄우지 않는다.

### 10-3. 에러 문구 (검증 실패 사유)

| 사유 | 문구 |
| --- | --- |
| 비었거나 공백만 | 닉네임을 입력해 주세요. |
| 2자 미만 | 2자 이상 입력해 주세요. |
| 16자 초과 | 16자 이하로 입력해 주세요. |
| 허용되지 않은 문자 | 사용할 수 없는 문자가 포함되어 있습니다. |

- 표시: 즉시(페이드 없음). 해제: 입력 변경 즉시.

### 10-5. 에러 문구 (접속 실패 사유)

`ConnectionEvents.OnDisconnected` 의 사유(`DisconnectCause`)별 문구. 같은 에러 문구 자리에 표시한다. 자동 재시도는 없다(`09-network.md`).

| 사유 | 문구 |
| --- | --- |
| `ExceptionOnConnect` · `DnsExceptionOnConnect` · `ServerAddressInvalid` (인터넷 없음 포함) | 서버에 연결할 수 없습니다. 인터넷을 확인해 주세요. |
| `ClientTimeout` · `ServerTimeout` (접속 제한 15초 초과 포함) | 연결 시간이 초과되었습니다. 다시 시도해 주세요. |
| `MaxCcuReached` | 접속자가 많습니다. 잠시 후 다시 시도해 주세요. |
| 그 외 | 연결이 끊어졌습니다. 다시 시도해 주세요. |

- Photon 원문 메시지는 보여주지 않는다.

### 10-4. 아티팩트에 없어 넣지 않는 것

입력창 포커스 연출 · 16자 도달 시 카운터 색 변경 · 에러 페이드 · 연결 중 버튼 비활성.
