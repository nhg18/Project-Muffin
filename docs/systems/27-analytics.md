# 27. 운영 지표 · 분석 이벤트

**최종 수정일**: 2026-11-19 (초안)
**분류**: MVP (제안 — `1.0` 포함, 출시 기능 13 과 함께)
**출처**: 2026-11-19 PM 질문 「구글 앱 등록만으로는 통계를 못 본다 — 직접 만들어야 하나」 에 대한 초안. 이 문서의 규칙은 **전부 제안**이다 — PM 확정 전에는 구현하지 않는다.
**범위**: 팀이 보는 **운영 지표**(DAU · 리텐션 · 이탈 지점 · 카드 사용률)를 무엇을 · 언제 · 누가 보내는가. 플레이어에게 보이는 전적은 이 문서가 아니다 — `07-win-condition` 11-6 (Cloud Save).

> 한 줄 요약: 처음부터 만들지 않는다. **UGS Analytics** 를 붙이면 DAU · 리텐션 · 세션은 저절로 나오고, 우리는 판 · 방 · 상자 같은 **게임 이벤트 17개**만 보낸다. 약관 동의 전에는 아무것도 보내지 않는다.

---

## 1. 목적

출시 뒤 「사람들이 돌아오는가 · 어디서 그만두는가 · 어떤 카드가 너무 세거나 안 쓰이는가」를 숫자로 보고 밸런스 · 화면을 고친다. 스토어 콘솔은 설치 · 크래시 · 평점까지만 보여 준다 (7-2).

## 2. 판정 주체

**게임 규칙 판정이 아니다.** 이벤트는 보내기만 하고, 그 값으로 게임 안의 아무것도 바뀌지 않는다.

| 이벤트 묶음 | 누가 보내나 | 이유 | 구분 |
| --- | --- | --- | --- |
| 판 단위 (5-3 의 `matchStarted` · `matchEnded` · `matchCardStats`) | **방장** 한 명 | 판마다 한 번만 남아야 한다 — 네 명이 다 보내면 4배로 센다. 값은 방장이 이미 집계하는 「게임 종료 요약」(07 11-4) 그대로 | 제안 |
| 플레이어 단위 (그 밖의 전부) | **해당 플레이어 기기** — 자기 것만 | 내 화면에서 일어난 일이다 | 제안 |
| 봇 | 보내지 않는다 — 판 단위 이벤트 안의 값(봇 수 · 봇 승리)으로만 남는다 | 봇에게 플레이어 ID 가 없다 | 제안 |

**비공개 정보**: 이벤트는 팀만 본다. 플레이어 화면 어디에도 나오지 않는다.

## 3. 핵심 규칙

| # | 규칙 | 구분 |
| --- | --- | --- |
| 1 | **도구 = UGS Analytics.** 계정 · 저장 · 설정이 이미 UGS 라 같은 플레이어 ID · 같은 대시보드로 묶인다. 별도 분석 서버 · DB 를 만들지 않는다 (`23-login` 3절 #4 「UGS 만」 과 같은 원칙) | 제안 |
| 2 | **동의 전에는 수집하지 않는다.** 약관 동의(`23` 3절 #9) 「동의하고 계속」 뒤에 수집을 켠다. 재실행 때는 기기의 동의 기록이 있으면 바로 켠다 | 제안 |
| 3 | **식별자 = UGS 플레이어 ID** (`23` 3절 #10 과 같은 값). **닉네임 · 친구 코드 · 방 코드 · 입력한 글자는 보내지 않는다** | 제안 |
| 4 | DAU · MAU · 리텐션 · 세션 길이 · 플랫폼 · 앱 버전 · 국가는 **SDK 기본 수집**으로 얻는다 — 이벤트를 따로 만들지 않는다 | 제안 |
| 5 | **분석이 게임을 막지 않는다.** 보내기 실패 · 초기화 실패 · 오프라인이어도 게임은 그대로 진행. 재시도 · 보관은 SDK 가 알아서 한다 — 우리가 재시도 코드를 두지 않는다 | 제안 |
| 6 | **개발 · 테스트 데이터는 섞지 않는다.** 에디터 · 개발 빌드 · 테스트 클론은 UGS 의 **개발 환경**, 스토어 빌드만 **운영 환경**으로 보낸다 | 제안 |
| 7 | **계정 삭제 때 분석 데이터 삭제도 요청한다** (`23` 7-3 「지우는 것」 에 추가) | 제안 |
| 8 | 턴 · 수 단위 이벤트는 보내지 않는다 — 카드 사용은 판 끝에 카드별로 한 번 묶는다 (5-3 `matchCardStats`) | 제안 |

## 4. 주요 수치

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 이벤트 종류 | 17개 (5절). 튜토리얼 이벤트는 튜토리얼 문서가 생긴 뒤 더한다 (11절 #3) | 제안 |
| 한 판에 나가는 이벤트 수 | 방장: `matchStarted` 1 + `matchEnded` 1 + `matchCardStats` (이 판에 나온 카드 종류 수, 최대 16) · 사람마다 `myMatchResult` 1 + `resultAction` 1 → 4인 판 ≈ 26개 이하 | 제안 |
| 표본 추출 | 없음 — 전원 수집 | 제안 |
| 보내는 주기 | SDK 기본값 | 제안 |

## 5. 이벤트 목록

값 이름은 영문 camelCase. 「질문」은 그 이벤트로 답하려는 것 — 답할 질문이 없는 이벤트는 두지 않는다.

### 5-1. 처음 실행 · 계정

| 이벤트 | 보내는 때 | 보내는 사람 | 값 | 질문 |
| --- | --- | --- | --- | --- |
| `consentAccepted` | 약관 동의 「동의하고 계속」 직후 (수집을 켠 뒤 첫 이벤트) | 해당 플레이어 | `language` (그때 화면 언어) | 설치한 사람 중 몇 %가 동의까지 오나 (설치 수는 스토어 콘솔) |
| `nicknameSaved` | 닉네임 저장 성공 | 해당 플레이어 | `isFirst` (첫 닉네임인가) · `rejectCount` (이번 저장 전에 금칙어로 거절된 횟수) | 첫 닉네임에서 막히나 · 금칙어 오탐이 많은가 |
| `signInFailed` | 로그인 실패 화면이 뜰 때 (`20` 8절) | 해당 플레이어 | `kind` (`network` · `rejected`) · `errorCode` | 로그인에 실패하는 비율 · 원인 |
| `titleBlocked` | 업데이트 필요 · 점검 팝업이 뜰 때 (`23` 7-6) | 해당 플레이어 | `reason` (`update` · `maintenance`) | 옛 버전에 묶인 사람이 얼마나 되나 |
| `accountLinked` | 연동 성공 (`23` 6-3) | 해당 플레이어 | `provider` (`google` · `apple`) · `switched` (「그 계정으로 바꾸기」 였나) | 게스트 중 몇 %가 연동하나 |

### 5-2. 로비 · 방

| 이벤트 | 보내는 때 | 보내는 사람 | 값 | 질문 |
| --- | --- | --- | --- | --- |
| `roomEntered` | 방 입장 성공 | 해당 플레이어 | `via` (`quickStart` · `create` · `code` · `invite`) · `isPublic` · `humans` (들어간 순간 사람 수) | 사람들이 어떤 길로 판에 들어가나 |
| `roomLeftBeforeStart` | 판이 시작되기 전에 방을 나옴 | 해당 플레이어 | `waitSeconds` (방에 있던 초) · `reason` (`self` · `kicked` · `disconnected` · `versionMismatch`) | 매칭 대기에 지쳐 나가나 · 몇 초 만에 |
| `languageChanged` | 설정 「언어」 변경 | 해당 플레이어 | `from` · `to` | 처음 고른 언어(기기 언어가 기본)를 나중에 바꾸나 (`25`) |

### 5-3. 판

| 이벤트 | 보내는 때 | 보내는 사람 | 값 | 질문 |
| --- | --- | --- | --- | --- |
| `matchStarted` | 판 시작 (덱을 나눌 때) | **방장** | `matchId` · `humans` · `bots` · `botEasy` · `botNormal` · `botHard` (난이도별 봇 수) · `quickStart` (빠른 시작 방인가) · `matchIndexInRoom` (이 방에서 몇 번째 판) | 봇 판 비율 · 같은 방에서 이어 하는가(재대전율) |
| `matchEnded` | 「게임 종료 요약」을 보낼 때 (`07` 11-4) | **방장** | `matchId` · `turns` · `durationSeconds` · `winType` (`kill` · `chapchu` · `draw`) · `winnerIsBot` · `leavers` (도중에 빠진 사람 수) · `reconnects` (재접속 횟수 합) | 한 판이 몇 분인가 · 승리 방식 비율 · 봇이 너무 이기나 |
| `matchCardStats` | `matchEnded` 바로 뒤, **이 판에 한 번 이상 나온 카드 종류마다 1개** | **방장** | `matchId` · `cardId` · `plays` (낸 횟수) · `playersUsed` (낸 사람 수) · `winnerUsed` (승자가 냈나) | 카드별 사용률 · 이 카드를 낸 사람이 이기는 비율 (밸런스) |
| `myMatchResult` | 「게임 종료 요약」을 받았을 때 (끝까지 있었던 판) | 해당 플레이어 (사람만) | `matchId` · `rank` · `won` · `winType` · `survivedTurns` · `damageDealt` · `kills` · `cardsPlayed` · `timeouts` (내 턴 시간 초과 횟수, `03`) · `chapchuDeclares` | 첫 판 · 첫 열 판의 승률 (처음 하는 사람이 너무 지나) · 15초 타이머가 짧은가 |
| `matchLeft` | 판 도중 나옴 · 3턴 연속 시간 초과 퇴장 · 끊겨서 못 돌아옴 | 해당 플레이어 | `matchId` · `turn` · `reason` (`quit` · `timeoutKick` · `disconnect`) | 판 중간에 몇 턴째 그만두나 |
| `resultAction` | 결과 화면에서 버튼을 누름 (`07` 11-2) | 해당 플레이어 | `action` (`toRoom` · `exit`) | 한 판 끝나고 다시 하려는가 |

`matchId` 는 「판 결과 보고」 의 판 식별과 같은 값이다 — 방 이름 + 판 시작 시각, 방장이 전원에게 준 값 (`24` 7-1). 방장의 이벤트와 각자의 이벤트를 이 값으로 잇는다.

### 5-4. 재화 · 치장 (`24` · `19`)

| 이벤트 | 보내는 때 | 보내는 사람 | 값 | 질문 |
| --- | --- | --- | --- | --- |
| `questRewardClaimed` | 「받기」 성공 (서버 응답 뒤). 갱신 때 자동 지급된 것도 1개씩 | 해당 플레이어 | `questId` · `kind` (`daily` · `weekly` · `achievement`) · `amount` · `auto` (자동 지급인가) | 어떤 퀘스트가 안 깨지나 · 수급이 `24` 5절 계산과 맞나 |
| `boxOpened` | 상자 결과를 받았을 때 (서버 응답 뒤) | 해당 플레이어 | `itemId` · `grade` · `duplicate` · `pity` (천장으로 나왔나) · `balanceAfter` | 실제 확률이 표시 확률과 맞나 · 뼈다귀가 남아도나 |
| `itemEquipped` | 장착 저장 성공 | 해당 플레이어 | `itemId` · `slot` | 어떤 치장이 인기인가 (디자인 우선순위) |

## 6. 상태 · 흐름

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| (앱 시작) | 기기에 동의 기록 없음 | **수집 안 함** | 아무것도 보내지 않는다 |
| 수집 안 함 | 약관 동의 | **수집 중** | 수집을 켜고 `consentAccepted` |
| (앱 시작) | 기기에 동의 기록 있음 | 수집 중 | 바로 켠다 |
| 수집 중 | 계정 삭제 성공 (`23` 6-4) | 수집 안 함 | 분석 데이터 삭제 요청 → 수집을 끈다 → 타이틀 (처음 실행) |

## 7. 상세

### 7-1. 보고 싶은 질문 → 어디서 보나

| 질문 | 볼 곳 |
| --- | --- |
| 하루 · 한 달에 몇 명이 하나 · 1일 / 7일 / 30일 뒤에 돌아오나 | UGS Analytics 기본 (3절 #4) |
| 설치 → 동의 → 첫 닉네임 → 첫 판 → 첫 판 끝 중 어디서 빠지나 | 스토어 설치 수 → `consentAccepted` → `nicknameSaved` (`isFirst`) → `matchStarted` · `myMatchResult` 의 첫 기록 |
| 판에 어떻게 들어가고, 기다리다 나가나 | `roomEntered` · `roomLeftBeforeStart` |
| 한 판 길이 · 승리 방식 · 봇 강도 | `matchEnded` · `matchStarted` |
| 카드가 너무 세거나 안 쓰이나 | `matchCardStats` (사용률 · 낸 사람의 승률) |
| 판 중간에 그만두나 · 타이머가 짧은가 | `matchLeft` · `myMatchResult.timeouts` |
| 재화 · 퀘스트 · 상자 수급이 계획과 맞나 | `questRewardClaimed` · `boxOpened` |

### 7-2. 스토어 콘솔과 나눔

| 지표 | 볼 곳 | 구분 |
| --- | --- | --- |
| 설치 · 삭제 · 국가 · 기기 · 스토어 페이지 전환 · 평점 · 리뷰 | Google Play Console · App Store Connect | 제안 |
| 크래시 · 응답 없음(ANR) | 스토어 콘솔 (Android vitals · App Store Connect). `1.0` 에는 별도 크래시 수집 도구를 두지 않는다 | 제안 |
| 게임 안의 모든 것 | UGS Analytics (이 문서) | 제안 |

### 7-3. 이벤트 등록

UGS Analytics 는 대시보드에 **먼저 등록한 이벤트 · 값만** 받는다. 이벤트를 더하거나 값을 바꾸면 이 문서 5절과 대시보드를 같이 고친다. 등록하지 않은 이벤트는 버려진다 — 게임은 영향 없다 (3절 #5).

### 7-4. 개인정보

| 항목 | 내용 | 구분 |
| --- | --- | --- |
| 개인정보 처리방침 | 「서비스 개선을 위한 앱 이용 기록(플레이 기록 · 기기 · 앱 버전 · 국가) 수집, UGS(Unity) 가 처리」 를 더한다 | 제안 |
| Google Play Data safety · Apple 개인정보 라벨 | 「앱 활동(앱 내 상호작용)」 · 「기기 · 기타 ID」 를 **분석** 목적으로 신고. 광고 · 추적 목적 없음 | 제안 |
| 보존 기간 | UGS Analytics 기본 보존 기간을 따른다 — 처리방침에 적는다 | 제안 (기간 값은 구현 전 확인) |

## 8. 예외

| 상황 | 처리 | 구분 |
| --- | --- | --- |
| 오프라인 · 서버 실패 | SDK 가 보관했다가 나중에 보낸다. 게임 진행에 영향 없음 | 제안 |
| 판 도중 방장이 바뀜 (`09` 9.1) | 게임 종료 때의 방장이 `matchEnded` · `matchCardStats` 를 보낸다 — 「게임 종료 요약」과 같은 값. `matchStarted` 는 처음 방장이 이미 보냈다 | 제안 |
| 재접속해서 판 끝까지 있었음 (`09` 12절) | `myMatchResult` 1개 · `matchLeft` 없음. `matchEnded.reconnects` 에 센다 | 제안 |
| 끊겨서 못 돌아옴 | `matchLeft (disconnect)` 는 다음 실행 때 나갈 수 있다 — SDK 보관. 끝내 안 들어오면 남지 않고, `matchEnded.leavers` 에만 센다 | 제안 |
| 결과 화면을 보는 중 방장이 다음 판 시작 (`07` 11-1) | `resultAction` 을 보내지 않는다 (누르지 않았다). 다음 판은 `matchStarted` 로 센다 | 제안 |
| 앱 버전마다 카드 번호가 다름 | `matchCardStats.cardId` 는 카드 데이터 번호 그대로. 같은 카드 데이터 버전끼리만 매칭되므로(`26-card-data` 7-6) 한 판 안에서는 섞이지 않는다 | 제안 |
| 분석 초기화 실패 | 이벤트를 버린다. 다음 실행 때 다시 켠다 | 제안 |
