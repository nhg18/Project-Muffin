# 07. 승리 조건

**최종 수정일**: 2026-11-07
**분류**: Core

---

## 1. 목적

게임이 끝나는 조건과 승자 판정 규칙을 정의한다.

---

## 2. 승리 조건 2가지

| # | 이름 | 조건 |
| --- | --- | --- |
| ① | **처치 승리** | 다른 모든 플레이어가 탈락하고 마지막 1인으로 생존. 탈락 = 최종 사망 · 나가기 · 연결 끊김 뒤 강제 퇴장 — 전부 최종 사망 처리(`01-game-flow` 6절)라 어떻게 빠졌든 같은 승리다 (확정 2026-11-07) |
| ② | **찹츄 승리** | 손패 10장 도달 후 선언 → 다음 자신의 턴 시작까지 정확히 10장 유지 |

---

## 3. 처치 승리

| 규칙 | 내용 | 구분 |
| --- | --- | --- |
| 판정 시점 | 모든 연쇄(체인) 처리와 사망 대기가 끝난 뒤. 예: 마지막 상대를 처치했는데 그 상대의 T01(사망 시 생존자 전원 피해)로 나도 죽으면 무승부. 단 연쇄가 없는 때 이탈로 1명이 남으면 바로 판정 | 확정 (2026-10-30) |
| 조건 | 게임에 남은(나가지 않고 최종 사망하지 않은) 플레이어가 1명. 혼자 시작한 게임(개발용)은 판정하지 않는다 | 확정 / 제안 (혼자 시작) |
| 탈락자 카드 | 손패·설치 함정 모두 버림 더미로 소멸 | 확정 |
| 전원 최종 사망 | **무승부** | 확정 |

## 4. 찹츄 승리

### 4.1 선언

| 규칙 | 내용 | 구분 |
| --- | --- | --- |
| 선언 조건 | 손패가 **정확히 10장** | 확정 |
| 선언 방식 | 소유자가 **찹츄 버튼을 직접 클릭** (자동 선언 아님) | 확정 |
| 선언 시점 | 살아 있고 손패가 10장인 동안 **언제든** (남의 턴 포함). 내 턴에는 드로우로 10장이 되면 5초 선언 대기가 열린다 (아래 줄) | 확정 (2026-10-30) |
| 내 턴 드로우로 10장 — 선언 대기 | 턴이 바로 끝나지 않고 **5초 「선언 대기」** 가 열린다 (`03-turn` 4절 · 7절). 5초 안에 찹츄 버튼을 누르면 선언이 승인된 순간 턴이 넘어가고, 누르지 않으면 5초 뒤 넘어간다. 시간 측정 · 판정은 **방장**. 대기 중 다른 입력(카드 사용 · 다시 뽑기)은 받지 않는다. 턴 제한 20초와 별개 창. 남의 턴 중 선언은 그 턴에 영향 없다. 봇도 같다 (`18-bot` 7-5) | 확정 (2026-11-07, PM) |
| 턴 시작 때 이미 10장(미선언)인 사람의 내 턴 중 선언 | 턴을 끝낼지 **규칙 없음** — 지금은 20초 대기가 생길 수 있다 (`03-turn` 12절 #7) | **미정 — PM** (12절 #6) |
| 선언 연출 | 전원 화면에 1.5초 연출 + 선언자 분홍 테두리 유지 (`10-ui` 7절) | 확정 (2026-11-07) |

### 4.2 유지

| 규칙 | 내용 | 구분 |
| --- | --- | --- |
| 유지 조건 | 다음 자신의 턴 시작까지 **정확히 10장** 유지 | 확정 |
| 해제 | 10장이 아니게 되는 **순간 즉시 해제** | 확정 |
| 자동 재선언 | 없음 | 확정 |
| 재선언 | 첫 선언과 같이 **언제든** 다시 선언 가능 | 확정 (2026-10-30) |

### 4.3 판정

> 선언 후 **자신의 다음 턴이 시작되는 순간** 찹츄 상태이면 승리.

* 생존 상태에서 자신의 턴이 시작될 때 손패가 정확히 10장이면 승리 조건 충족.
* 판정은 마스터가 한다.

## 7. 찹츄 상태를 조작하는 카드

| 카드 | 효과 |
| --- | --- |
| 찹츄 전원 피해 (A02) | 찹츄 상태 플레이어 전원 HP - N |
| 찹츄 옮기기 (A20) | 첫 번째 대상의 찹츄 상태를 제거하고 두 번째 대상에게 부여 |
| 자기 찹츄 해제 (A21) | 본인 패에서 무작위 N장 버린 후 본인의 찹츄 상태 제거 |
| 찹츄 부여 무효화 카운터 (C15) | 다른 플레이어가 본인에게 찹츄 상태를 부여할 때 무효화 |
| 찹츄 전원 3장 버림 함정 (T04) | 찹츄 상태 플레이어 전원(본인 제외) 패에서 3장 강제 버림 |
| 찹츄 되돌려 주기 함정 (T16) | 본인에게 찹츄를 부여한 플레이어에게도 찹츄 상태 부여 |

> **찹츄 상태는 손패 10장에서 파생되는 값이 아니라, 별도로 부여·제거되는 상태다.** (찹츄 옮기기 카드(A20)가 이를 요구한다)
> 단, 손패가 10장이 아니게 되면 부여된 찹츄도 즉시 해제된다.

## 8. 상태 흐름

```
Normal ──(손패 10장 + 찹츄 버튼)──→ ChapChu
ChapChu ──(손패 ≠ 10장)──────────→ Normal (즉시 해제)
ChapChu ──(A20/A21 효과)────────→ Normal
Normal  ──(A20/T16 효과)────────→ ChapChu (손패 10장 아니면 즉시 해제)
ChapChu ──(자신의 턴 시작)───────→ 승리
```

## 11. 결과 화면 · 통계

> 이 절은 전부 **확정 (2026-11-07, PM)** 이다. PM 지시(2026-11-06): 「5초 뒤 자동 방 복귀」 는 폐기하고, 결과 화면에서 안 나오는 사람 처리 · 룸에서 지난 결과를 다시 보는 UI · 통계를 새로 짠다 → 2026-11-07 승인. 승인 때 바뀐 것: 결과 화면에 방장 「시작」 버튼을 두지 않는다 · 「최후 1인」 라벨 폐기 · 「찹츄 성공 수」 삭제. 화면 자리 · 크기만 **미정 (디자인)** — [`10-ui.md`](10-ui.md) 10절.

### 11-1. 흐름 — 결과 화면은 방(Room)의 한 상태

| 현재 상태 | 조건 | 다음 상태 | 결과 | 판정 | 구분 |
| --- | --- | --- | --- | --- | --- |
| 플레이 | 승리 판정 확정 (3 · 4 · 6절) | 결과 화면 | 방장이 「게임 종료 요약」(11-4)을 전원에게 1회 보내고, 방을 바로 **대기**로 돌린다 (공개 · 열림 — `08-room` 4절). 각 클라이언트는 받은 요약으로 결과 화면을 그린다 | 방장 | 확정 (2026-11-07) |
| 결과 화면 | 「방으로」 탭 | 방 화면 (대기) | **자기 화면만** 방 화면으로 바뀐다. 다른 사람은 그대로 결과 화면 | 각 클라이언트 | 확정 (2026-11-07) |
| 결과 화면 | 방장이 **방 화면에서** 다음 판 시작 | 플레이 | 결과 화면을 보고 있던 사람도 결과 화면이 닫히고 게임에 들어간다 — 방에 있으니 참가자다. 「안 나오는 사람」 때문에 막히는 것은 없다 | 방장 | 확정 (2026-11-07) |
| 결과 화면 | 「나가기」 탭 | 로비 | 방을 나간다 (`02-player` 6절 퇴장과 같다) | 각 클라이언트 | 확정 (2026-11-07) |
| 결과 화면 | 시간 경과 | — | **아무 일도 없다 — 자동 복귀 없음** | — | 확정 (2026-11-07 — 2026-11-06 「5초 뒤 방으로」 폐기) |

* 결과 화면을 보는 동안에도 그 사람은 **방에 있는 사람**이다 — 방 화면의 인원 수 · 칸에 그대로 보이고, 그 사람 칸에 「결과 보는 중」 표시가 붙는다 (`16-room-ui` 가 정한다 — 담당 다름).
* 방장이 결과 화면에 있어도 방은 대기 상태다. **결과 화면에는 시작 버튼을 두지 않는다** — 방장도 「방으로」 를 눌러 방 화면에 가야 시작 버튼이 보인다 (확정 2026-11-07, PM).
* 봇은 결과 화면이 없다 — 방에 남는다 (`18-bot` 8절).

오버레이 — 인게임 화면 위에 덮는다. 자리 · 크기는 `10-ui` 10절.

| 찹츄 승리 | 4절 | 확정 (2026-11-07) |

### 11-3. 순위 · 킬

| 킬 | 어떤 플레이어의 HP 를 0 으로 만든 **마지막 피해의 주인**에게 1. 피해의 주인 = 그 피해를 낸 카드(행동 · 함정)를 낸 · 발동한 플레이어. 전원 피해 카드도 같다 | 확정 (2026-11-07) |

### 11-4. 이 판의 통계 — 「게임 종료 요약」

| 항목 | 세는 법 | 구분 |
