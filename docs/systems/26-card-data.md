**최종 수정일**: 2026-11-21 (게임이 `cards.json` 을 직접 읽어 얹는다 — 「카드 패치하기」 버튼 · 「카드 패치」 창 · 빌드 검사 · 확인값을 걷어냄, PM. 2절 · 3절 #10 · #11 · 6-1 · 7-2 · 7-3 · 7-4 · 8절). 이전: 2026-11-21 (원격 패치를 걷어냄), 2026-11-20 (개선안), 2026-11-19
**분류**: MVP (출시 `1.0` 에 포함)
**출처**: 2026-11-19 PM 결정 (플랜 세션) — 능력은 정의와 함께 · 그림만 따로 불러오기 · 노션 → 봇 → 카드 데이터 파일. 2026-11-20 PM 「문서대로 하지 말고 허점을 찾아 개선해서 구현」 — 이 문서의 **「확정 (개선안)」** 은 그 위임으로 AI 가 정한 값이다. 2026-11-20 PM 결정 — 카드 패치는 **빌드 패치에 넣는다**(원격 패치 없음) · 봇이 `cards.json` 을 `develop` 에 PR 하고 PM 이 머지하면 끝 · 게임을 켰을 때 새 버전이 있으면 막고 스토어로 보낸다. **2026-11-21 PM 결정** — 버튼을 눌러 에셋에 반영하지 않는다. **게임이 켜질 때 `cards.json` 을 읽어 카드 정의(SO) 위에 값을 얹는다.**
**범위**: 카드 데이터를 **어디에 두고 어떻게 빌드까지 가는가**. 카드마다의 효과는 [`11-card-list.md`](11-card-list.md), 덱 · 손패 규칙은 [`05-deck.md`](05-deck.md), 문구 번역 규칙은 [`25-localization.md`](25-localization.md), 버전 · 올리는 순서는 [`../versioning.md`](../versioning.md), 최소 버전 · 「업데이트 필요」 는 [`23-login.md`](23-login.md) 7-6.

> 한 줄 요약: **카드의 값(이름 · 문구 · 수치 · 장수)은 파일 하나(`cards.json`)가 원본이다.** 노션에서 고치면 봇이 그 파일을 `develop` 에 PR 하고, **PM 이 머지하면 끝이다** — 파일이 빌드에 같이 들어가고, 게임이 플레이를 시작할 때 읽어 카드 정의 위에 얹는다. 유저에게는 **앱 업데이트로** 나간다 — 앱 버전이 같으면 카드도 같다.

### 6-1. 값 얹기 (플레이를 시작할 때)

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| 앱이 켜짐 | — | 얹기 전 | 화면에 단계가 없다 — 타이틀의 로딩 글 · 순서는 그대로다 (`20-title-ui-full` 6절) |
| 얹기 전 | 덱을 처음 쓴다 (카드를 찾는다 · 덱을 만든다 · 그림을 불러온다) | 얹음 | `Deck_Main` 이 쥔 `cards.json` 을 읽는다 → 카드 정의마다 **사본**을 만들어 파일의 값을 넣는다 → 덱을 파일의 순서 · 장수로 짠다. 그 실행 동안 이 사본을 쓴다 |
| 얹음 | 앱을 끈다 (에디터: 플레이를 끝낸다) | — | 사본이 사라진다. 다음에 켜면 다시 얹는다 |

* **에셋은 고치지 않는다.** 얹는 것은 메모리에서만 일어난다. 에디터에서 플레이를 눌러도 같다.
* 에디터에서 플레이 중이 아닐 때(씬을 만드는 도구 등)는 에셋을 그대로 본다 — 사본이 씬 · 에셋에 물리지 않게.
* 값 파일이 없는 덱(시험용 `Deck_Default` · `Deck_Test`)은 에셋 값 그대로 쓴다.
* 순서는 파일 순서다 — 같은 빌드끼리 장 번호가 같아야 방장 이주가 된다 (`09-network` 9.1).
* 새 버전이 있는지는 타이틀의 「설정 읽는 중」 이 본다 (`23-login` 6-1).

## 7. 상세

### 7-1. 데이터 넷

| 데이터 | 무엇 | 무게 | 어디 |
| --- | --- | --- | --- |
| **카드 정의** | 카드 1종의 **구조** — 번호 · 종류 · 효과(종류와 순서) · 반응 대상 · 연출 시간. 값 칸(이름 · 문구 · 수치 …)도 있지만 게임에 나오는 값이 아니다 — 값 파일을 읽지 못했을 때만 쓴다 (8절) | 가볍다 | 빌드 — `Assets/Cards/Main/Card_<카드 번호>.asset` |
| **값 파일** | 카드마다의 **값** — 이름 · 문구 · 대상 · 조건 · 등급 · 장수 · 효과 값 (7-2) | 가볍다 (약 6KB) | 빌드 — `Assets/Cards/Main/cards.json` |
| **카드 그림** | 앞면 그림 | 무겁다 (한 종류 약 1MB) | 빌드 — `Assets/Resources/CardArt/<카드 번호>.png` |
| **덱** | 이 빌드에 있는 카드 정의의 목록 + 값 파일. 어떤 카드를 몇 장 넣는지는 값 파일의 장수가 정한다 (`05-deck` 8절) | 가볍다 | 빌드 — `Deck_Main` |

* 게임 안의 **카드 한 장**은 데이터가 아니라, 방장이 게임 시작 때 덱에서 장마다 만드는 값이다 (`05-deck` 3절).
* 카드 목록(도감용)은 따로 두지 않는다 — `cards.json` 의 모든 줄이 목록이고, 장수 0 인 줄이 「덱에는 없지만 게임에 있는 카드」 다.
* 연출 시간은 `cards.json` 에 없다 (에셋에만 있다).

### 7-2. 값 파일 (`cards.json`)

저장소 `MuffinProject/Assets/Cards/Main/cards.json`. **빌드에 들어간다** — `Deck_Main` 이 이 파일을 쥐고, 게임이 읽는다 (6-1).

```json
{
  "cards": [
    {
      "id": 1005, "name": "드롭킥", "type": "Action", "target": "OneOther", "targetCondition": "None", "grade": "Rare", "count": 3,
      "text": "{0} 피해를 준다. 못 쓰러뜨리면 나도 {1} 피해를 받는다",
      "effects": [ { "type": "DamageEffect", "args": "subject=Target, amount=49" }, { "type": "RecoilDamageEffect", "args": "amount=49" } ]
    }
  ]
}
```

| 칸 | 뜻 | 파일만 고치면 되나 |
| --- | --- | --- |
| `id` | 카드 번호. 이 번호의 카드 에셋이 빌드에 있어야 한다 | ✗ (새 카드 = 개발 작업, 7-3) |
| `name` · `text` | 이름 · 문구 | ○ |
| `type` | 카드 종류. 에셋과 다르면 그 카드는 실패 (8절) | ✗ |
| `target` · `targetCondition` · `grade` | 대상 · 대상 후보 조건 · 등급 | ○ |
| `count` | 덱에 넣는 장수. 0 이면 덱에서 빠진다 | ○ |
| `effects[].type` | 효과 종류 — 순서 · 개수까지 에셋과 같아야 한다 | ✗ |
| `effects[].args` | 효과 값 — `필드=값, 필드=값` | ○ (값만. 음수는 받지 않는다) |

「○」 인 칸은 **봇 PR → 머지로 끝난다.** 「✗」 인 칸이 바뀌면 사람이 에셋 · 코드를 같이 고친다.

**값 자리** — 문구의 `{n}` 은 **그 카드의 효과 `args` 에 적힌 숫자 값을, 적힌 순서대로 0번부터 센 n번째**다. 위 예에서 `{0}` = 49(피해), `{1}` = 49(반동). 숫자가 아닌 값(`subject=Target`)은 세지 않는다. 문구에 숫자를 그대로 써도 된다(값 자리 없이) — 그때는 수치를 바꿔도 문구가 따라 바뀌지 않는다. 값 자리 번호가 효과 값 개수를 넘거나, 번호를 읽을 수 없으면(전각 숫자 `{１}` 처럼 ASCII 숫자가 아니다 · 너무 크다) 그 카드는 실패다 (8절).

```
노션 카드 DB (기획 편집)
 → 카드 정리 봇 (매일, GitHub Actions) → cards.json 을 develop 에 PR (bot/card-sync)   ← 수치만 바뀐 문구는 효과 값(args)을 고친다
 → PM 이 머지                                                                         ← 끝. develop 을 받아 플레이하면 새 값이다
 → 버전을 올리고 빌드 → 스토어                                                        ← cards.json 이 빌드에 같이 들어간다
 → (출시 뒤) 두 스토어에 다 올라가면 minVersion 을 올린다
 → 유저: 앱을 켜면 「업데이트 필요」 → 「스토어로」
```

| 단계 | 누가 | 구분 |
| --- | --- | --- |
| 봇이 확정 카드만 파일에 넣는다 | 봇 | 확정 (기존) |
| 봇: 노션 문구가 값 자리를 채운 글과 **숫자만** 다르면 효과 값을 고친다. 글이 다르면 노션 글을 그대로 넣고(값 자리가 풀린다) PR 에 알린다 — 사람이 값 자리를 다시 넣는다 | 봇 | 확정 (개선안) |
| 봇은 Unity 를 모른다 — 글자 파일(`cards.json` · `11-card-list` 1-1)만 고친다. 카드 에셋을 고치는 것은 아무도 없다 | 봇 | 확정 (2026-11-21 PM) |
| 봇 PR 을 **그대로 머지한다. 그 뒤 할 일이 없다** — 값 얹기는 게임이 한다 (6-1) | PM | 확정 (2026-11-20 · 2026-11-21 PM) |
| 버전 · 빌드 · `minVersion` | PM | [`../versioning.md`](../versioning.md) 「올리는 순서」 |
| **되돌리기** = 노션을 되돌린다(봇이 되돌리는 PR 을 낸다) → 머지 → 새 빌드. 이미 나간 빌드의 카드는 바뀌지 않는다 | PM | 확정 (2026-11-20 PM 에서 따라 나옴) |
| **새 카드** = 봇이 넣지 않는다(효과를 만들어야 한다). 개발이 효과 코드 · 그림을 넣고 `cards.json` 에 줄을 더한 뒤 **「카드 가져오기」**(메뉴 `Chapchu/카드 가져오기`)를 누른다 — 카드 에셋이 생기고(효과는 파일의 종류대로) `Deck_Main` 의 목록에 들어간다. 반응 대상 · 연출 시간 같은 구조 값은 에셋에서 넣는다. 에셋 · `Deck_Main` 을 커밋한다 | 개발 | 확정 (기존) |
| **효과 구성이 바뀐 카드**(리워크) = 개발이 카드 에셋의 효과와 `cards.json` 의 `effects` 를 같이 고친다 | 개발 | 확정 (기존) |

**「카드 가져오기」** 는 누를 때 모든 카드 에셋의 값 칸도 파일 값으로 덮는다 — 인스펙터에 보이는 값이 파일과 같아진다. 값이 바뀐 카드는 「전 → 후」 를 콘솔에 찍는다. 누르지 않아도 게임에 나오는 값은 파일 값이다. 효과는 **에셋에 효과가 하나도 없을 때만** 파일의 종류대로 새로 만든다 — 이미 있으면 종류 · 순서가 파일과 같아야 하고 값만 덮는다.

### 7-6. 노션을 게임이 직접 읽지 않는 이유

| 이유 | 내용 |

| 토큰 | 앱 안에 노션 토큰이 들어가야 한다. 꺼내면 미공개 카드 · 회의 내용을 읽는다 |

### 7-7. 카드 문구의 번역 (12L 때 만든다)

지금은 한국어 `cards.json` 하나다. 다국어(12L)를 만들 때 카드 이름 · 문구의 번역을 **빌드에 넣는다** — 화면 문구와 같은 길이고, 언어를 바꿀 때 받는 단계가 없다 (2026-11-20 PM 결정에서 따라 나옴, `25-localization` 6절 · 7-3). 값 자리(7-2)가 있어 수치 패치에는 번역이 필요 없다. 파일 모양은 12L 때 정한다 (9절 #2).

## 8. 예외

틀린 파일로도 게임은 멈추지 않는다. 같은 빌드는 모두 같은 파일을 읽으므로 **모두 같은 결과**가 나온다 — 방 안에서 값이 갈리지 않는다. 어느 경우든 콘솔에 에러로 남는다(에디터에서 플레이하면 보인다).

| 상황 | 처리 | 구분 |
| --- | --- | --- |
| `cards.json` 이 JSON 이 아니다 · 카드가 없다 · 같은 번호가 두 번 · 장수가 음수 · 덱이 0장 | 파일을 통째로 쓰지 않는다 — **전부 에셋 값**(덱 구성 포함)으로 간다 | 제안 |
| 카드 종류가 에셋과 다르다 · 효과의 종류 · 개수 · 순서가 다르다 · 효과에 없는 값 이름 · 음수 · 모르는 대상 · 조건 · 등급(이름이 정확히 맞아야 한다 — 숫자 · 쉼표 목록은 받지 않는다) · 이름이 비었다 · 값 자리가 값보다 많다 · 값 자리 번호를 읽을 수 없다 | **그 카드만** 에셋 값으로 간다(반쯤 얹은 사본은 버린다). 장수는 파일대로. 나머지 카드는 파일 값 | 제안 |
| 파일에 있는데 카드 에셋이 없는 번호 (새 카드를 「카드 가져오기」 없이 넣었다) | 그 카드는 덱에 들어가지 않는다 | 제안 |
| 카드 에셋은 있는데 파일에 없는 번호 | 덱에서 빠진다(0장). 정의는 남는다 | 확정 (개선안) |
| 카드 에셋의 값 칸을 손으로 고쳤다 | 게임에 나오지 않는다 — 파일 값이 얹힌다. 다음 「카드 가져오기」 가 파일 값으로 되돌린다 | 확정 (2026-11-21) |
| 에셋의 값이 파일보다 낡았다 (값만 바뀐 패치 뒤에는 아무도 에셋을 고치지 않는다) | 정상이다 — 게임은 파일 값을 쓴다. 에셋 값은 위 실패 때만 나온다 | 확정 (2026-11-21) |
| 그림이 없는 카드 | 그 카드만 그림 없이 보인다 (6-3) | 확정 (2026-11-19) |
| 앱을 켠 채 새 버전이 나왔다 | 로비에서 방에 가려 할 때 「업데이트 필요」 → 타이틀 (`23-login` 7-6). 그 전까지는 옛 버전끼리 논다 | 확정 (2026-11-20) |
