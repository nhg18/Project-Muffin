**범위**: 카드 데이터를 **어디에 두고 어떻게 빌드까지 가는가**. 카드마다의 효과는 [`11-card-list.md`](11-card-list.md), 덱 · 손패 규칙은 [`05-deck.md`](05-deck.md), 문구 번역 규칙은 [`25-localization.md`](25-localization.md), 버전 · 올리는 순서는 [`../versioning.md`](../versioning.md), 최소 버전 · 「업데이트 필요」 는 [`23-login.md`](23-login.md) 7-6.

> 한 줄 요약: **카드의 값(이름 · 문구 · 수치 · 장수)은 파일 하나(`cards.json`)가 원본이다.** 노션에서 고치면 봇이 그 파일을 `develop` 에 PR 하고, PM 이 머지하고, Unity 에서 「카드 패치하기」 를 눌러 카드 에셋에 반영한다. 유저에게는 **앱 업데이트로** 나간다 — 앱 버전이 같으면 카드도 같다.

## 6. 상태 · 흐름

### 6-1. 앱 시작 (타이틀)

카드 데이터 단계는 **없다.** 게임은 빌드에 든 카드 에셋을 그대로 쓴다 — 받지도 맞추지도 않는다. 새 버전이 있는지는 타이틀의 「설정 읽는 중」 이 본다 (`23-login` 6-1 · `20-title-ui-full` 6절).

### 6-2. 설정에서 언어 바꾸기

다국어(12L)를 만들 때 한다 — 7-7.

### 6-3. 게임 화면

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| 게임 화면이 열림 | — | 인게임 | 덱에 든 카드 종류(장수 1 이상)의 그림을 전부 불러와 화면이 쥐고 있는다 |
| 인게임 | 그림이 없는 카드 | 인게임 | 그 카드만 그림 없이(이름 · 문구만) 보인다. 판을 멈추지 않는다 |
| 인게임 | 게임 화면을 떠남 | — | 그림이 내려간다 |

* 같은 카드가 여러 장이어도 그림은 하나다 — **종류 수**만큼 불러온다.
* 그림이 많아져 화면 여는 시간이 눈에 띄면, 게임 시작 전환(`15-screen` 9절)이 화면을 덮은 동안 불러오게 옮긴다. 지금(15종)은 그럴 필요가 없다. 확정 (개선안).

### 6-4. 도감

도감 화면을 만들 때 한다. 규칙은 3절 #6 — 정의는 전부(가볍다), 그림은 보이는 칸만 불러오고 화면에서 나가면 내린다. 그림을 불러오는 길은 6-3 과 같다(카드 번호로 찾기).

## 7. 상세

### 7-1. 데이터 셋

| 데이터 | 무엇 | 무게 | 어디 |
| --- | --- | --- | --- |
| **카드 정의** | 카드 1종 — 번호 · 이름 · 문구 · 종류 · 대상 · 조건 · 등급 · 효과(종류 + 값) · 연출 시간 | 가볍다 | 빌드 — `Assets/Cards/Main/Card_<카드 번호>.asset` |
| **카드 그림** | 앞면 그림 | 무겁다 (한 종류 약 1MB) | 빌드 — `Assets/Resources/CardArt/<카드 번호>.png` |
| **덱** | 어떤 카드를 몇 장 (`05-deck` 8절) | 가볍다 | 빌드 — `Deck_Main` |

* 게임 안의 **카드 한 장**은 데이터가 아니라, 방장이 게임 시작 때 덱에서 장마다 만드는 값이다 (`05-deck` 3절).
* 카드 목록(도감용)은 따로 두지 않는다 — `cards.json` 의 모든 줄이 목록이고, 장수 0 인 줄이 「덱에는 없지만 게임에 있는 카드」 다.
* 연출 시간은 `cards.json` 에 없다 (에셋에만 있다).

### 7-2. 카드 데이터 파일 (`cards.json`)

저장소 `MuffinProject/Assets/Cards/Main/cards.json`. **에디터에서만 읽는다** — 빌드에 들어가지 않고, 게임은 이 파일을 얹은 카드 에셋을 읽는다.

```json
{
  "cards": [
    {
      "id": 1005, "name": "드롭킥", "type": "Action", "target": "OneOther", "targetCondition": "None", "grade": "Rare", "count": 3,
      "text": "{0} 피해를 준다. 못 쓰러뜨리면 나도 {1} 피해를 받는다",
      "effects": [ { "type": "DamageEffect", "args": "subject=Target, amount=49" }, { "type": "RecoilDamageEffect", "args": "amount=49" } ]
    }
  ]
}
```

| 칸 | 뜻 | 파일만 고치면 되나 |
| --- | --- | --- |
| `id` | 카드 번호. 에셋이 없는 번호면 「카드 패치하기」 가 에셋을 새로 만든다 — 효과 코드 · 그림은 사람이 넣는다 | ✗ (새 카드 = 개발 작업) |
| `name` · `text` | 이름 · 문구 | ○ |
| `type` | 카드 종류. 에셋과 다르면 그 카드는 실패 | ✗ |
| `target` · `targetCondition` · `grade` | 대상 · 대상 후보 조건 · 등급 | ○ |
| `count` | 덱에 넣는 장수. 0 이면 덱에서 빠진다 | ○ |
| `effects[].type` | 효과 종류 — 순서 · 개수까지 에셋과 같아야 한다 | ✗ |
| `effects[].args` | 효과 값 — `필드=값, 필드=값` | ○ (값만. 음수는 받지 않는다) |

「○」 인 칸은 봇 PR → 머지 → 「카드 패치하기」 로 끝난다. 「✗」 인 칸이 바뀌면 사람이 에셋 · 코드를 같이 고친다.

**값 자리** — 문구의 `{n}` 은 **그 카드의 효과 `args` 에 적힌 숫자 값을, 적힌 순서대로 0번부터 센 n번째**다. 위 예에서 `{0}` = 49(피해), `{1}` = 49(반동). 숫자가 아닌 값(`subject=Target`)은 세지 않는다. 문구에 숫자를 그대로 써도 된다(값 자리 없이) — 그때는 수치를 바꿔도 문구가 따라 바뀌지 않는다. 값 자리 번호가 효과 값 개수를 넘거나, 번호를 읽을 수 없으면(전각 숫자 `{１}` 처럼 ASCII 숫자가 아니다 · 너무 크다) 그 카드는 실패다 (8절).

**확인값** — 파일 내용의 SHA-256(소문자 16진수). 줄바꿈(CRLF · LF)과 BOM 은 빼고 센다 — 같은 파일이 저장소 줄바꿈 정책 때문에 다른 값이 되지 않게. 「카드 패치하기」 가 다 얹은 뒤 `Deck_Main` 에 이 값을 적는다. **파일의 확인값 ≠ `Deck_Main` 에 적힌 값 = 아직 패치하지 않았다** (7-3).

**「카드 패치하기」** — Unity 메뉴 `Chapchu/카드 패치하기` (또는 「카드 패치」 창의 버튼). 이 파일을 카드 에셋 · `Deck_Main` 에 얹는다. 값이 바뀐 카드는 「전 → 후」 를 콘솔에 찍는다. 효과는 **에셋에 효과가 하나도 없을 때만** 파일의 종류대로 새로 만든다(새 카드) — 이미 있으면 종류 · 순서가 파일과 같아야 하고 값만 덮어쓴다.

### 7-3. 패치 흐름

```
노션 카드 DB (기획 편집)
 → 카드 정리 봇 (매일, GitHub Actions) → cards.json 을 develop 에 PR (bot/card-sync)   ← 수치만 바뀐 문구는 효과 값(args)을 고친다
 → PM 이 머지
 → develop 을 받아 Unity 를 열면 「카드 패치」 창 → 「카드 패치하기」 → 바뀐 카드 에셋 · Deck_Main 을 커밋
 → 버전을 올리고 빌드 → 스토어                                                        ← 패치하지 않았으면 빌드가 실패한다
 → (출시 뒤) 두 스토어에 다 올라가면 minVersion 을 올린다
 → 유저: 앱을 켜면 「업데이트 필요」 → 「스토어로」
```

| 단계 | 누가 | 구분 |
| --- | --- | --- |
| 봇이 확정 카드만 파일에 넣는다 | 봇 | 확정 (기존) |
| 봇: 노션 문구가 값 자리를 채운 글과 **숫자만** 다르면 효과 값을 고친다. 글이 다르면 노션 글을 그대로 넣고(값 자리가 풀린다) PR 에 알린다 — 사람이 값 자리를 다시 넣는다 | 봇 | 확정 (개선안) |
| 봇 PR 은 `cards.json` · `11-card-list` 1-1 만 바꾼다. **그대로 머지한다** — 에셋은 머지 뒤에 패치한다 | PM | 확정 (2026-11-20 PM) |

### 7-6. 노션을 게임이 직접 읽지 않는 이유

| 이유 | 내용 |
| --- | --- |
| 요청 제한 | 노션 API 는 통합 하나당 평균 초당 3회 — 게임 전체가 나눠 쓴다 |
| 토큰 | 앱 안에 노션 토큰이 들어가야 한다. 꺼내면 미공개 카드 · 회의 내용을 읽는다 |
| 속도 | 요청 한 번이 0.3 ~ 1초, 한 번에 100행까지 |

### 7-7. 카드 문구의 번역 (12L 때 만든다)

지금은 한국어 `cards.json` 하나다. 다국어(12L)를 만들 때 카드 이름 · 문구의 번역을 **빌드에 넣는다** — 화면 문구와 같은 길이고, 언어를 바꿀 때 받는 단계가 없다 (2026-11-20 PM 결정에서 따라 나옴, `25-localization` 6절 · 7-3). 값 자리(7-2)가 있어 수치 패치에는 번역이 필요 없다. 파일 모양은 12L 때 정한다 (9절 #3).
