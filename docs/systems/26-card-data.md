# 26. 카드 데이터 — 불러오기 · 원격 패치

**최종 수정일**: 2026-11-19
**분류**: MVP (출시 `1.0` 에 포함 — 원격 패치 구조는 출시 전에 넣는다. 출시 뒤에 넣으면 이미 깔린 옛 앱이 원격 데이터를 읽지 못한다)
**출처**: 2026-11-19 PM 결정 (플랜 세션) — 데이터 넷 · 능력은 정의와 함께 · 그림만 따로 불러오기 · 도감 / 게임 화면 불러오는 때 · 노션 → 봇 → 카드 데이터 파일 → UGS CCD · 같은 데이터 버전끼리 매칭 · 과금 안전장치 · 다국어 카드 문구도 원격, 언어를 바꿀 때 그 언어를 받는다. 같은 날 PM: 원격 범위(버전 · 문구 · 수치 · 덱 구성, 새 카드는 앱 패치) · 처음 시작 때 언어 선택(기본 = 기기 지역 · 언어) · 방 속성으로 같은 버전만 들어가기 · 로비에서 방에 가려 할 때 버전 확인 → 받을지 묻기 · 안전장치 값은 조사해서 추천안을 받기로.
**범위**: 카드 데이터를 **어디에 두고 언제 불러오는가**. 카드마다의 효과는 [`11-card-list.md`](11-card-list.md), 덱 · 손패 규칙은 [`05-deck.md`](05-deck.md), 문구 번역 규칙은 [`25-localization.md`](25-localization.md), 외부 서비스 비용은 [`../store-release.md`](../store-release.md) 3절.

> 한 줄 요약: **카드 정의(이름 · 문구 · 수치 · 능력)는 가볍게 한 번에, 무거운 그림만 필요할 때 불러온다.** 밸런스 · 문구 패치는 앱 업데이트 없이 서버(UGS CCD)의 파일을 바꾸고, 앱은 켤 때 버전이 바뀌었을 때만 받는다. 같은 데이터 버전끼리만 같이 논다.

## 1. 목적

카드가 수백 장이 되어도 모바일 메모리 · 로딩이 버티게 하고, 밸런스 · 문구를 스토어 심사 없이 고칠 수 있게 한다.

| 9 | **원격 패치** — 카드의 **이름 · 문구 · 수치 · 덱 구성(카드별 장수)** 은 앱 업데이트 없이 서버(UGS CCD)의 파일을 바꿔 고친다. **새 카드**(빌드에 없는 카드 번호)는 앱 업데이트로만 낸다 — 그림 · 효과 종류가 빌드에 있어야 하기 때문이다 (7-3) | 확정 (2026-11-19) |
| 10 | **노션은 편집하는 곳이다.** 게임은 노션을 읽지 않는다 — 유저에게는 봇이 만든 파일만 나간다 (7-9) | 확정 (2026-11-19) |

| 12 | 받기에 실패하면 **기기 저장본**, 그것도 없으면 **빌드 기본본**으로 간다. 받지 못해도 게임은 된다 | 확정 (2026-11-19) |
| 13 | 카드 이름 · 카드 문구의 다국어도 원격 파일에 같이 둔다. 파일은 **언어마다** 나눈다 — 처음 시작할 때 그 언어만 받고, 설정에서 언어를 바꾸면 **그때** 그 언어를 받는다 (7-7) | 확정 (2026-11-19) |

## 4. 수치

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 카드 데이터 크기 (지금) | 카드 20장에 약 7KB (한 장 약 355바이트, 한국어 이름 · 문구 평균 68바이트) | 확인 (2026-11-19 실측) |
| 카드 데이터 크기 (예상) | 300장 · 5개 언어 약 225KB. 공통 + 한 언어 약 130KB | 가정 |
| 카드 그림 한 장 | 약 0.3 ~ 1.5MB (해상도 · 압축에 따라) | 가정 — 실제 그림이 오면 잰다 |
| CCD 무료 전송량 | 월 50GB, 넘으면 1GB 당 $0.08 (올리기도 포함). 저장 용량 · 파일 크기 한도는 공식 문서에 없다 (저장은 무료) | 확인 (2026-11-19, `store-release` 9절 출처) |
| Remote Config 크기 | 설정 하나 최대 5MB · 문자열 값 하나 최대 65,535자 — 카드 데이터는 담지 않는다 (게임 데이터용이 아니라는 것이 Unity 안내) | 확인 (2026-11-19, 공식 API 문서) |
| 받기 — 한 번 기다림 | 10초 (넘으면 실패로 본다) | 제안 (2026-11-19 조사) |
| 받기 — 다시 시도 | 처음 1번 + 다시 2번 = **최대 3번**. 기다림 1초 → 2초, 각각 ±30% 무작위로 흔든다(지터 — 여러 기기가 한꺼번에 다시 몰리지 않게). 서버가 「너무 많음」(429)과 기다릴 시간을 주면 그만큼 기다린다. 타이틀에서 이 모두를 합쳐 **15초**를 넘기면 그만두고 저장본으로 간다 | 제안 (2026-11-19 조사) |
| 버전 다시 확인 간격 (6-5) | 마지막으로 읽은 지 **30초** 안이면 다시 읽지 않는다 | 제안 (2026-11-19 조사) |
| 카드 데이터 파일 크기 상한 | **봇**: 파일 하나가 **1MB** 를 넘으면 올리지 않고 알린다 (예상의 4 ~ 10배). **앱**: 받는 파일이 **2MB** 를 넘으면 받다가 끊고 실패로 본다 | 제안 (2026-11-19 조사) |

## 6. 상태 · 흐름

### 6-1. 앱 시작 (타이틀)

Remote Config 를 읽은 뒤, 네트워크 서버에 접속하기 **전**에 카드 데이터를 맞춘다 — 로비에서 바로 같은 버전의 방을 찾을 수 있게 (7-6). 화면 상태는 `20-title-ui-full` 6절.

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| 설정 읽는 중 | 통과 | **카드 데이터 확인** | Remote Config 의 카드 데이터 버전을 기기 저장본과 비교한다 |
| 카드 데이터 확인 | 원격 카드 끄기 = 참 (7-5) | 연결 중 | 저장본(없으면 빌드 기본본)으로 간다. 받지 않는다 |
| 카드 데이터 확인 | 버전이 같다 | 연결 중 | 저장본을 쓴다. 받지 않는다 |
| 카드 데이터 확인 | 버전이 **다르다** (크든 작든 — 되돌리기도 받는다) | **카드 데이터 받는 중** | 공통 파일 + 지금 언어 파일만 받는다 |
| 카드 데이터 받는 중 | 성공 + 확인값 맞음 (7-5) | 연결 중 | 기기에 저장한다. 다른 언어의 옛 저장본은 지운다 |
| 카드 데이터 받는 중 | 실패 · 확인값 틀림 · 다시 시도를 다 씀 | 연결 중 | 저장본, 없으면 빌드 기본본 (8절) |
| 설정 읽는 중 | Remote Config 읽기 실패 | 연결 중 | 저장본, 없으면 빌드 기본본. 받지 않는다 |

* 로딩 묶음 문구는 그대로 「로그인 중…」 — 사용자에게 단계를 더 나누어 보이지 않는다 (`20-title-ui-full` 7-4). 제안.
* 받은 카드 데이터는 카드 정의 값 위에 카드 번호로 덮어쓴다. 빌드 기본본에 없는 번호가 있으면 그 파일을 쓰지 않는다 — 새 카드는 앱 업데이트로만 낸다 (3절 #9 · 8절).
* 다시 시도 · 기다림 · 크기 상한은 4절.

### 6-2. 설정에서 언어 바꾸기

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| 로비 | 다른 언어를 고름 + 그 언어 파일이 지금 데이터 버전으로 저장돼 있음 | 로비 | 바로 바꾼다 (`25-localization` 6절) |
| 로비 | 다른 언어를 고름 + 저장본 없음 | **언어 받는 중** | 로딩 팝업 「바꾸는 중…」, 화면 입력 막음 |
| 언어 받는 중 | 성공 | 로비 | 저장 → 화면 문구 · 카드 문구를 **한꺼번에** 바꾼다. 반만 바뀐 화면을 보이지 않는다 |
| 언어 받는 중 | 실패 | 로비 | 언어를 바꾸지 않는다. 경고 팝업 「잠시 후 다시 시도해 주세요.」 (`08` 7절 「그 밖의 실패」 문구) |

* 빌드 기본본에는 다섯 언어가 모두 있다. 지금 데이터 버전이 빌드 기본본과 같으면 받지 않고 빌드 기본본으로 바꾼다. 제안.

### 6-3. 게임 시작

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| 룸 「시작 중」 | 전환 덮개가 화면을 다 덮음 (`15-screen` 9-4 ③) | **그림 불러오는 중** | 덱에 든 카드 종류의 그림을 전부 불러온다. 덮개는 머문다 (`15-screen` 9-3 「머묾」) |
| 그림 불러오는 중 | 다 불러옴 | 인게임 | 덮개가 걷힌다 |
| 그림 불러오는 중 | 한 장을 못 불러옴 | 인게임 | 그 카드만 그림 없이(이름 · 문구만) 진행하고 개발 로그를 남긴다. 판을 멈추지 않는다. 제안 |
| 인게임 | 게임 끝 · 방으로 | — | 불러온 그림을 모두 내린다 |

* 같은 카드가 여러 장이어도 그림은 하나다 — 장수가 아니라 **종류 수**만큼 불러온다.

### 6-5. 로비에서 방에 가려 할 때 (앱을 켠 채 패치가 나왔을 때)

랜덤 매칭 · 혼자 하기 · 방 만들기 · 방 참가(코드) · 초대 수락 · 친구 따라 참가를 누르면, 그 요청을 보내기 **전에** 버전을 다시 확인한다. 게임 중 · 방 안에서는 확인하지 않는다 — 그 방의 버전으로 끝까지 간다.

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| 로비 | 방에 가는 버튼을 누름 | **버전 확인 중** | Remote Config 를 다시 읽는다 (마지막으로 읽은 지 30초 안이면 그 값을 쓴다, 4절). 그 요청의 로딩 팝업(찾는 중… 등, `14-lobby-ui` 7절)이 이때부터 뜬다 |
| 버전 확인 중 | `minVersion` > 내 앱 | 업데이트 필요 | 타이틀과 같은 닫을 수 없는 팝업 「업데이트 필요」 + 「스토어로」 (`23-login` 7-6 · `22-popup-ui` 3절) |
| 버전 확인 중 | `maintenance` = 참 | 점검 | 타이틀과 같은 점검 팝업 (`23-login` 7-6) |
| 버전 확인 중 | 카드 데이터 버전이 같다 · 읽기 실패 · `remoteCardsOff` | (요청) | 누른 요청을 그대로 보낸다 |
| 버전 확인 중 | 카드 데이터 버전이 **다르다** | **받기 확인** | 확인 팝업 「새 카드 데이터」 / 「새 카드 데이터가 있어요. 받을까요?」 / 「취소」 「받기」 |
| 받기 확인 | 「받기」 | **받는 중** | 로딩 팝업 「받는 중…」 — 6-1 과 같은 받기 (공통 + 지금 언어) |
| 받는 중 | 성공 | (요청) | 저장하고, 누른 요청을 이어서 보낸다 — 다시 누르지 않아도 된다 |
| 받는 중 | 실패 | 로비 | 경고 팝업 「잠시 후 다시 시도해 주세요.」. 요청은 보내지 않는다 |
| 받기 확인 | 「취소」 | 로비 | 요청을 보내지 않는다 — 옛 버전으로는 새 버전의 방에 갈 수 없다. 다음에 누르면 다시 묻는다 |

* 확인 · 받기 문구는 `22-popup-ui` 3절 「로비」. 제안.

## 7. 상세

### 7-1. 데이터 넷

| 데이터 | 무엇 | 무게 | 어디 |
| --- | --- | --- | --- |
| **카드 정의** | 카드 1종 — 번호 · 이름 · 문구 · 종류 · 대상 · 조건 · 등급 · 효과(종류 + 값) · 연출 시간 · **그림 주소** | 가볍다 (한 종류 몇 KB) | 빌드 기본본 + 원격 파일 (7-2) |
| **카드 그림** | 앞면 그림 | 무겁다 (한 종류 약 1MB) | 빌드 (Addressables 로컬 그룹) |
| **카드 목록** | 게임에 있는 모든 카드 정의의 목록 — 도감용. 덱과 다르다 | 가볍다 | 빌드 기본본 + 원격 파일 |
| **덱** | 어떤 카드를 몇 장 (`05-deck` 8절) | 가볍다 | 빌드 기본본 + 원격 파일 |

* 게임 안의 **카드 한 장**은 데이터가 아니라, 방장이 게임 시작 때 덱에서 장마다 만드는 값이다 (`05-deck` 3절).

### 7-2. 원격 파일

| 파일 | 담는 것 | 받는 때 |
| --- | --- | --- |
| **공통** | 데이터 버전 · 카드 목록 · 덱 구성 · 카드마다 종류 · 대상 · 조건 · 등급 · 효과 값 · 연출 시간 | 데이터 버전이 바뀌었을 때 |
| **언어** (언어마다 하나 — 지금 5개) | 데이터 버전 · 카드마다 이름 · 문구 | 데이터 버전이 바뀌었을 때(지금 언어만) · 언어를 바꿀 때 |

* 언어를 더하는 일 = 언어 파일 하나 더하기 (`25-localization` 3절 #10 · 7-7).
* 언어 파일의 문구는 노션 「🌐 다국어 문구」 DB 의 `card.<카드 ID>.name` · `.text` 행에서 만든다 (`25-localization` 7-3). 번역이 「검수 완료」 가 아닌 칸은 빠진 번역 규칙(`25-localization` 4-2)을 따른다.

### 7-3. 배포 흐름

```
노션 카드 DB · 다국어 DB (기획 편집)
 → 카드 정리 봇 (매일, GitHub Actions) → 카드 데이터 파일 PR
 → 사람이 검토 · 머지                         ← 사람 확인 단계
 → 자동: CCD 개발 버킷에 올림 → 릴리스 → 개발 환경에서 확인
 → CCD 운영 버킷에 올림 → 릴리스 → live 배지를 새 릴리스로
 → Remote Config 카드 데이터 버전을 올림
 → 유저: 다음 앱 실행 때 버전이 다르면 받음
```

| 단계 | 누가 | 구분 |
| --- | --- | --- |
| 봇이 확정 카드만 파일에 넣는다 (미공개 · 제안 카드는 나가지 않는다) | 봇 | 확정 (기존 — 카드 정리 봇) |
| 머지 | 사람 | 확정 |
| 개발 버킷 → 확인 → 운영 버킷 | 사람이 확인, 올리기는 자동 | 확정 (방식) / 제안 (확인 방법) |
| 같은 파일을 Unity 「카드 가져오기」 로 넣어 **빌드 기본본**을 만든다 — 원격과 빌드가 한 파일에서 나온다 | 개발 | 확정 |
| **되돌리기** = live 배지를 옛 릴리스로 옮기고 Remote Config 버전도 되돌린다. 파일을 다시 올리지 않는다 | 사람 | 확정 |
| **새 카드가 든 데이터** = 그 카드가 든 앱 업데이트가 두 스토어에 다 올라간 뒤, `minVersion` 을 올릴 때 **같이** 운영 버킷 · 카드 데이터 버전을 올린다 — 옛 앱이 모르는 카드 번호를 받지 않게 ([`../versioning.md`](../versioning.md) 「올리는 순서」) | 사람 | 확정 (새 카드 = 앱 패치) / 제안 (순서) |

### 7-4. CCD 의 말

| 말 | 뜻 | 우리 쓰임 |
| --- | --- | --- |
| 버킷 | 파일을 담는 폴더 | 「카드 데이터 · 개발」 · 「카드 데이터 · 운영」 |
| 엔트리 | 버킷 안의 파일 하나 | 공통 파일 · 언어 파일 |
| 릴리스 | 그 순간 버킷 내용의 스냅숏 (바뀌지 않음) | 데이터 버전 하나 = 릴리스 하나 |
| 배지 | 릴리스에 붙이는 이름표. 앱은 배지 주소로 받는다 | `live` = 지금 유저에게 나가는 릴리스 |

### 7-5. Remote Config 키 (`23-login` 7-6 에 더함)

| 키 | 형 | 뜻 | 구분 |
| --- | --- | --- | --- |
| `cardDataVersion` | 정수 | 지금 쓸 카드 데이터 버전. 기기 저장본과 **다르면** 받는다 | 확정 (있음) / 제안 (이름 · 형) |
| `cardDataHash` | 문자열 | 그 버전 공통 파일의 확인값. 받은 파일 · 저장본이 맞지 않으면 버린다 — 깨진 파일 · 기기에서 고친 파일을 쓰지 않게 | 제안 |
| `remoteCardsOff` | 불리언 | 참이면 받지 않고 저장본 · 빌드 기본본만 쓴다 — 문제가 생겼을 때 바로 멈추는 스위치 | 확정 (있음, 7-8) / 제안 (이름) |

### 7-6. 버전 · 매칭

| 항목 | 규칙 | 구분 |
| --- | --- | --- |
| 방의 버전 | 방장이 방을 만들 때 **방 속성**에 자기 카드 데이터 버전을 쓴다. 로비에서 보이는 속성으로 둔다 (랜덤 매칭이 거르려면) | 확정 (2026-11-19) / 제안 (로비 속성) |
| 랜덤 매칭 (찾기) | 내 버전과 **같은 버전의 방만** 찾는다. 없으면 내 버전으로 새 방을 만든다 (`08-room` 4절) | 확정 (2026-11-19) |
| 방 참가 · 초대 수락 · 친구 따라 참가 | 6-5 로 내 버전을 최신으로 맞춘 뒤 참가한다. 들어간 방의 버전이 내 것과 다르면(그 방이 옛 버전) **바로 나오고** 경고 팝업 「방 참가 실패」 / 「방의 카드 버전이 달라요. 방장이 로비에 나갔다 오면 같이 할 수 있어요.」 | 확정 (같은 버전만, 2026-11-19) / 제안 (문구) |
| 방장 확인 | 방장도 들어온 사람의 버전(Player 속성)을 보고 다르면 내보낸다 — 들어온 쪽이 나오지 않아도 막히게. 게임 시작 때 한 번 더 본다 (`09-network` 13절 12-1) | 제안 |
| 앱 버전 | 네트워크 서버 접속 버전은 지금처럼 **앱 버전만** 쓴다 — 카드 데이터 버전은 방 속성이 가른다 ([`../versioning.md`](../versioning.md)) | 확정 (2026-11-19) |
| 판 도중 · 방 안 | 데이터를 바꾸지 않는다. 그 방의 버전으로 끝까지 간다. 판이 끝나 방으로 돌아와도 그 방은 그 버전이다 | 확정 (2026-11-19) |
| 앱을 켠 채 패치가 나옴 | 로비에서 방에 가려 할 때 확인하고 받을지 묻는다 (6-5) | 확정 (2026-11-19) |
| 앱 버전과의 관계 | 카드 데이터만 바뀐 패치는 앱 버전을 올리지 않는다. 패치 노트 「버전」 칸에는 카드 데이터 버전을 적는다 ([`../versioning.md`](../versioning.md)) | 확정 (2026-11-19) |

### 7-7. 언어 파일

| 때 | 받는 것 |
| --- | --- |
| 처음 시작 | 공통 + 처음 화면에서 고른 언어 (`25-localization` 3절 #2 — 기본 선택은 기기 지역 · 언어) |
| 평소 실행 | 없음 (버전이 같으면) |
| 패치 (버전이 바뀜) | 공통 + **지금 언어만**. 다른 언어의 옛 저장본은 지운다 |
| 설정에서 언어를 바꿈 | 그 언어 (6-2). 지금 버전으로 저장돼 있으면 받지 않는다 |

### 7-8. 과금 안전장치

UGS 예산 알림은 알리기만 하고 서비스를 멈추지 않는다 (`store-release` 3-1). 그래서 우리 쪽에서 막는다.

| # | 장치 | 막는 것 | 구분 |
| --- | --- | --- | --- |
| 1 | 버전이 바뀔 때만 받는다. 실패하면 최대 3번(1초 → 2초, ±30%) · 타이틀 전체 15초 · 서버가 주는 기다릴 시간을 따른다 (4절). 로비 확인은 30초에 한 번 | 실패한 앱이 계속 다시 받는 것 · 패치 날 한꺼번에 몰리는 것 | 제안 (2026-11-19 조사) |
| 2 | 봇: 파일 하나 1MB 를 넘으면 올리지 않고 알린다. 앱: 2MB 를 넘는 파일은 받다가 끊는다 (4절) | 실수로 큰 파일을 올리거나 받는 것 | 제안 (2026-11-19 조사) |
| 3 | `remoteCardsOff` 스위치 (7-5) | 문제가 생겼을 때 즉시 멈춤 | 제안 |
| 4 | Cloud Code 호출은 한 판에 한 번 — 판 결과 보고 하나로 (`23-login` 7-1 · `24` 2절, 기존) | 호출 수 과금 | 확정 (기존) |
| 5 | Unity 대시보드 예산 알림 **월 $5 · $20 · $50** 세 단계 + 무료 한도 알림(75% · 100%) 켜기 + 월 1회 사용량 확인. 받는 사람 = **PM** (조직 Owner 만 설정할 수 있다). 팀 메신저(Slack 등)로도 받을 수 있으면 개발 채널에 같이 | 모르는 사이의 과금 — $5 는 「처음 돈이 나가기 시작함」 신호 | 제안 (2026-11-19) |
| 6 | UGS 결제 카드는 **월 한도 10만 원**으로 정한 카드 (체크 · 가상 카드) | 최악의 경우 피해 상한 | 제안 (2026-11-19) |

### 7-9. 노션을 게임이 직접 읽지 않는 이유

| 이유 | 내용 |
| --- | --- |
| 요청 제한 | 노션 API 는 통합 하나당 평균 초당 3회 — 게임 전체가 나눠 쓴다. 동접 100명이 패치 날 1분 안에 켜면 초당 5회로 넘친다 |
| 토큰 | 앱 안에 노션 토큰이 들어가야 한다. 꺼내면 미공개 카드 · 회의 내용을 읽고, 한 사람이 요청을 퍼부으면 모두가 못 받는다 |
| 속도 | 요청 한 번이 0.3 ~ 1초. 한 번에 100행까지라 여러 번 불러야 한다 |
