# 26. 카드 데이터 — 불러오기 · 원격 패치

**최종 수정일**: 2026-11-20 (개선안 — 7-11 「2026-11-19 안에서 바꾼 것」). 이전: 2026-11-19

**범위**: 카드 데이터를 **어디에 두고 언제 불러오는가**. 카드마다의 효과는 [`11-card-list.md`](11-card-list.md), 덱 · 손패 규칙은 [`05-deck.md`](05-deck.md), 문구 번역 규칙은 [`25-localization.md`](25-localization.md), 외부 서비스 비용은 [`../store-release.md`](../store-release.md) 3절.

> 한 줄 요약: **카드의 값(이름 · 문구 · 수치 · 장수)은 파일 하나(`cards.json`)가 원본이다.** 빌드에 든 것도, 서버에서 받는 것도 그 파일이다. 밸런스 · 문구 패치는 앱 업데이트 없이 서버(UGS CCD)에 그 파일을 올리고 Remote Config 키 **하나**를 바꾼다. 같은 파일을 쓰는 사람끼리만 같이 논다 — 같은지는 파일의 **확인값**으로 가른다.

## 1. 목적

밸런스 · 문구를 스토어 심사 없이 고칠 수 있게 하고, 잘못 올린 패치가 게임을 막지 않게 한다. 카드가 늘어도 모바일 메모리 · 로딩이 버티게 한다.

| 카드 데이터 크기 (예상) | 300종 약 100KB | 가정 |

| CCD 무료 전송량 | 월 50GB, 넘으면 1GB 당 $0.08 | 확인 (2026-11-19, `store-release` 9절 출처) |
| 받기 — 한 번 기다림 | 10초 | 확정 (추천안) |
| 받기 — 다시 시도 | 처음 1번 + 다시 2번 = **최대 3번**. 기다림 1초 → 2초, 각각 ±30% 무작위. 서버가 「너무 많음」(429)과 기다릴 시간을 주면 그만큼 기다린다. 모두 합쳐 **15초**를 넘기면 그만둔다 | 확정 (추천안) |
| 받기 — 다시 시도하지 않는 실패 | 없는 파일 · 거절(4xx, 408 · 429 는 빼고) · 2MB 를 넘는 파일 · 확인값이 다른 파일 · 앱이 못 쓰는 파일. 그 확인값은 **앱을 끌 때까지** 다시 받지 않는다 | 확정 (개선안) |
| 서버 값 다시 확인 간격 (6-5) | 마지막으로 확인한 지 **30초** 안이면 다시 읽지 않는다 (읽기 실패도 센다). 그 사이 늦게 도착한 새 값이 있으면 그 값으로는 맞춘다 | 확정 (추천안) |
| 카드 데이터 파일 크기 상한 | **올릴 때**(`publish.py`): **1MB** 를 넘으면 멈춘다. **앱**: 받는 파일이 **2MB** 를 넘으면 받다가 끊는다 | 확정 (추천안) |
| 확인값 | SHA-256, 소문자 16진수 64자 (7-2) | 확정 (개선안) |

## 6. 상태 · 흐름

### 6-1. 앱 시작 (타이틀)

Remote Config 를 읽은 뒤, 네트워크 서버에 접속하기 **전**에 카드 데이터를 맞춘다 — 로비에서 바로 같은 데이터의 방을 찾을 수 있게. 화면 상태는 `20-title-ui-full` 6절.

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| 설정 읽는 중 | 통과 · 읽기 실패(마지막 값) | **카드 데이터 확인** | `cardData` 의 확인값을 본다 (7-5) |
| 카드 데이터 확인 | `cardData` 가 비었다 · 모양이 틀리다 | 연결 중 | **빌드 기본본** — 원격을 쓰지 않는다 |
| 카드 데이터 확인 | 확인값 = 빌드 기본본의 확인값 | 연결 중 | 빌드 기본본. 받지 않는다 |
| 카드 데이터 확인 | 확인값 = 기기 저장본 (7-10) | 연결 중 | 저장본을 얹는다. 받지 않는다 |
| 카드 데이터 확인 | 그 밖 | **받는 중** | `cardData` 의 주소에서 받는다 (4절) |
| 받는 중 | 받음 + 확인값 맞음 + 앱이 쓸 수 있음 | 연결 중 | 얹고 기기에 저장한다 |
| 받는 중 | 그 밖 | 연결 중 | 8절 — 쓰던 데이터 → 마지막 저장본 → 빌드 기본본 |

* 로딩 묶음 문구는 그대로 「로그인 중…」 — 단계를 더 나누어 보이지 않는다 (`20-title-ui-full` 7-4). 확정 (추천안).
* **얹기** = 빌드의 카드 정의를 복사해 파일의 값을 덮어쓴다. 에셋(빌드 기본본)은 바뀌지 않는다. 한 장이라도 못 얹으면 **하나도 얹지 않는다** — 반만 바뀐 덱을 쓰지 않는다.

### 6-2. 설정에서 언어 바꾸기

다국어(12L)를 만들 때 한다 — 7-7.

### 6-3. 게임 화면

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| 게임 화면이 열림 | — | 인게임 | 덱에 든 카드 종류(장수 1 이상)의 그림을 전부 불러와 화면이 쥐고 있는다 |
| 인게임 | 그림이 없는 카드 | 인게임 | 그 카드만 그림 없이(이름 · 문구만) 보인다. 판을 멈추지 않는다 |
| 인게임 | 게임 화면을 떠남 | — | 그림이 내려간다 |

* 같은 카드가 여러 장이어도 그림은 하나다 — **종류 수**만큼 불러온다.
* 그림이 많아져 화면 여는 시간이 눈에 띄면, 게임 시작 전환(`15-screen` 9절)이 화면을 덮은 동안 불러오게 옮긴다. 지금(15종)은 그럴 필요가 없다. 확정 (개선안).

### 6-5. 로비에서 방에 가려 할 때 (앱을 켠 채 패치가 나왔을 때)

랜덤 매칭 · 혼자 하기 · 방 만들기 · 방 참가(코드) · 초대 수락 · 친구 따라 참가를 누르면, 그 요청을 보내기 **전에** 서버 값을 다시 확인한다. 게임 중 · 방 안에서는 확인하지 않는다 — 그 방의 데이터로 끝까지 간다.

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| 로비 | 방에 가는 버튼을 누름 | **확인 중** | 그 요청의 로딩 팝업(찾는 중… 등, `14-lobby-ui` 7절)이 이때부터 뜬다. Remote Config 를 다시 읽는다 (마지막으로 확인한 지 30초 안이면 읽지 않는다 — 4절) |
| 확인 중 | `minVersion` > 내 앱 | 타이틀 | 경고 팝업 「업데이트 필요」 / 「새 버전으로 업데이트해 주세요.」 → 「확인」 을 누르면 타이틀로 — 타이틀이 닫을 수 없는 업데이트 팝업을 띄운다 (`23-login` 7-6) |
| 확인 중 | `maintenance` = 참 | 타이틀 | 경고 팝업 「점검 중」 / 점검 안내 문구 → 「확인」 → 타이틀의 점검 팝업 |
| 확인 중 | 카드 데이터가 같다 · 읽기 실패 · `cardData` 가 비었다 | (요청) | 누른 요청을 그대로 보낸다 |
| 확인 중 | 카드 데이터가 **다르다** | **받는 중** | **묻지 않고** 받는다. 로딩 팝업 글을 「받는 중…」 으로 바꾼다. 6-1 과 같은 받기 |
| 받는 중 | 성공 | (요청) | 얹고 저장한 뒤, 누른 요청을 이어서 보낸다 (로딩 팝업 글은 그 요청의 글로) |
| 받는 중 | 실패 | (요청) | **지금 가진 데이터로 요청을 그대로 보낸다.** 랜덤 매칭 · 방 만들기 · 혼자 하기는 그 데이터끼리 논다. 코드 · 초대로 간 방이 새 데이터면 7-6 의 「내 쪽이 옛 데이터」 안내가 뜬다 |

* 받기 실패가 방에 가는 것을 막지 않는 이유: 파일을 잘못 올렸거나 CCD 가 죽은 날 **모든 사람이 로비에 갇히지 않게**. 확정 (개선안).

## 7. 상세

### 7-1. 데이터 셋

| 데이터 | 무엇 | 무게 | 어디 |
| --- | --- | --- | --- |
| **카드 정의** | 카드 1종 — 번호 · 이름 · 문구 · 종류 · 대상 · 조건 · 등급 · 효과(종류 + 값) · 연출 시간 | 가볍다 | 빌드 기본본(에셋) + 원격 파일 |
| **카드 그림** | 앞면 그림 | 무겁다 (한 종류 약 1MB) | 빌드 — `Assets/Resources/CardArt/<카드 번호>.png` |
| **덱** | 어떤 카드를 몇 장 (`05-deck` 8절) | 가볍다 | 빌드 기본본(`Deck_Main`) + 원격 파일 |

* 게임 안의 **카드 한 장**은 데이터가 아니라, 방장이 게임 시작 때 덱에서 장마다 만드는 값이다 (`05-deck` 3절).
* 카드 목록(도감용)은 따로 두지 않는다 — `cards.json` 의 모든 줄이 목록이고, 장수 0 인 줄이 「덱에는 없지만 게임에 있는 카드」 다.
* 연출 시간은 원격으로 바꾸지 않는다 (에셋에만 있다).

### 7-2. 카드 데이터 파일 (`cards.json`)

저장소 `MuffinProject/Assets/Cards/Main/cards.json`. 서버에 올리는 것도 이 파일이다.

```json
{
  "cards": [
    {
      "id": 1005, "name": "드롭킥", "type": "Action", "target": "OneOther", "targetCondition": "None", "grade": "Rare", "count": 3,
      "text": "{0} 피해를 준다. 못 쓰러뜨리면 나도 {1} 피해를 받는다",
      "effects": [ { "type": "DamageEffect", "args": "subject=Target, amount=49" }, { "type": "RecoilDamageEffect", "args": "amount=49" } ]
    }
  ]
}
```

| 칸 | 뜻 | 원격으로 바꿀 수 있나 |
| --- | --- | --- |
| `id` | 카드 번호. 빌드에 없는 번호가 있으면 파일을 쓰지 않는다 | ✗ (새 카드 = 앱 업데이트) |
| `name` · `text` | 이름 · 문구 | ○ |
| `type` | 카드 종류. 빌드와 달라지면 파일을 쓰지 않는다 | ✗ |
| `target` · `targetCondition` · `grade` | 대상 · 대상 후보 조건 · 등급 | ○ |
| `count` | 덱에 넣는 장수. 0 이면 덱에서 빠진다. 파일에 없는 카드도 0 장이다 | ○ |
| `effects[].type` | 효과 종류 — 순서 · 개수까지 빌드와 같아야 한다 | ✗ |
| `effects[].args` | 효과 값 — `필드=값, 필드=값` | ○ (값만. 음수는 받지 않는다) |

**값 자리** — 문구의 `{n}` 은 **그 카드의 효과 `args` 에 적힌 숫자 값을, 적힌 순서대로 0번부터 센 n번째**다. 위 예에서 `{0}` = 49(피해), `{1}` = 49(반동). 숫자가 아닌 값(`subject=Target`)은 세지 않는다. 문구에 숫자를 그대로 써도 된다(값 자리 없이) — 그때는 수치를 바꿔도 문구가 따라 바뀌지 않는다. 값 자리 번호가 효과 값 개수를 넘거나, 번호를 읽을 수 없으면(전각 숫자 `{１}` 처럼 ASCII 숫자가 아니다 · 너무 크다) 파일을 쓰지 않는다 — 올리기 전 검사(`publish.py --check`)도 같은 것을 잡는다.

**확인값** — 파일 내용의 SHA-256(소문자 16진수). 줄바꿈(CRLF · LF)과 BOM 은 빼고 센다 — 같은 파일이 저장소 줄바꿈 정책 때문에 다른 값이 되지 않게. 한 글자라도 다르면 다른 데이터다. Unity(`CardSheet.HashOf`) · 올리기 도구(`publish.py`)가 같은 값을 낸다.

**빌드 기본본** — Unity 메뉴 「Chapchu/카드 가져오기」 가 이 파일을 카드 에셋 · `Deck_Main` 에 얹고, `Deck_Main` 에 파일의 확인값을 적는다. 값이 바뀐 카드는 「전 → 후」 를 콘솔에 찍는다. 효과는 **에셋에 효과가 하나도 없을 때만** 파일의 종류대로 새로 만든다(새 카드) — 이미 있으면 종류 · 순서가 파일과 같아야 하고 값만 덮어쓴다.

### 7-3. 배포 흐름

```
노션 카드 DB (기획 편집)
 → 카드 정리 봇 (매일, GitHub Actions) → cards.json PR        ← 수치만 바뀐 문구는 효과 값(args)을 고친다
 → 사람이 검토 · Unity 에서 「카드 가져오기」 · 머지           ← 빌드 기본본이 같이 바뀐다
 → publish.py --check → --out 으로 올릴 파일 · 확인값
 → CCD 개발 버킷에 올림 → 릴리스 → 개발 환경 Remote Config cardData 를 그 릴리스로 → 개발 빌드로 확인
 → CCD 운영 버킷에 올림 → 릴리스 → 운영 환경 Remote Config cardData 를 그 릴리스로
 → 유저: 다음 앱 실행 · 다음 「방에 가기」 때 받음
```

| 단계 | 누가 | 구분 |
| --- | --- | --- |
| 봇이 확정 카드만 파일에 넣는다 | 봇 | 확정 (기존) |
| 봇: 노션 문구가 값 자리를 채운 글과 **숫자만** 다르면 효과 값을 고친다. 글이 다르면 노션 글을 그대로 넣고(값 자리가 풀린다) PR 에 알린다 — 사람이 값 자리를 다시 넣는다 | 봇 | 확정 (개선안) |
| 머지 전에 「카드 가져오기」 를 돌려 에셋 · `Deck_Main` 을 같이 커밋한다. `publish.py --check` 가 `Deck_Main` 의 확인값이 파일과 같은지 본다 | 사람 | 확정 (개선안) |
| 올리기 = `scripts/card-data/publish.py` 로 파일 · 확인값 · Remote Config 값을 만들고, CCD · Remote Config 는 대시보드에서 손으로 (`scripts/card-data/README.md`) | 사람 | 확정 (개선안) — 자동 올리기는 9절 #3 |
| **되돌리기** = Remote Config `cardData` 를 옛 값으로 되돌린다. 그 하나로 끝난다 — 옛 릴리스는 CCD 에 그대로 있다. 원격을 아예 끄려면 `cardData` 를 비운다 | 사람 | 확정 (개선안) |
| **새 카드가 든 데이터** = 그 카드가 든 앱 업데이트가 두 스토어에 다 올라간 뒤, `minVersion` 을 올릴 때 **같이** `cardData` 를 바꾼다 ([`../versioning.md`](../versioning.md) 「올리는 순서」). 순서를 어겨도 옛 앱은 그 파일을 버리고 쓰던 데이터로 논다(8절) — 새 데이터의 방에만 못 들어간다 | 사람 | 확정 (추천안 · 순서) |

### 7-4. CCD 의 말

| 말 | 뜻 | 우리 쓰임 |
| --- | --- | --- |
| 버킷 | 파일을 담는 폴더 | 「카드 데이터 · 개발」 · 「카드 데이터 · 운영」 |
| 엔트리 | 버킷 안의 파일 하나 | `cards.json` |
| 릴리스 | 그 순간 버킷 내용의 스냅숏 (**바뀌지 않음**) | 카드 데이터 하나 = 릴리스 하나 |
| 배지 | 릴리스에 붙이는 이름표 | **쓰지 않는다** — 배지 주소는 내용이 바뀌는 주소라, 배지를 옮긴 직후 옛 파일이 오면 확인값이 틀린다 (7-11 #3) |

* 앱이 받는 주소 = **릴리스 주소** — 내용이 바뀌지 않는 주소다:
  `https://<프로젝트 ID>.client-api.unity3dusercontent.com/client_api/v1/buckets/<버킷 ID>/releases/<릴리스 ID>/entry_by_path/content/?path=cards.json`
  확인 (2026-11-20, Unity CCD FAQ). 인증 없이 받는다. **실제 CCD 로 받아 보지는 않았다** — 버킷을 만들고 처음 올릴 때 이 주소로 받아지는지 확인한다 (9절 #2).
* 주소는 `https` 만 받는다. 개발 빌드 · 에디터만 `http`(로컬 서버 시험)를 받는다.

### 7-5. Remote Config 키 (`23-login` 7-6 에 더함)

| 키 | 형 | 값 | 구분 |
| --- | --- | --- | --- |
| `cardData` | JSON | `{ "version": 12, "hash": "<확인값 64자>", "url": "<릴리스 주소>" }` | 확정 (개선안) |

| 칸 | 뜻 |
| --- | --- |
| `hash` | 지금 쓸 카드 데이터의 확인값. 앱은 이 값으로 같은지 본다 — 빌드 기본본 · 저장본 · 받은 파일 모두 |
| `url` | 그 파일을 받는 주소 (7-4) |
| `version` | 사람이 부르는 번호 — 패치 노트의 「카드 12」 ([`../versioning.md`](../versioning.md)). 앱은 로그에만 쓴다 |

* **키가 없다 · 비었다(`{}`) · `hash` 가 64자 16진수가 아니다 · `url` 이 비었다 = 원격 끔.** 앱은 빌드 기본본으로 논다. 문제가 생기면 이 키를 비우는 것이 멈춤 스위치다.
* 확인값과 주소가 **한 값**이라 따로 바뀌는 순간이 없다. 대시보드에서 `publish.py --url` 이 찍은 줄을 그대로 붙인다.

### 7-6. 같은 데이터끼리

| 항목 | 규칙 | 구분 |
| --- | --- | --- |
| 방의 데이터 | 방을 만들 때 **방 속성 `cd`** 에 자기 카드 데이터의 확인값을 쓴다. 로비에서 보이는 속성이다. 방을 만든 뒤에는 바뀌지 않는다 (방장이 바뀌어도) | 확정 (2026-11-19) / 확정 (개선안 · 확인값) |
| 랜덤 매칭 (찾기) | 내 확인값과 **같은 방만** 찾는다. 없으면 내 데이터로 새 방을 만든다 (`08-room` 4절) | 확정 (2026-11-19) |
| 방 참가 · 초대 수락 · 친구 따라 참가 | 6-5 로 내 데이터를 맞춘 뒤 참가한다. 들어간 방의 확인값이 내 것과 다르면 **바로 나오고** 경고 팝업 「방 참가 실패」 — 아래 두 글 중 하나 | 확정 (2026-11-19) / 확정 (개선안 · 글 둘) |
| ↳ 방이 옛 데이터 (내 것이 서버 값과 같다) | 「방의 카드 버전이 달라요. 방장이 로비에 나갔다 오면 같이 할 수 있어요.」 | 확정 (추천안) |
| ↳ 내 쪽이 옛 데이터 (받지 못했다 · 앱이 못 쓰는 데이터) | 「새 카드 데이터를 받지 못해 이 방에 들어갈 수 없어요. 잠시 후 다시 시도해 주세요.」 | 확정 (개선안) |
| 방장 확인 | **하지 않는다.** 들어온 사람이 스스로 나온다. 고친 클라이언트는 「같다」 고 속일 수 있어 방장이 검사해도 막지 못하고, 그런 클라이언트가 얻는 것은 자기 화면의 글이 틀리는 것뿐이다 — 판정은 방장 값으로 한다 | 확정 (개선안) |
| 방장 이주 | 새 방장도 같은 방에 있었으므로 같은 데이터다. 덱의 카드 순서(파일 순서)가 같아 카드마다의 번호가 이어진다 (`09-network` 방장 이주) | 확정 (개선안) |
| 앱 버전 | 네트워크 서버 접속 버전은 지금처럼 **앱 버전만** 쓴다 ([`../versioning.md`](../versioning.md)) | 확정 (2026-11-19) |
| 판 도중 · 방 안 | 데이터를 바꾸지 않는다. 판이 끝나 방으로 돌아와도 그 방은 그 데이터다 | 확정 (2026-11-19) |

### 7-7. 언어 파일 (12L 때 만든다)

지금은 한국어 `cards.json` 하나다. 다국어(12L)를 만들 때 — 이름 · 문구를 언어마다 파일로 나누고(`cardData` 에 언어별 `hash` · `url`), 처음 시작할 때 고른 언어만 받고, 설정에서 언어를 바꾸면 그때 그 언어를 받는다 (2026-11-19 확정 · 방향, `25-localization` 3절 #2 · #10). 값 자리(7-2)가 있어 수치 패치에는 번역이 필요 없다. 같은 방인지는 **공통 파일(효과 값 · 장수)의 확인값**으로만 가른다 — 언어가 달라도 같이 논다.

| 마지막 저장본 | 마지막으로 받은 확인값 · 그때의 앱 버전을 기기 설정에 적어 둔다 (8절 「물러나기」 가 쓴다) | 확정 (개선안) |

### 7-11. 2026-11-19 안에서 바꾼 것

| # | 2026-11-19 안 | 허점 | 지금 |
| --- | --- | --- | --- |
| 1 | 효과 값은 에셋에, `cards.json` 은 처음 만들 때만 | 원본이 둘 — 봇은 문구의 「20 피해」 를 고치는데 효과는 에셋에 20 인 채로 남는다. 원격 파일로 수치를 바꿀 길도 없다 | `cards.json` 이 값의 원본. 가져오기 · 원격이 같은 코드로 얹는다 (3절 #10) |
| 2 | 정수 버전 + 확인값 따로 | 번호 올리기를 잊으면 아무도 안 받는다. 같은 번호에 다른 내용이 생긴다. 개발 · 운영의 번호가 엇갈린다 | **확인값이 곧 데이터의 이름**. 번호는 사람이 부르는 이름표일 뿐 (7-5) |
| 3 | 키 셋 + 「live 배지를 옮기고 → 버전을 올림」 | 두 걸음 사이에 앱이 켜지면 새 확인값으로 옛 파일을 받아 실패한다. 배지 주소는 캐시가 남는다 | 키 하나(`cardData`)에 확인값 + **바뀌지 않는 릴리스 주소**. 바꾸는 것도 되돌리는 것도 한 번 (7-5) |

| 6 | 방장도 들어온 사람의 버전을 검사 | 고친 클라이언트는 속일 수 있어 막지 못한다. 코드만 는다 | 들어온 사람이 스스로 나온다 (7-6) |
| 7 | 그림 = Addressables, 「나중에 서버로 옮길 때 그룹만 바꾸게」 | 그림은 빌드 안에 있고 새 카드는 앱 업데이트다 — 지금 얻는 것이 없다. 패키지 · 빌드 단계 · 비동기 불러오기 · CI 가 는다 | 카드 번호로 찾는 `Resources` 폴더. 정의가 그림을 쥐지 않으니 「필요할 때만」 은 그대로 지켜진다. 그림을 서버로 옮길 일이 생기면 그때 `CardData.LoadArt` 한 곳을 바꾼다 (3절 #3 · #4) |

| 11 | 로비에서 업데이트 · 점검이면 「타이틀과 같은 팝업」 | 로비에는 그 팝업이 없다 | 경고 팝업 → 「확인」 → 타이틀 (6-5) |

## 8. 예외

**물러나기** — 서버가 정한 데이터로 맞추지 못했을 때의 순서:

| 순서 | 무엇 | 조건 |
| --- | --- | --- |
| 1 | **쓰던 원격 데이터 그대로** | 이번 실행에 이미 얹은 것이 있다 (로비에서 새 패치를 못 받은 때) |
| 2 | **마지막 저장본** | 마지막으로 받았을 때와 **앱 버전이 같다** — 앱을 업데이트한 뒤에는 옛 저장본으로 물러나지 않는다(새 빌드에 든 것이 그보다 새 데이터다) |
| 3 | **빌드 기본본** | 그 밖 |

| 상황 | 처리 | 구분 |
| --- | --- | --- |
| 처음 시작인데 오프라인 · 받기 실패 | 빌드 기본본 | 확정 (2026-11-19) |
| Remote Config 를 못 읽음 | 지난 실행에 받아 둔 설정 값으로 6-1 을 한다. 그것도 없으면 빌드 기본본 | 확정 (개선안) |
| 받은 파일의 확인값이 다르다 | 버린다 → 물러나기. 앱을 끌 때까지 그 확인값을 다시 받지 않는다 | 확정 (개선안) |
| 파일이 JSON 이 아니다 · 카드가 없다 · 같은 번호가 두 번 · 장수가 음수 · 덱이 0장 | 위와 같다 | 확정 (개선안) |
| 이 앱이 모르는 카드 번호 · 카드 종류가 다르다 · 효과의 종류 · 개수 · 순서가 다르다 · 효과에 없는 값 이름 · 음수 · 모르는 대상 · 조건 · 등급(이름이 정확히 맞아야 한다 — 숫자 · 쉼표 목록은 받지 않는다) · 값 자리가 값보다 많다 · 값 자리 번호를 읽을 수 없다(ASCII 숫자가 아니다) | 위와 같다 — **한 장이라도 걸리면 파일을 통째로** 쓰지 않는다. 개발 로그에 어느 카드가 왜인지 남긴다 | 확정 (개선안) |
| 저장본이 깨졌다 | 지우고 받는다 (7-10) | 확정 (개선안) |
| 저장에 실패 (용량 · 권한) | 이번 실행은 얹은 값으로 논다. 다음 실행에 다시 받는다 | 확정 (개선안) |
