# 26. 카드 데이터 — 불러오기 · 빌드 패치

**최종 수정일**: 2026-11-20 (원격 패치(UGS CCD · Remote Config 카드 키 · 카드 데이터 버전 · 방 속성 버전) 폐기 — 카드도 빌드로 패치, PM). 이전: 2026-11-19
**분류**: MVP (출시 `1.0` 에 포함)
**출처**: 2026-11-19 PM 결정 (플랜 세션) — 데이터 넷 · 능력은 정의와 함께 · 그림만 따로 불러오기 · 도감 / 게임 화면 불러오는 때. 같은 날의 「확정 (추천안)」 은 AI 추천을 그대로 확정한 값이라 테스트 뒤 바뀔 수 있다. **2026-11-20 PM — UGS 를 통한 카드 버전 관리를 하지 않는다. 카드도 빌드에 패치한다: 노션 카드 DB 수정 → 봇이 `develop` 에 PR → 사람이 머지.** 이 결정으로 원격 파일 · 카드 데이터 버전 · 같은 버전끼리 매칭 · 받기 안전장치 · 언어 파일 받기를 모두 지웠다.
**범위**: 카드 데이터를 **어디에 두고 언제 불러오는가**, 노션에서 빌드까지 가는 길. 카드마다의 효과는 [`11-card-list.md`](11-card-list.md), 덱 · 손패 규칙은 [`05-deck.md`](05-deck.md), 문구 번역 규칙은 [`25-localization.md`](25-localization.md), 버전 번호는 [`../versioning.md`](../versioning.md).

> 한 줄 요약: **카드 정의(이름 · 문구 · 수치 · 능력)는 가볍게 한 번에, 무거운 그림만 필요할 때 불러온다.** 카드 데이터는 전부 빌드 안에 있고, 카드를 고치는 것은 앱 업데이트다. 같은 앱 버전 = 같은 카드다.

---

## 1. 목적

카드가 수백 장이 되어도 모바일 메모리 · 로딩이 버티게 하고, 노션에서 고친 카드가 사람 확인 한 번으로 빌드에 들어가게 한다.

## 3. 핵심 규칙

| # | 규칙 | 구분 |
| --- | --- | --- |
| 1 | 카드 데이터는 넷이다 — **카드 정의** · **카드 그림** · **카드 목록** · **덱** (7-1) | 확정 (2026-11-19) |
| 2 | 카드 능력(효과)은 카드 정의 안에 같이 둔다. **따로 불러오지 않는다** — 효과는 종류 + 값 몇 개라 아낄 메모리가 거의 없다 | 확정 (2026-11-19) |
| 3 | 카드 정의는 그림을 직접 갖지 않고 **그림 주소만** 갖는다. 그림은 필요할 때 불러오고 다 쓰면 내린다 (Unity Addressables) | 확정 (2026-11-19) |
| 4 | 카드 그림은 **빌드 안**에 둔다 (Addressables 로컬 그룹) | 확정 (2026-11-19) |
| 5 | 카드 그림을 큰 아틀라스 하나로 묶지 않는다 — 한 장만 써도 아틀라스 전체가 올라온다 | 확정 (추천안) |
| 6 | **도감** — 카드 목록의 정의는 전부 불러온다. 그림은 **화면에 보이는 칸만** 불러오고, 도감을 닫으면 모두 내린다 (6-4) | 확정 (2026-11-19) |
| 7 | **게임 화면** — 게임 시작 전환 동안 **덱에 든 카드 종류의 그림을 전부** 불러온다. 다 불러온 뒤 전환을 끝낸다. 게임이 끝나면 내린다 (6-3). 뽑을 때마다 불러오지 않는다 — 남이 낸 카드 · 버림 더미 · 기록 · 빼앗은 카드도 아무 때나 보이기 때문이다 | 확정 (2026-11-19) |
| 8 | 게임 중에는 카드 번호만 오가고(`09-network` 7절), 각자 자기 기기에서 정의 · 그림을 찾는다. 진행 중에는 불러오기가 없다 | 확정 (2026-11-19) |
| 9 | **카드 패치 = 빌드 패치.** 이름 · 문구 · 수치 · 덱 구성(장수) · 새 카드 모두 앱 업데이트로 낸다. 서버에서 카드 데이터를 받지 않는다 — UGS(CCD · Remote Config)로 카드 버전을 관리하지 않는다 | 확정 (2026-11-20) |
| 10 | **노션은 편집하는 곳이다.** 게임은 노션을 읽지 않는다 — 봇이 저장소의 `cards.json` 을 고치는 PR 을 열고, 머지된 파일만 빌드에 들어간다 (7-3 · 7-9) | 확정 (2026-11-20) |
| 11 | **같은 앱 버전끼리만** 같은 방 — 카드 데이터가 빌드에 들어 있으므로 앱 버전이 같으면 카드도 같다. 카드 데이터 버전 · 방 속성 버전은 따로 두지 않는다 (7-6) | 확정 (2026-11-20) |
| 12 | 카드 이름 · 카드 문구의 다국어도 빌드에 둔다 — 다섯 언어가 모두 들어 있고, 언어를 바꿀 때 받지 않는다 (`25-localization` 7-3) | 확정 (2026-11-20) |
| 13 | 카드 문구에 수치를 박지 않고 **값 자리**(`{0}`)로 쓰고, 효과 값으로 채운다 — 수치를 바꿀 때 다섯 언어 문구를 다 고치지 않게 (`25-localization` 7-4 #3 을 카드 문구에도) | 확정 (추천안) |
| 14 | `cards.json` 이 바뀌면 Unity 가 카드 에셋에 **자동으로** 넣는다. 빌드할 때도 한 번 더 넣는다 — 머지한 뒤 손으로 돌리는 단계가 없다 (7-4) | 확정 (2026-11-20) |

## 4. 수치

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 카드 데이터 크기 (지금) | 카드 20장에 약 7KB (한 장 약 355바이트, 한국어 이름 · 문구 평균 68바이트) | 확인 (2026-11-19 실측) |
| 카드 데이터 크기 (예상) | 300장 · 5개 언어 약 225KB — 빌드 안이라 다운로드 · 과금과 상관없다 | 가정 |
| 카드 그림 한 장 | 약 0.3 \~ 1.5MB (해상도 · 압축에 따라) | 가정 — 실제 그림이 오면 잰다 |

## 6. 상태 · 흐름

### 6-3. 게임 시작

| 현재 상태 | 조건 | 다음 상태 | 결과 |
| --- | --- | --- | --- |
| 룸 「시작 중」 | 전환 덮개가 화면을 다 덮음 (`15-screen` 9-4 ③) | **그림 불러오는 중** | 덱에 든 카드 종류의 그림을 전부 불러온다. 덮개는 머문다 (`15-screen` 9-3 「머묾」) |
| 그림 불러오는 중 | 다 불러옴 | 인게임 | 덮개가 걷힌다 |
| 그림 불러오는 중 | 한 장을 못 불러옴 | 인게임 | 그 카드만 그림 없이(이름 · 문구만) 진행하고 개발 로그를 남긴다. 판을 멈추지 않는다. 확정 (추천안) |
| 인게임 | 게임 끝 · 방으로 | — | 불러온 그림을 모두 내린다 |

- 같은 카드가 여러 장이어도 그림은 하나다 — 장수가 아니라 **종류 수**만큼 불러온다.

## 7. 상세

### 7-1. 데이터 넷

| 데이터 | 무엇 | 무게 | 어디 |
| --- | --- | --- | --- |
| **카드 정의** | 카드 1종 — 번호 · 이름 · 문구 · 종류 · 대상 · 조건 · 등급 · 효과(종류 + 값) · 연출 시간 · **그림 주소** | 가볍다 (한 종류 몇 KB) | 빌드 (`Card_{ID}.asset`) |
| **카드 그림** | 앞면 그림 | 무겁다 (한 종류 약 1MB) | 빌드 (Addressables 로컬 그룹) |
| **카드 목록** | 게임에 있는 모든 카드 정의의 목록 — 도감용. 덱과 다르다 | 가볍다 | 빌드 |
| **덱** | 어떤 카드를 몇 장 (`05-deck` 8절) | 가볍다 | 빌드 (`Deck_Main.asset`) |

- 게임 안의 **카드 한 장**은 데이터가 아니라, 방장이 게임 시작 때 덱에서 장마다 만드는 값이다 (`05-deck` 3절).

### 7-3. 배포 흐름

```
노션 카드 DB · 다국어 DB (기획 편집)
 → 카드 정리 봇 (매일, GitHub Actions) → cards.json 을 고치는 PR (bot/card-sync → develop)
 → 사람이 검토 · 머지                         ← 사람 확인 단계
 → Unity 가 cards.json 변경을 보고 카드 에셋 · Deck_Main 에 넣는다 (자동, 7-4)
 → 빌드 (빌드 직전에 한 번 더 넣는다) → 앱 업데이트로 배포 (../versioning.md)
```

| 단계 | 누가 | 구분 |
| --- | --- | --- |
| 봇이 확정 카드만 고친다 (미공개 · 제안 카드는 나가지 않는다). 새 카드는 효과를 만들어야 하므로 넣지 않는다 — 개발이 `cards.json` 에 넣는다 (`scripts/card-sync/README.md`) | 봇 | 확정 (기존 — 카드 정리 봇) |
| 머지 | 사람 | 확정 (2026-11-20) |
| 카드 에셋에 넣기 | Unity 자동 (7-4) | 확정 (2026-11-20) |
| 배포 | 앱 업데이트 — 버전 번호는 `../versioning.md` | 확정 (2026-11-20) |
| **되돌리기** = 그 PR 을 되돌리는 PR 을 머지하고 다시 빌드한다 | 사람 | 확정 (2026-11-20) |

### 7-4. 카드 가져오기 (Unity)

| 때 | 하는 일 | 구분 |
| --- | --- | --- |
| `cards.json` 이 바뀌어 Unity 가 다시 가져옴 (머지한 develop 을 받았을 때 등) | 「카드 가져오기」 를 자동으로 돌린다 — `Card_{ID}.asset` 을 만들거나 고치고, 장수대로 `Deck_Main` 을 다시 짠다. 콘솔에 한 줄 남긴다 | 확정 (2026-11-20) |
| 빌드 직전 | 한 번 더 돌린다. `cards.json` 이 깨졌거나 없는 종류 · 대상 · 효과 이름이 있으면 **빌드를 멈춘다** | 확정 (2026-11-20) |
| 손으로 | 메뉴 `Chapchu/카드 가져오기` | 확정 (기존) |

- 덮는 값 · 효과를 처음만 채우는 규칙은 `11-card-list` 0절 그대로다.

### 7-6. 버전 · 매칭

| 항목 | 규칙 | 구분 |
| --- | --- | --- |
| 매칭 | 네트워크 서버 접속 버전 = 앱 버전 (Photon `GameVersion`). 앱 버전이 다르면 만나지 않으므로 같은 방은 같은 카드 데이터다 (`../versioning.md`) | 확정 (2026-11-20) |
| 판 도중 · 방 안 | 카드 데이터가 바뀌지 않는다 — 빌드 안에만 있다 | 확정 (2026-11-20) |
| 옛 앱 | 카드가 바뀐 업데이트가 두 스토어에 다 올라가면 `minVersion` 을 올려 옛 앱을 막을 수 있다 (`23-login` 7-6) | 확정 (기존 구조) |

### 7-9. 노션을 게임이 직접 읽지 않는 이유

| 이유 | 내용 |
| --- | --- |
| 요청 제한 | 노션 API 는 통합 하나당 평균 초당 3회 — 게임 전체가 나눠 쓴다. 동접 100명이 패치 날 1분 안에 켜면 초당 5회로 넘친다 |
| 토큰 | 앱 안에 노션 토큰이 들어가야 한다. 꺼내면 미공개 카드 · 회의 내용을 읽고, 한 사람이 요청을 퍼부으면 모두가 못 받는다 |
| 속도 | 요청 한 번이 0.3 \~ 1초. 한 번에 100행까지라 여러 번 불러야 한다 |

- 7-2 원격 파일 · 7-5 Remote Config 카드 키 · 7-7 언어 파일 · 7-8 과금 안전장치는 2026-11-20 에 지웠다. UGS 전체 예산 알림 · 결제 카드 한도는 `../store-release.md` 3-1 로 옮겼다.
