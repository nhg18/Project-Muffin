# 08. 방(Room) · 로비

**최종 수정일**: 2026-09-25
**분류**: MVP
**상태: 결정되지 않은 항목이 많다. 구현 전 5절을 먼저 확정해야 한다.**

---

## 1. 목적

게임 시작 전 플레이어들이 모여 대기하는 공간을 제공한다.

---

## 2. 핵심 수치

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 최소 인원 | 2명 | 확정 (`NetworkManager.MinPlayers`) |
| 최대 인원 | 4명 | 확정 (`NetworkManager.MaxPlayers`) |
| room code | 랜덤 생성 코드 (영대문자 4자리) | 확정 (5절 #3) |

> ⚠ 레거시 `PrototypeNetwork`는 `MaxPlayers = 6`으로 방을 만든다. 기획(2~4인) 위반.

---

## 3. 화면 구성 (노션 원본 = 명칭만 존재)

| 친구 초대 버튼 | 친구 초대 | Optional |

## 4. 현재 동작 (코드 기준)

| 처리 | 동작 | 위치 |
| --- | --- | --- |
| 방 생성 | 랜덤 코드 생성 → `CreateRoom(code, maxPlayers=4, visible, open)` | `PhotonRoom.CreateRoom` |
| 코드 중복 (에러 32766) | 자동으로 다시 생성 시도 | `PhotonRoom.OnCreateRoomFailed` |
| 방 참가 | 코드를 `Trim().ToUpper()` 후 참가 | `PhotonRoom.JoinRoom` |
| 랜덤 매칭 | `JoinRandomRoom()` → 빈 방이 있으면 참가, 없으면(`OnJoinRandomFailed`) 새 방 생성 — **확정 (2026-09-25, MVP 포함)** | `PhotonRoom.JoinRandomRoom` · `OnJoinRandomFailed` |
| 참가 실패 | `RoomEvents.RaiseJoinRoomFailed` → 팝업 | `PhotonRoom` |
| 방 씬 이동 | `OnJoinedRoom` → Room 씬 로드 | `PhotonRoom` |
| 게임 시작 | 방장이 `PhotonNetwork.LoadLevel` | 레거시 `PrototypeNetwork.GameStart` |

## 5. 결정 항목 (2026-09-25 확정)

| # | 항목 | 결정할 것 | **확정** (2026-09-25) | 근거 |
| --- | --- | --- | --- | --- |
| 1 | 표시 조건 | 방장과 참가자에게 UI가 다르게 보이는가 | **시작 버튼만 방장에게** 표시, 나머지 동일 | 현재 구현. 방장 표시는 `(Host)` 글자 |
| 2 | 시작 버튼 활성 조건 | 최소 인원(2명)만 충족하면 되는가, 전원 준비 완료가 필요한가 | **인원 2명 이상이면 활성.** 준비 상태 없음 | 파티 게임 4인 이하 — 준비 단계는 흐름만 늘린다. 현재 구현 |
| 3 | room code 규칙 | 자릿수, 생성 방식, 만료 여부 | **영대문자 4자리** 랜덤(중복 시 재생성), 만료 없음(방이 사라지면 끝) | 현재 구현 (`RandomCode.Length`). 4자리 = 26⁴ ≈ 45만 개 |
| 4 | 로그 내용 | 입장 / 퇴장 / 설정 변경 중 무엇을 기록하는가 | **입장 · 퇴장 · 방장 교체** 3종, 최대 30줄 | 설정 항목이 없으므로(#7) 설정 변경 로그도 없음 |
| 5 | 나가기 처리 | 방장이 나가면 **위임**인가 **방 폭파**인가 | **위임** (PUN 기본) — 남은 사람 중 먼저 들어온 사람이 방장 | 폭파는 남은 사람을 로비로 강제 이동시켜야 해 처리가 더 많다. 현재 구현 |
| 6 | 준비(Ready) 상태 | 존재하는가 | **없음** | #2 와 같은 이유 |
| 7 | 방 설정 항목 | 무엇을 설정할 수 있는가 | **MVP 에는 없음** — 인원 4 고정, 공개(랜덤 매칭 대상) 고정 | 14-lobby-ui 3절 #1 (동작하는 기능만) 과 같은 원칙 |
| 8 | 게임 중 방 공개 여부 | 시작 후 `IsOpen = false` 처리 여부 | **닫는다** (`IsOpen = false`, `IsVisible = false`) — 시작된 방은 참가 · 랜덤 매칭 대상에서 제외 | 현재 구현 (`RoomPanel.OnStartClicked`). 중간 참가 · 재접속은 09-network 미정과 함께 |

8건 전부 확정 (사용자 승인 2026-09-25). #1 · #2 · #3 · #5 · #8 은 현재 구현과 같다. #4 방장 교체 로그는 미구현.

---

## 6. 상태 흐름 (제안)

```
Lobby ──(방 생성)──→ Room(방장)
Lobby ──(코드 입력/초대)──→ Room(참가자)
Lobby ──(랜덤 매칭)──→ Room(빈 방이 있으면 참가자, 없으면 방장)
Room  ──(시작 버튼)──→ GameScene
Room  ──(나가기)──→ Lobby
```

## 7. 예외

| 상황 | 처리 | 구분 |
| --- | --- | --- |
| 존재하지 않는 코드 | 참가 실패 팝업 — "방을 찾을 수 없습니다." | 확정 (구현됨) |
| 인원 초과 | 참가 실패 팝업 — "방이 가득 찼습니다." | 확정 (구현됨) |
| 코드 미입력 | 참가 실패 팝업 — "방 코드가 없습니다." | 확정 (구현됨) |
| 이미 시작된 방 | 참가 실패 팝업 — "이미 시작된 방입니다." (`GameClosed`). 시작 시 `IsOpen=false` (5절 #8) | 확정 (구현됨) |
| 그 밖의 실패 | "잠시 후 다시 시도해 주세요." (Photon 원문은 보여주지 않음) | 확정 (구현됨) |
| 방장 이탈 | **위임** (PUN 기본) — 남은 사람 중 한 명이 방장이 되고, `(Host)` 표기 · 시작 버튼이 즉시 갱신된다 | 확정 (5절 #5, 구현됨) |
| 연결 끊김 | **미정** | 미정 |
