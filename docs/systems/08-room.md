## 4. 동작

| 처리 | 동작 |
| --- | --- |
| 방 생성 | 랜덤 코드를 만들어 방 이름으로 쓴다. 최대 4명, 공개 · 열림 |
| 코드 중복 (에러 32766) | 자동으로 다시 생성 시도 |
| 방 참가 | 입력 코드의 앞뒤 공백을 지우고 대문자로 바꿔 참가 |
| 랜덤 매칭 | 자리가 있는 공개 방에 참가. 없으면 새 방 생성 — **확정 (2026-09-25, MVP 포함)** |
| 참가 실패 | 실패 이유를 팝업으로 알린다 (문구는 14-lobby-ui) |
| 방 씬 이동 | 입장에 성공하면 방 씬을 연다 |
| 게임 시작 | 방장이 방을 닫고(참가 · 검색 불가) 전원을 게임 씬으로 이동시킨다 |

## 5. 결정 항목 (2026-09-25 확정)

| # | 항목 | 결정할 것 | **확정** (2026-09-25) | 근거 |
| --- | --- | --- | --- | --- |
| 1 | 표시 조건 | 방장과 참가자에게 UI가 다르게 보이는가 | **시작 버튼만 방장에게** 표시, 나머지 동일 | 방장 표시는 `(방장)` 글자 |
| 2 | 시작 버튼 활성 조건 | 최소 인원(2명)만 충족하면 되는가, 전원 준비 완료가 필요한가 | **인원 2명 이상이면 활성.** 준비 상태 없음 | 파티 게임 4인 이하 — 준비 단계는 흐름만 늘린다 |
| 3 | room code 규칙 | 자릿수, 생성 방식, 만료 여부 | **영대문자 4자리** 랜덤(중복 시 재생성), 만료 없음(방이 사라지면 끝) | 4자리 = 26⁴ ≈ 45만 개 |
| 4 | 로그 내용 | 입장 / 퇴장 / 설정 변경 중 무엇을 기록하는가 | **입장 · 퇴장 · 방장 교체** 3종, 최대 30줄 | 설정 항목이 없으므로(#7) 설정 변경 로그도 없음 |
| 5 | 나가기 처리 | 방장이 나가면 **위임**인가 **방 폭파**인가 | **위임** (PUN 기본) — 남은 사람 중 먼저 들어온 사람이 방장 | 폭파는 남은 사람을 로비로 강제 이동시켜야 해 처리가 더 많다 |
| 6 | 준비(Ready) 상태 | 존재하는가 | **없음** | #2 와 같은 이유 |
| 7 | 방 설정 항목 | 무엇을 설정할 수 있는가 | **MVP 에는 없음** — 인원 4 고정, 공개(랜덤 매칭 대상) 고정 | 14-lobby-ui 3절 #1 (동작하는 기능만) 과 같은 원칙 |
| 8 | 게임 중 방 공개 여부 | 시작 후 `IsOpen = false` 처리 여부 | **닫는다** (`IsOpen = false`, `IsVisible = false`) — 시작된 방은 참가 · 랜덤 매칭 대상에서 제외 | 중간 참가 · 재접속은 09-network 미정과 함께 |

8건 전부 확정 (사용자 승인 2026-09-25).

## 6. 상태 흐름 (확정 — 5절)

```
Lobby ──(방 생성)──→ Room(방장)
Lobby ──(코드 입력/초대)──→ Room(참가자)
Lobby ──(랜덤 매칭)──→ Room(빈 방이 있으면 참가자, 없으면 방장)
Room  ──(시작 버튼)──→ GameScene
Room  ──(나가기)──→ Lobby
```
