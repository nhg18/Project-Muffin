# 04. 카드 시스템

**최종 수정일**: 2026-11-06
**분류**: Core
**개별 카드 효과는 [`11-card-list.md`](11-card-list.md) 참고. 이 문서는 "카드가 어떻게 처리되는가"만 다룬다.**

---

## 1. 목적

카드의 사용·발동·반응·처리 순서를 정의한다. 게임의 모든 상호작용은 이 파이프라인을 통과한다.

## 2. 핵심 수치

| 항목 | 값 | 구분 |
| --- | --- | --- |
| 함정 슬롯 최대 설치 수 | 3장 / 플레이어 | 확정 |
| 반응 시간 | 5초 (처리 카드 등록마다 갱신) | 확정 |
| 메인 행동 | 턴당 1회 | 확정 |

## 3. 카드 구성

| 항목 | 설명 |
| --- | --- |
| 카드 타입 | 행동 / 함정 / 카운터 |
| 사용 조건 | 카드를 사용·발동하기 위해 필요한 조건 |
| 대상 | 효과가 적용되는 플레이어 또는 카드 |
| 효과 | 처리 시 적용되는 결과 |

### 게임 요소

| 요소 | 설명 | 공개 범위 |
| --- | --- | --- |
| 손패 | 보유 중인 카드 | 내용은 소유자만 / 장수는 공개 |
| 덱 | 아직 뽑히지 않은 카드 | 비공개 / 잔여 장수는 공개 |
| 버림 더미 | 처리가 끝난 카드 | 공개 |
| 함정 슬롯 | 설치한 함정이 대기하는 영역 | 개수는 공개 / **종류는 비공개(뒷면)** |

---

## 4. 카드 타입별 요약

| 타입 | 사용 시점 | 이동 경로 |
| --- | --- | --- |
| 행동 | 자신의 턴, 메인 행동 1회 | 손패 → 사용 → 반응 대기(5초) 및 처리 → 버림 더미 |
| 함정 | 조건 충족 시 소유자 **수동** 발동 | 손패 → 설치 → 조건 충족 → 발동 선택 → 반응 대기 → 처리 → 버림 더미 |
| 카운터 | 처리 중인 카드에 반응, 언제든 | 손패 → 사용 → 반응 대기 → 처리 → 버림 더미 |

### 공통 규칙 (확정)

* 사용·발동한 카드는 처리 후 **반드시** 버림 더미로 이동한다. 무효화·불발돼도 동일하다.
* 발동하지 않은 함정 카드는 슬롯에 유지된다.
* 승인되지 않은(거절된) 요청의 카드는 원래 위치를 유지한다.

---

## 5. 행동 카드

### 사용 조건 (전부 만족)

1. 자신의 턴
2. 손패에 존재
3. 메인 행동 미사용
4. 카드별 조건 충족
5. (필요 시) 유효한 대상 존재

### 사용 규칙

* 사용 시점에 **대상이 확정**된다. 처리 중 변경·재선택 불가.
* 현재 처리 카드로 등록되고 **5초 반응 시간**이 시작된다. (대응 카드 보유 여부와 무관하게 항상 5초)
* 행동 카드 사용과 드로우는 **둘 중 하나만** 가능하다.
* 모든 함정·카운터 처리가 끝난 뒤 턴이 종료된다. **무효화·불발돼도 턴은 종료된다.**

---

## 6. 함정 카드

### 설치 조건 (전부 만족)

1. 자신의 턴
2. 메인 행동 미사용
3. 손패에 존재
4. 빈 함정 슬롯 존재

### 설치 규칙

* 플레이어당 **최대 3장**.
* 자신의 턴에 빈 슬롯 수만큼 **여러 장** 설치할 수 있다.
* 설치는 **메인 행동으로 처리하지 않는다.** 설치 후에도 추가 설치와 메인 행동이 가능하다.

### 노출 규칙

* 슬롯 **존재 여부와 개수는 공개**.
* 카드 **종류는 비공개**(뒷면 표시).
* 발동하는 순간 공개된다.

### 발동 규칙

* 자신의 턴이 아니어도 발동할 수 있다.
* 조건을 충족해도 **자동 발동하지 않는다.** 소유자가 선택해야 한다.
* 발동한 함정은 공개 후 현재 처리 카드로 등록되고 5초 반응 시간이 시작된다.
* 처리 후 효과 적용·무효화·불발 여부와 관계없이 버림 더미로 이동한다.

### 효과 규칙

* 함정 효과는 **카드에 작성된 내용만** 적용한다.
* 원래 카드를 무효화하려면 효과에 **무효화가 명시**되어 있어야 한다. 함정 발동 자체가 무효화를 의미하지 않는다.
* 카운터로 무효화되면 해당 함정의 효과 **전체**가 미적용된다.

### 여러 함정 동시 발동

* 마스터 도착 순서로 **1개만 승인**, 나머지는 거절되어 슬롯에 유지된다.
* 승인된 함정과 그에 대한 카운터 처리를 모두 마친 뒤, 남은 함정의 발동 가능 여부를 **재확인**한다.
* 조건을 여전히 충족해도 **소유자가 다시 발동해야** 한다.

---

## 7. 카운터 카드

### 사용 조건 (전부 만족)

1. 반응 가능한 카드가 존재 — 체인에 카드가 있다
2. 반응 조건 충족 — 체인 **맨 위 카드의 종류**(행동 / 함정 / 카운터)가 카운터 카드의 「반응 대상」에 들어 있다. 「피해를 줄 때」 같은 카드별 세부 조건은 기능 9 에서 더한다 (2026-11-06)
3. 손패에 존재
4. **반응 시간 안**에 사용 (8절 — 연출 시간이 끝난 뒤부터 5초)

### 사용 규칙

* 자신의 턴이 아니어도 사용 가능. 사용 시 반응 대상이 확정된다.
* 카운터가 등록되면 기존 카드는 **처리 대기**로 밀리고, 반응 시간이 **5초로 갱신**된다.
* 추가 카운터는 **가장 최근 카운터**를 대상으로 한다.
* 처리는 **마지막 사용 카드부터 역순**으로 진행한다.

### 동시 사용

마스터 도착 순서로 1개만 승인. 늦은 요청은 거절되어 손패에 유지된다.

---

## 8. 반응 시간 (확정)

* 카드가 현재 처리 카드로 등록될 때마다 **그 카드의 연출 시간(1 ~ 3 단계, [`10-ui.md`](10-ui.md) 5-1)이 지난 뒤** 5초가 시작된다. (대응 카드가 아무에게도 없어도 5초는 유지) (2026-11-06)
* 새 카운터가 등록되면 그 카운터의 연출 시간 뒤 5초로 **초기화**된다.
* 연출 시간은 카드 데이터에 카드마다 적힌 값이다. 마스터는 이 값으로 반응 시작 · 마감 시각을 계산해 알리고, 클라이언트의 연출이 끝나기를 기다리지 않는다 (2026-11-06).
* 반응 시간이 열리기 전(연출 중)에 도착한 카운터 요청은 거절한다 (2026-11-06).
* 5초 동안 아무도 내지 않으면 체인을 위에서부터 **한 번에** 처리한다. 처리하는 동안에는 다시 기다리지 않는다 (2026-10-30).
* 체인을 처리한 뒤 다음 턴은 **체인 맨 아래 카드의 후처리 시간(4 단계 + 버림 더미로 이동, 카드 데이터 값)** 이 지난 뒤 시작한다 (2026-11-06, `03-turn.md` 4절).
* 모든 플레이어에게 **동일하게** 표시된다.
* 제한 시간 내 **마스터에 도착해 승인된** 요청만 인정한다. 이후 도착 요청은 거절.
* 시간 기준은 `PhotonNetwork.Time` ([`09-network.md`](09-network.md) 8절).

## 9. 처리 순서

### 9.1 카운터 체인 (역순 처리)

```
A(행동 카드) ← B(카운터, A 무효화) ← C(카운터, B 무효화)

처리 순서: C → B → A
결과:      C가 B를 무효화 → B는 A를 무효화하지 못함 → A 정상 적용
카드 이동: A, B, C 전부 버림 더미
```

### 9.2 함정 발동 시

```
기존 카드 / 게임 처리 일시 대기
   ↓
함정 등록 + 5초 반응
   ↓
함정에 대한 카운터 처리
   ↓
대기 중이던 카드로 복귀
   ↓
무효화되지 않았으면 바로 처리 (다시 기다리지 않음, 8절)
```

함정 자체가 카운터로 무효화되면 함정 효과 전체가 미적용된 뒤 동일하게 복귀한다.

## 10. 대상 확정 및 효과 불발

| 상황 | 처리 | 구분 |
| --- | --- | --- |
| 사용·발동 시점 | 대상 확정. 처리 중 변경·재선택 불가 | 확정 |
| 대상이 처리 전 사망·무효화 | 효과 미적용. 카드는 **사용된 것으로** 버림 더미 이동. 행동 카드면 턴 종료 | 확정 |
| 사용 요청 시 조건 미충족 | 요청 거절, 카드 원위치 유지 | 확정 |
| 다중 대상 중 일부만 사망 | 생존 대상 효과는 계속 처리 | 확정 |
| 대상이 없는 카드 (`TargetType.None`) | 대상 없이 효과 1회 실행 | 확정 |

## 11. 대상 지정 타입

| 타입 | 의미 | 선택 방식 |
| --- | --- | --- |
| `None` | 대상 없음 | 선택 불필요 |
| `OneOther` | 나를 뺀 1명 | 플레이어 탭 |
| `TwoOthers` | 나를 뺀 2명 | 플레이어 2회 탭 |
| `AllOthers` | 나를 뺀 전원 | 자동 |
| `Self` | 나 | 자동 |
| `Everyone` | 나를 포함한 전원 | 자동 |

> 이름 규칙 (2026-10-10): 개인전이라 "적(Enemy)" 대신 "나를 뺀 사람(Other)" 으로 쓴다. 카드 에셋에는 순서 번호로 저장되므로 **순서를 바꾸거나 중간에 끼우지 않는다** — 새 타입은 끝에 추가한다.

카드 목록(`11-card-list.md`)에는 위 외에 다음 대상이 등장한다. **대상 타입 확장 필요 (미정)**

* 찹츄 상태 플레이어 전원 (A02, T04)
* 본인보다 손패가 많은 모든 플레이어 (A23)
* 본인 + 다른 플레이어 선택 (A11)
* 생존한 모든 플레이어 (A14, T01)
* 카드(플레이어가 아님): 현재 함정카드 / 현재 카운터카드 / 파괴될 본인 함정 (C06, C07, C12)

> **대상이 "플레이어"가 아니라 "처리 중인 카드"인 경우가 존재한다.** 현재 `TargetType` 열거형으로는 표현할 수 없다.

## 15. 미정 / 결정 필요

1. 카드별 수치 N (`11-card-list.md`의 모든 N/M) — **카드 효과 구현 전부를 막고 있음**
2. 대상 타입 확장 (조건부 대상 / 카드 대상)
3. 함정 설치·발동 입력 방식 (UI)
4. 카운터 사용 입력 방식 (반응 5초 안에 어떻게 고르는가)
5. 체인 깊이 제한 여부 (무한 카운터 방지)
6. 카드 사용 요청이 거절됐을 때 사용자에게 보여줄 메시지 규칙
