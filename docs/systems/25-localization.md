# 25. 지역 언어 (다국어)

**최종 수정일**: 2026-11-15
**분류**: MVP (출시 `1.0` 에 포함 — `development-plan` 기능 12L)
**출처**: 2026-11-15 PM 결정 — 언어 5개 · 기기 언어 자동 + 설정 팝업 · 원본은 노션 · Unity Localization 패키지 · 한국어 원본에서 바로 번역 · 출시 뒤 통계를 보고 언어 추가. 2026-11-07 「한국어만 · 언어 항목 없음」(`17-lobby-ui-full` 7-4 · 12절 #5)을 뒤집는다. 근거로 본 시장 자료는 worklog 2026-11-15.

> 한 줄 요약: **기기 언어로 자동으로 정하고, 설정 팝업에서 바꿀 수 있다.** 문구의 원본은 노션 「🌐 다국어 문구」 DB 이고, 모든 언어는 한국어에서 바로 번역한다. 문구는 네트워크로 보내지 않는다 — 각 화면이 자기 언어로 그린다.

---

## 1. 목적

한국 밖(일본 · 미국 · 중화권)의 플레이어가 같은 게임을 자기 언어로 하게 한다. 출시 때는 아래 5개 언어만 넣고, 출시 뒤 플레이 국가 통계를 보고 그 나라 언어를 패치로 더한다 — 언어를 더할 때 코드 · 화면을 고치지 않게 만든다.

## 2. 판정 주체

| 무엇 | 누가 | 구분 |
| --- | --- | --- |
| 화면에 쓸 언어 | **각 클라이언트** — 그 기기에서만 정한다. 방장 · 서버가 정하지 않는다 | 확정 (2026-11-15) |
| 문구 표시 | **각 클라이언트** — 방장이 보내는 것은 카드 번호 · 거절 코드 · 숫자 · 닉네임이고, 문장은 받은 쪽이 자기 언어로 만든다 | 확정 (2026-11-15) |
| 언어 설정 저장 | 그 기기 (로컬). 서버(Cloud Save)에 올리지 않는다 — 기기마다 언어가 다를 수 있다 | 제안 |

### 7-2. 번역하는 것 · 하지 않는 것

| 번역한다 | 번역하지 않는다 |
| --- | --- |
| 화면의 모든 글자 — 버튼 · 제목 · 안내 · 토스트 · 팝업 · 에러 · 방 로그 · 기록 · 대상 안내 · 결과 화면 | 닉네임 (사람이 쓴 그대로) |
| 카드 이름 · 카드 문구 (`11-card-list` 의 카드마다) | 방 코드 · 친구 코드 · 버전 |
| 봇 이름 「봇 N」 · 「(봇)」 · 난이도 이름 | 개발용 로그 · 기획서 |
| 추천 닉네임 단어 (`12-title-ui` 4-2 — 언어마다 목록) | — |
| 날짜 · 시간 표기 (「{0}일 {1}시간」 등 — 언어마다 순서 · 단위) | — |

- 카드 그림 · 로고 안에 글자가 있으면 번역 대상인지는 9절 #2.
- 약관 · 개인정보 처리방침 본문의 언어는 9절 #3.

### 7-3. 원본 · 흐름 — 노션 → 게임

| 단계 | 누가 | 무엇 | 구분 |
| --- | --- | --- | --- |
| 1 | 기획 · 개발 | 새 문구는 노션 DB 에 한 행 — **키** · 화면 · 종류 · **한국어** · 의도 · 메모 · 최대 글자. 상태 「원본만」 | 확정 (2026-11-15) |
| 2 | 번역 (초벌은 AI) | 한국어에서 네 언어 칸을 채운다. 상태 「초벌 번역」 | 확정 (원본 한국어) / 제안 (초벌 AI) |
| 3 | 검수 | 그 언어를 아는 사람이 본다. 상태 「검수 완료」 | 제안 — 누가 검수하나는 9절 #1 |
| 4 | 개발 | 노션 DB 를 내보내 게임의 문구 표로 가져온다. 키가 같으면 덮어쓴다 | 제안 |
| 5 | 한국어를 고치면 | 그 행의 상태를 「원본 바뀜」 으로 — 네 언어를 다시 본다 | 확정 (2026-11-15) |

- **키** 는 `화면.영역.이름` 소문자 영문 (예: `title.fail.timeout`, `game.history.draw`). 한 번 붙인 키는 바꾸지 않는다 — 바꾸면 번역이 끊긴다. 확정 (2026-11-15).
- 카드 이름 · 카드 문구 행은 노션 「카드 목록 (기획 원본)」 의 그 카드와 연결한다. 키는 `card.<카드 ID>.name` · `card.<카드 ID>.text`.
- **의도 · 메모** 칸: 말장난 · 밈 · 어감 · 값 자리(`{0}`)에 들어가는 것. 카드 이름(「군침이 싹 도노」 「무야호」 「팍씨」 등)은 직역하지 않고 그 나라에서 같은 느낌이 나는 표현을 찾는다 — 이 칸이 그 근거다.

### 7-4. 문구 쓰는 규칙

| # | 규칙 | 이유 |
| --- | --- | --- |
| 1 | 바뀌는 값은 **값 자리**(`{0}` `{1}`)로 쓰고, 문장을 코드에서 이어 붙이지 않는다 | 언어마다 어순이 다르다 (「{0}의 턴」 / 「{0}'s turn」) |
| 2 | 수에 따라 모양이 바뀌는 말은 **복수형** 서식으로 쓴다 | 영어 「1 card · 2 cards」 |
| 3 | 규칙 수치(10장 · 2명 · 15초)는 값 자리로 넣는다 — 문구에 숫자를 박지 않는다 | 수치가 바뀌어도 다섯 언어를 다 고치지 않게 |
| 4 | 한 문구 = 한 키. 두 화면에 같은 한국어가 있어도 뜻 · 자리가 다르면 키를 나눈다 | 언어에 따라 다르게 옮겨야 할 수 있다 (예: 버튼 「삭제」 와 팝업 제목 「삭제」 — 영어는 「Delete」 · 「Delete account?」) |
| 5 | 칸에 들어가는 길이가 정해져 있으면 **최대 글자**를 적는다. 번역이 넘치면 그 칸은 글자를 줄여 맞추지 않고 번역을 고친다 | 영어 · 독일어는 한국어보다 30 ~ 50% 길다 |

### 7-5. 글꼴

일본어 가나 · 한자, 중국어 한자는 지금 글꼴(Jua)에 없다. 언어별 글꼴 · 이름 칸 글꼴은 [`21-font.md`](21-font.md) 2절 #10 · #11.

### 7-6. 닉네임

닉네임은 번역하지 않는다. 허용 글자 · 길이(한중일 글자 포함 · 폭으로 셈) · 추천 닉네임은 [`12-title-ui.md`](12-title-ui.md) 4-2, 금칙어는 [`23-login.md`](23-login.md) 8절 (언어마다 목록).

### 7-8. 한국어 원본 문체 · 용어 — 확정 (2026-11-15, PM 「추천하는 방식으로 통일」)

번역의 원본이라 한국어부터 한 가지로 맞춘다. 화면 문서(`10` · `12` · `16` · `17` · `22` …)의 문구도 이 규칙을 따르고, 어긋나면 이 표가 옳다. 팝업 자리별 규칙(제목 6자 · 버튼 2개 순서 등)은 `22-popup-ui` 1-1.

| # | 자리 | 규칙 | 예 |
| --- | --- | --- | --- |
| 1 | 문장 (안내 · 토스트 · 팝업 본문 · 오류 · 거절 · 방 로그 · 빈 목록) | **해요체**. 합쇼체(「~습니다」 「~입니다」)는 쓰지 않는다 | 방이 가득 찼어요. · 내 턴이 아니에요. |
| 2 | 부탁 | 「~해 주세요.」 (띄어 쓴다). 「~하세요」 는 쓰지 않는다 | 둘 중 하나를 골라 주세요. |
| 3 | 문장 끝 | 완결 문장은 **마침표**. 연출 외침만 「!」 (찹츄! · 개판 오분전! · 목표 조준! · 복사했어요!) | 아직 기록이 없어요. |
| 4 | 버튼 · 제목 · 라벨 · 칩 · 게임 기록 줄 | 끝에 부호 없음. 버튼은 하는 일 그대로(「~하기」 · 「참가」), 제목 · 라벨 · 기록 줄은 명사구 | 방 나가기 · 연결 끊김 · 손패 꼴찌 · 턴 건너뜀 |
| 5 | 기다리는 동안의 글 | 「~ 중…」 (말줄임표 한 글자 `…`). 「~고 있어요」 는 쓰지 않는다. HUD 상태 칩은 `…` 없이 | 방을 찾는 중… · 바꾸는 중… / 칩 「기다리는 중」 |
| 6 | 사람 부르기 | 이름 뒤 「님」 은 **붙여 쓴다** | {0}님이 입장했어요. |
| 7 | 값 자리 뒤 조사 | 값 자리(`{0}`) 바로 뒤에 받침에 따라 바뀌는 조사(을/를 · 이/가 · 은/는 · 으로/로)를 두지 않는다 — 「님」 · 「계정」 처럼 끝이 정해진 말을 붙이거나 문장을 바꾼다. 「의」 · 「에」 · 「도」 는 괜찮다 | {0} 계정으로 로그인 · '{0}'({1} · {2}) — {3} {4}에 살까요? |
