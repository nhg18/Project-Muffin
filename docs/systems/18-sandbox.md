# 18. 샌드박스 모드 (규칙 없는 카드 테이블)

**최종 수정일**: 2026-09-26
**분류**: 개발 도구 (출시판 제외)
**상태**: 방향 확정 (사용자 2026-09-26) · 세부는 제안

---

## 1. 목적

규칙 판정과 카드 효과가 만들어지기 전에, **실제 게임 화면으로 종이 카드처럼 플레이**할 수 있게 한다.

| 누가 | 무엇을 얻는가 |
| --- | --- |
| 기획 | 카드 59장의 규칙 · 숫자를 개발을 기다리지 않고 시험한다. 원격으로 4명이 같이 한다 |
| UI 개발 | 손패 · 가운데 더미 · 버림 더미 · 함정 칸 · 좌석 화면을 규칙과 상관없이 먼저 완성한다 |
| 로직 개발 | 서버의 첫 층(상태 원본 · 비공개 전달)을 실제 사용으로 검증한다 |
| 전원 | 규칙이 붙은 뒤에도 "체력 10 만들기" 같은 수동 조작을 테스트 도구로 쓴다 |

> 샌드박스는 **실제 서버의 첫 층**이다. 따로 만드는 임시 도구가 아니다. (3절)

---

## 2. 핵심 규칙

| # | 규칙 | 구분 |
| --- | --- | --- |
| 1 | 게임 상태(덱 · 손패 · 함정 칸 · 가운데 더미 · 버림 더미 · 체력 · 턴 · 찹츄 표시)의 원본은 **방장 기기**에 하나만 있다. 규칙 모드와 같다 (`09-network.md` 2절) | 확정 |
| 2 | 방장 기기는 요청을 **검사하지 않는다.** 내 턴인지, 낼 수 있는 카드인지 보지 않고 그대로 적용한다 | 확정 |
| 3 | 카드 **효과는 실행되지 않는다.** 카드를 내면 가운데로 옮겨질 뿐이고, 효과는 사람이 조작 버튼으로 처리한다 | 확정 |
| 4 | **비공개 정보는 규칙 모드와 똑같이 지킨다.** 손패 내용은 본인에게만, 덱 순서는 아무에게도, 함정은 뒷면 (4절) | 확정 |
| 5 | 승리 판정 · 시간 제한 · 강제 퇴장은 없다. 사람이 판단한다 | 확정 |
| 6 | **출시판에는 들어가지 않는다.** 개발 빌드에서만 켤 수 있다 | 확정 |

## 3. 규칙 모드와의 관계

방장 기기의 서버는 세 층으로 만든다. 샌드박스는 1층만 켠 상태다.

| 층 | 내용 | 샌드박스 | 규칙 모드 |
| --- | --- | --- | --- |
| 1층 | 상태 원본, 카드 이동, 섞기, 시작 배분, 비공개 전달 | 켬 | 켬 |
| 2층 | 요청 검사 (턴 · 소유 · 메인 행동 1회 · 대상 유효 · 반응 시간) | 끔 | 켬 |
| 3층 | 효과 자동 실행, 체인 역순 처리, 사망 · 승리 판정 | 끔 | 켬 |

규칙을 붙이는 작업 = 2층과 3층을 켜는 것. 1층과 화면은 그대로 쓴다.

**두 가지 요청 약속을 나눈다** (제안):

| 약속 | 내용 | 규칙 모드에서 |
| --- | --- | --- |
| 게임 요청 (`IGameRequests`) | 뽑기 · 카드 내기(대상 포함) · 함정 놓기 · 턴 종료 · 찹츄 선언 | 그대로 쓴다. 검사가 붙는다 |
| 샌드박스 요청 (`ISandboxRequests`, 신설) | 5절의 수동 조작 전부 | 끈다 (개발 빌드에서는 테스트 도구로 남긴다) |

## 4. 영역과 공개 범위

카드는 항상 아래 영역 중 하나에 있다. 모든 조작은 **카드를 한 영역에서 다른 영역으로 옮기는 것**이다.

| 영역 | 개수 | 카드 내용 | 장수 |
| --- | --- | --- | --- |
| 덱 | 1 | 아무도 모름 | 전체 공개 |
| 손패 | 플레이어마다 | **본인만** | 전체 공개 |
| 함정 칸 | 플레이어마다 3칸 | 뒷면 — 본인만 앎. 공개하면 전체 | 전체 공개 |
| 가운데 더미 | 1 | 전체 공개 | 전체 공개 |
| 버림 더미 | 1 | 전체 공개 (맨 위 카드) | 전체 공개 |

카드가 비공개 영역으로 들어가면 그 영역 주인에게만 카드 내용을 보낸다. 다른 사람은 "누가 어디서 어디로 1장 옮겼다"만 받는다.

## 5. 조작 목록

누구나, 언제든, 누구에게나 할 수 있다 (검사 없음).

| # | 조작 | 결과 | 공개 |
| --- | --- | --- | --- |
| 1 | 덱에서 뽑기 | 덱 맨 위 1장 → 내 손패 | 내용은 나만 |
| 2 | 카드 내기 | 내 손패 1장 → 가운데 더미. 대상을 고르면 전원에게 화살표로 표시 | 전체 |
| 3 | 함정 놓기 | 내 손패 1장 → 내 빈 함정 칸 (뒷면) | 장수만 |
| 4 | 함정 공개 | 내 함정 칸 1장을 앞면으로 | 전체 |
| 5 | 함정 발동 | 내 함정 칸 1장 → 가운데 더미 | 전체 |
| 6 | 가운데 치우기 | 가운데 더미 전부 → 버림 더미 | 전체 |
| 7 | 버리기 | 내 손패 1장 → 버림 더미 | 전체 |
| 8 | 주기 | 내 손패 1장 → 다른 사람 손패 | 내용은 받은 사람만 |
| 9 | 무작위로 가져오기 | 다른 사람 손패에서 무작위 1장 → 내 손패 | 내용은 가져온 사람만 |
| 10 | 함정 칸 카드 옮기기 | 누구 함정 칸 1장 → 버림 더미 / 그 사람 손패 / 내 함정 칸 | 옮긴 곳의 공개 범위를 따름 |
| 11 | 체력 바꾸기 | 아무 좌석 체력 + / − (한 번에 1 · 5 · 10) | 전체 |
| 12 | 턴 넘기기 | 턴 표시를 다음 사람에게 | 전체 |
| 13 | 찹츄 표시 | 아무 좌석 찹츄 표시 켜기 / 끄기 | 전체 |
| 14 | 덱 섞기 | 덱 순서를 무작위로 | 전체 (알림만) |
| 15 | 버림 더미를 덱으로 | 버림 더미 전부 → 덱, 섞기 | 전체 |
| 16 | 5초 타이머 | 전원 화면에 같은 5초 카운트 (서버 시각 기준) | 전체 |

> 11번부터 16번의 수치(1 · 5 · 10, 5초)는 **제안**이다.

## 6. 시작

| # | 처리 | 구분 |
| --- | --- | --- |
| 1 | 방장이 방 화면에서 "샌드박스" 를 켜고 시작한다 (개발 빌드만) | 제안 |
| 2 | 덱 = 카드 데이터에 있는 카드 전부 × 각 1장. 덱 구성이 확정되면 그 매수를 따른다 | 가정 (`05-deck.md` 덱 구성 미정) |
| 3 | 섞기 → 전원 체력 100 → 5장씩 → 첫 턴 무작위. 규칙 모드와 같은 시작 순서 (`01-game-flow.md` 3절) | 확정 |

카드 데이터는 효과 없이 **이름 · 종류 · 효과 문구**만 있어도 된다. 처음에는 `11-card-list.md` 59장의 문구를 N · M 그대로 넣는다.

## 7. 화면

| 요소 | 내용 | 구분 |
| --- | --- | --- |
| 내 손패 · 상대 손패 · 덱 · 좌석 | 규칙 모드와 같은 화면 (`10-ui.md`) | 확정 |
| 가운데 더미 | 맨 위 카드를 크게, 쌓인 장수 표시 | 제안 |
| 버림 더미 | 맨 위 카드와 장수 | 제안 |
| 함정 칸 | 좌석마다 3칸. 뒷면 · 공개 구분 | 제안 |
| 대상 화살표 | 카드 낸 사람 → 대상 좌석, 가운데를 치울 때까지 | 제안 |
| **행동 로그** | "○○님이 A09 를 □□님에게 냈습니다" 한 줄씩. 규칙을 사람이 판단하므로 누가 무엇을 했는지 보여야 한다 | 제안 |
| 조작 방법 | 드래그: 손패 → 가운데(내기) · 내 함정 칸(놓기) · 좌석(주기) · 버림 더미(버리기). 탭: 덱(뽑기) · 가운데(치우기). 길게 누르기: 덱 메뉴(섞기 · 버림 되돌리기) · 좌석 메뉴(체력 · 가져오기 · 찹츄 · 함정 칸) | 제안 |
| 샌드박스 표시 | 화면 구석에 "샌드박스" 글자 — 규칙이 없다는 것을 항상 보이게 | 제안 |

모바일 기준이다. 마우스 우클릭은 쓰지 않는다.

## 8. 하지 않는 것

* 규칙 흉내 (예: 내 턴이 아니면 버튼을 막기) — 샌드박스는 검사가 없다. 규칙은 2층에서 한 번만 만든다
* 효과 자동 실행 — 3층의 일이다
* 출시판 포함

---

## 9. 미정 / 결정 필요

1. 조작 수치 (체력 단위 · 타이머 길이) — 5절 제안값 확인
2. 행동 로그를 방 전체가 보는지, 몇 줄까지 남기는지
3. 게임 중 샌드박스 ↔ 규칙 모드 전환 허용 여부 (제안: 불가. 시작할 때만 정한다)
