# 버전 규칙

`MAJOR.MINOR.PATCH` — Player Settings `Version`. 타이틀 좌하단에 `ver {버전} · Project ChapChu` 로 표시된다.

* 숫자 세 자리만 쓴다. `0.3.0-beta` 처럼 글자를 붙이지 않는다 — iOS 는 숫자 세 자리만 받는다.
* 테스트 단계 이름은 버전에 넣지 않고 빌드 이름에만 붙인다. 타이틀 표시에도 넣지 않는다.
* 현재: `0.1.0` · code 1.

## 출시 전 (`0.x.y`)

| 자리 | 올리는 시점 |
| --- | --- |
| MINOR | 점검 빌드마다 (`0.n.0`) |
| PATCH | 같은 점검 안에서 테스트 빌드를 다시 배포할 때 |
| MAJOR | 정식 출시 = `1.0.0` |

테스트 단계가 바뀌어도 번호는 이어서 올린다 (단계마다 되돌리지 않는다).

| 단계 | 하는 사람 | 배포 |
| --- | --- | --- |
| 내부 점검 | 팀원 | PC 빌드 · Play 내부 테스트 · TestFlight 내부 |
| 비공개 테스트 | 초대한 외부 테스터 | Play 비공개 테스트 · TestFlight 외부 |
| 공개 테스트 | 누구나 (할 경우) | Play 공개 테스트 · TestFlight 공개 링크 |

출시 빌드는 마지막 테스트 빌드에서 번호만 `1.0.0` 으로 올려 다시 만든다 (code 도 +1).

## 출시 뒤 (`1.x.y`)

| 자리 | 올리는 시점 |
| --- | --- |
| PATCH | 버그 · 화면 문구만 고친 핫픽스 |
| MINOR | 새 기능 · **새 카드**가 하나라도 있는 업데이트 (새 카드는 앱 업데이트로만 — `systems/26-card-data.md` 3절 #9) |
| MAJOR | 게임 규칙이 크게 바뀌는 대개편 |

카드 데이터만 바뀐 패치(이름 · 문구 · 수치 · 덱 구성 — `systems/26-card-data.md` 3절 #9)는 **앱 버전을 올리지 않는다.** 아래 「카드 데이터 번호」 를 올린다 (2026-11-19).

## 카드 데이터 번호

카드 데이터가 같은지는 번호가 아니라 **파일의 확인값**으로 가른다 (`systems/26-card-data.md` 7-2 · 7-5, 2026-11-20). 번호는 사람이 부르는 이름표다.

* 카드 데이터를 운영에 올릴 때마다 +1 — Remote Config `cardData` 의 `version` 칸에 적는다. 앱은 이 번호를 로그에만 쓴다.
* 되돌릴 때는 `cardData` 를 옛 값(번호 · 확인값 · 주소)으로 통째로 되돌린다.
* 번호를 올리는 것을 잊어도 패치는 나간다 (확인값이 다르면 받는다). 패치 노트와 어긋날 뿐이다.
* 노션 「📝 패치 노트」 의 「버전」 칸: 카드 데이터만 바뀌었으면 이 번호(예: `카드 12`), 앱 업데이트와 함께 바뀌었으면 앱 버전과 이 번호를 같이 적는다.

## 빌드 번호

* Android `Bundle Version Code` 는 기기 · 스토어에 올리는 빌드마다 +1, 재사용 금지. iOS `Build` 도 같은 숫자.
* 버전 변경은 따로 커밋한다: `chore: 버전 0.2.0 (code 3)`.

## 빌드 이름

`<버전> (<code>) <단계> <차수>차` — 출시 뒤에는 단계 자리에 `업데이트` · `핫픽스`.

* 예: `0.4.0 (5) 내부 점검 4차` · `0.6.1 (10) 비공개 테스트 1차` · `1.1.0 (24) 업데이트` · `1.0.1 (22) 핫픽스`
* Play Console 「출시 이름」, TestFlight 「테스트할 내용」 첫 줄, QA 기록에 똑같이 쓴다.

## 버전이 다르면 매칭되지 않는다

* 접속할 때 이 값을 Photon `GameVersion` 으로 보낸다 (`PhotonConnection.Connect`). PATCH 만 달라도 나뉜다 (2026-11-12). 테스트 때는 모두 같은 빌드 이름인지 확인한다.
* **카드 데이터도 같아야 한다** — 접속 버전은 앱 버전만 쓰고, 카드 데이터는 **방 속성**(확인값)으로 가른다: 같은 데이터의 방만 찾고 들어간다 (확정 2026-11-19 · 확인값 2026-11-20, `systems/26-card-data.md` 7-6).
* 출시 뒤 옛 버전은 Remote Config `minVersion` 으로 막는다 (`systems/23-login.md` 7-6). 새 버전이 Play · App Store **둘 다** 올라간 뒤에 `minVersion` 을 새 버전으로 올린다 — 그 사이에는 옛 · 새 버전끼리 따로 매칭된다.

## 올리는 순서

1. 위 표로 버전 · code 를 정한다.
2. Player Settings `Version` · `Bundle Version Code` · iOS `Build` 를 바꾸고 따로 커밋.
3. 빌드 → 빌드 이름으로 배포.
4. 카드가 바뀌었으면 패치 노트 「버전」 칸을 채운다 (위 「카드 데이터 번호」).
5. (출시 뒤) 두 스토어에 다 올라가면 `minVersion` 을 올린다. 그 업데이트에 **새 카드**가 있으면, 이때 같이 새 카드가 든 카드 데이터를 운영에 올리고 `cardData` 를 바꾼다 — 옛 앱이 모르는 카드를 받지 않게 (`systems/26-card-data.md` 7-3). 순서를 어겨도 옛 앱은 그 파일을 버리고 쓰던 데이터로 논다.
